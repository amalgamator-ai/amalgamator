The code_gen_V3.patch implements the Multi-Pass Context Compaction feature,
porting Hermes Agent's multi-pass compaction system to OpenClaw's TypeScript
codebase. The implementation follows the Review V4 plan exactly, with all
corrections from previous iterations incorporated from the start.

KEY COMPONENTS:

  Step 1+2: compaction-progress.ts (NEW, 145 lines)
    - Constants: MAX_COMPACTION_PASSES=3, PROGRESS_THRESHOLD=0.05,
      INEFFECTIVE_SAVINGS_THRESHOLD=0.1, MAX_INEFFECTIVE_COMPRESSIONS=2,
      DEFAULT_COMPACTION_TIMEOUT_MS=180000
    - compactionMadeProgress() -- per-pass progress detection
    - CompactionProgressTracker class -- anti-thrashing guard tracking
      consecutive ineffective compressions
    - Interfaces: MultiPassCompactionState, CompactionProgressTrackerState

  Step 3: pre-compaction-pruning.ts (NEW, 303 lines)
    - preCompactionPrune() with 3 sub-passes:
      1. Hash-based deduplication of identical tool results (SHA-256)
      2. Replacement of old tool results with 1-line summaries
      3. Truncation of large tool call arguments (Record<string, unknown>)
    - Uses correct OpenClaw field names:
      - ToolResultMessage: toolCallId, toolName, content
      - ToolCall content blocks: id, name, arguments (Record<string, unknown>)
    - Uses node:crypto import (V2 fix incorporated)
    - Uses Object.assign() instead of spread in map (V2 fix incorporated)
    - All if/else/for bodies use curly braces (V2 fix incorporated)

  Step 4: compaction.ts (MODIFIED, +77 lines)
    - Added maxPasses? and progressThreshold? to CompactionSettings interface
    - Added user message anchoring to findCutPoint()
    - Added assistant message anchoring (with hasVisibleContent check)
    - Added safety floor: cutIndex = Math.max(cutIndex, startIndex + 1)
    - Helper functions: findLastMessageIndex(), hasVisibleContent()
    - Uses correct property paths: (entry.message as HarnessMessage).role
      (V4 review fix incorporated from the start)
    - Structural type cast for hasVisibleContent (V1 fix incorporated)

  Step 5: messages.ts (MODIFIED, +12/-4 lines)
    - Enhanced COMPACTION_SUMMARY_PREFIX with "[COMPACTION -- REFERENCE ONLY]"
      directive, "Do NOT answer questions" instruction, "Respond ONLY to
      the latest user message" instruction
    - New COMPACTION_SUMMARY_END_MARKER constant
    - Updated convertToLlm() to append end marker after compaction summaries

  Step 6: multi-pass-compaction.ts (NEW, 266 lines)
    - multiPassCompact() implementing iterative compaction loop
    - Clamps maxPasses to [1, 10] (safety bounds)
    - Anti-thrashing gate via CompactionProgressTracker
    - Composed AbortSignal (external + timeout) via AbortSignal.any()
    - Per-pass lifecycle: adoptTranscript + optional runMaintenance
    - Progress detection using compactionMadeProgress()
    - Multiple stop reasons: threshold_met, no_progress, max_passes,
      timeout, aborted, anti_thrash
    - MultiPassCompactionResult and MultiPassCompactParams interfaces

  Step 8: Config schema extension (3 files modified)
    - types.agent-defaults.ts: Added maxPasses? and progressThreshold? to
      AgentCompactionConfig
    - zod-schema.agent-defaults.ts: Added Zod validators:
      maxPasses: z.number().int().min(1).max(10).optional()
      progressThreshold: z.number().gt(0).lt(1).optional()
    - defaults.ts: Modified applyCompactionDefaults() to apply per-field
      defaults (maxPasses=3, progressThreshold=0.05) even when mode is set

  Integration:
    - compaction-safeguard.ts: Injected preCompactionPrune() call before
      provider/LLM paths, with import after node: built-ins (V2 fix)
    - index.ts: Exported CutPointResult, CompactionProgressTracker,
      compactionMadeProgress, and all constants/types from compaction-progress
