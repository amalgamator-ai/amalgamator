## Fixes Applied for Review Findings

All four review findings from the ClawSweeper review have been addressed. Below is a summary of each finding and the corresponding fix.

---

### 1. [P1] Keep provider compaction inputs unpruned

> *"The new pruning pass runs before the configured provider path, so `allMessages` no longer contains all messages even though this path explicitly says the provider handles its own context management."*

**Fix:** Moved the `preCompactionPrune()` call from before the provider path (line ~964) to after the provider path and before the LLM path (line ~1029). The provider path now receives the original unpruned `baseMessagesToSummarize`, preserving its all-message contract. The LLM path continues to benefit from pruning. The comment on the pruning block was updated to document this LLM-only scope.

---

### 2. [P1] Wire the multi-pass loop into real callers

> *"This helper is added and tested, but production compaction entry points still call `activeSession.compact()` or `contextEngine.compact()` through the existing single-call timeout wrappers. Users who set `maxPasses` or rely on the advertised iterative behavior would still get the old path."*

**Fix:** Rather than prematurely wiring the multi-pass loop into production callers, the fix removes the user-facing surface that would promise multi-pass behavior before it is integrated. Specifically:
- Removed `maxPasses` and `progressThreshold` from the user-facing config schema and defaults
- Removed all multi-pass exports from the public `agent-core` index
- The `multiPassCompact` module and its 30+ tests are retained as internal, well-tested code for future production integration

This ensures no user-visible knobs exist that don't work, while preserving the implementation for when callers are ready to be wired.

---

### 3. [P2] Keep new compaction knobs private until they work

> *"The schema now accepts `maxPasses` and `progressThreshold`, and defaults.ts materializes them, but current settings managers and compaction callers do not propagate those values."*

**Fix:**
- Removed `maxPasses` and `progressThreshold` from the Zod schema (`zod-schema.agent-defaults.ts`)
- Removed both fields from the `AgentCompactionConfig` type definition (`types.agent-defaults.ts`)
- Reverted `defaults.ts` to the original mode-only default guard (no per-field spreading of `maxPasses`/`progressThreshold`)
- Added `@internal` JSDoc markers to the `CompactionSettings` interface fields so they remain available for programmatic use but are explicitly not user-configurable
- Updated config tests to verify these fields are rejected in the user-facing schema

---

### 4. [P2] Do not export unapproved compaction internals

> *"Exporting the tracker, constants, and state types from `packages/agent-core` plus changing the surface-budget script turns this unintegrated helper into public API."*

**Fix:**
- Removed all 10 compaction-progress exports from `packages/agent-core/src/index.ts`: `CompactionProgressTracker`, `compactionMadeProgress`, `MAX_COMPACTION_PASSES`, `PROGRESS_THRESHOLD`, `INEFFECTIVE_SAVINGS_THRESHOLD`, `MAX_INEFFECTIVE_COMPRESSIONS`, `DEFAULT_COMPACTION_TIMEOUT_MS`, `MultiPassCompactionState`, `CompactionProgressTrackerState`, and `CutPointResult`
- Updated surface budget values to match: `publicExports` 10399 &rarr; 10389, `publicFunctionExports` 5215 &rarr; 5214
- Internal consumers (multi-pass-compaction.ts, test files) use direct source imports, so they are unaffected

---

### 5. [P1] Behavior proof

> *"Needs real behavior proof before merge: the PR body lists tests but does not include redacted terminal output, logs, recordings, linked artifacts, or live output showing a real OpenClaw session after the change."*

Behavior proof has been generated. See the collapsible section below.

## Remaining Open Items

- **Production caller integration:** The multi-pass compaction loop (`multiPassCompact`) is implemented and tested internally but is not yet wired into production compaction entry points (`activeSession.compact()`, `contextEngine.compact()`). This is intentional — the module is kept as internal code, and the user-facing knobs have been removed until integration is complete.
- **Branch rebase:** The review noted the branch is dirty against current main and surface-budget defaults differ. The surface budgets have been corrected in this fix, but a clean rebase against main may still be needed before merge.
- **Compaction architecture direction:** The review suggested using the open compaction architecture discussion to decide whether multi-pass loops, progress thresholds, and public tracker exports belong in core. This is deferred to maintainer decision.
