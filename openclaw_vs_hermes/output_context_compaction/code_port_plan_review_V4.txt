             a. Parse as JSON
             b. Truncate string values > 200 chars
             c. Re-serialize
             d. On JSON parse failure: truncate raw string"

          Actual: ToolCall.arguments is Record<string, unknown> — already
          a parsed object, not a JSON string.

          In Hermes (Python), tool call arguments are stored as a JSON
          string (tc.function.arguments). In OpenClaw, they are stored as
          a parsed object (tc.arguments: Record<string, unknown>).

          FIX: Sub-pass 3 adapted to object-based truncation:
            a. Estimate serialized size: JSON.stringify(tc.arguments).length
            b. If > 500 chars: walk the object's values
            c. For string values > 200 chars: truncate with head + "...[truncated]"
            d. Return a new Record with truncated values (no JSON parse needed)

            (entry.message as HarnessMessage).role

          V4's predicate would never match because "role" is not a direct
          property of the entry — it's nested inside entry.message.

          FIX: Use (entry as MessageEntry).message.role to access the role,
          matching the existing code pattern in findValidCutPoints.

  FIX-4:  hasVisibleContent HELPER PROPERTY PATH CORRECTED (Step 4).

          Actual: For a MessageEntry, the content is at entry.message.content,
          not entry.content. The entry itself has { type, message, ... } —
          the content array lives on the message, not the entry.

          FIX: Access (entry as MessageEntry).message to get the AgentMessage,
          then check its content field.

  REF-2:  STALE compactParams ON SESSION ROTATION documented as limitation.

          params (including sessionId, sessionFile) to each pass. If a pass
          rotates the session (returns a new sessionId/sessionFile in the
          CompactResult), adoptTranscript updates the run-scope variables

          the updated session file on each compact() call.

          For context engine plugins that rotate sessions, subsequent passes
          would use stale session references. This is documented as a known
          limitation in the risk analysis.

     For AssistantMessage messages BEFORE the prune boundary:
       - Walk message.content blocks looking for type "toolCall"
       - ToolCall content block has fields:
           { type: "toolCall", id: string, name: string,
             arguments: Record<string, unknown> }
         NOT { toolCallId, toolName } — those are ToolResultMessage fields.

       - ToolCall.arguments is Record<string, unknown> (a parsed object),
         NOT a JSON string as in Hermes.

       - Truncation algorithm (adapted from Hermes's string-based approach):
         a. Estimate serialized size: JSON.stringify(tc.arguments).length
         b. If estimated size > 500 chars:
            - Walk the Record's values
            - For any string value > 200 chars: replace with
              value.slice(0, 150) + "...[truncated]"
            - Return a new Record with truncated values
         c. No JSON parse needed (already an object)
         d. Preserve object structure (only truncate leaf string values)

         mutating the original. Produce a new ToolCall block with the
         truncated arguments Record.

     RATIONALE FOR CHANGE:
       In Hermes (Python), tool_call.function.arguments is a JSON string.
       In OpenClaw (TypeScript), ToolCall.arguments is Record<string, unknown>.
       The truncation logic must work with parsed objects, not strings.
       JSON.stringify is used only for size estimation, not for data access.

STEP 4: Cut Point Enhancement (Message Anchoring)
────────────────────────────────────────────────────────────────────────────────

PURPOSE: Enhance findCutPoint() to anchor the last user message and last
substantive assistant message in the tail. This prevents the "active task
lost" and "can't see the output" bugs that Hermes resolved.

─── FILE: packages/agent-core/src/harness/compaction/compaction.ts (MODIFY)

  MODIFY: findCutPoint() function (line 388)

  After the existing cut-point selection algorithm (backward token walk),
  add two anchoring passes:

  CHANGE FROM V4: Property paths corrected to access role and content
  through entry.message (matching the existing code pattern using
  (entry.message as HarnessMessage).role).

  1. USER MESSAGE ANCHORING

     // After cut point is selected, ensure the last user message is in the tail.
     const lastUserIdx = findLastMessageIndex(entries, startIndex, cutIndex,
       (msg) => msg.role === "user");
     if (lastUserIdx >= 0 && lastUserIdx < cutIndex) {
       cutIndex = lastUserIdx;
     }

  2. ASSISTANT MESSAGE ANCHORING

     // Ensure the last assistant message with visible content is in the tail.
     const lastAssistantIdx = findLastMessageIndex(entries, startIndex, cutIndex,
       (msg) => msg.role === "assistant" && hasVisibleContent(msg));
     if (lastAssistantIdx >= 0 && lastAssistantIdx < cutIndex) {
       cutIndex = lastAssistantIdx;
     }

  3. SAFETY FLOOR

     cutIndex = Math.max(cutIndex, startIndex + 1);

  Both anchors are MONOTONIC: the tail can only grow, never shrink.
  This matches Hermes's behavior exactly.

  ADD HELPERS (file-local, not exported):

     import type { HarnessMessage } from "../types.js";
     import type { MessageEntry } from "../types.js";

     /**
      * Find the last message entry matching a predicate, searching backward
      * from `end` (exclusive) to `start` (inclusive).
      *
      * Uses (entry.message as HarnessMessage) to access the role, matching
      * the existing pattern in findValidCutPoints (line 323).
      */
     function findLastMessageIndex(
       entries: SessionTreeEntry[],
       start: number,
       end: number,
       predicate: (msg: HarnessMessage) => boolean,
     ): number {
       for (let i = end - 1; i >= start; i--) {
         const entry = entries[i];
         if (entry.type === "message") {
           const msg = entry.message as HarnessMessage;
           if (predicate(msg)) return i;
         }
       }
       return -1;
     }

     /**
      * Check if a HarnessMessage has visible text content (not just tool
      * calls or thinking blocks).
      */
     function hasVisibleContent(msg: HarnessMessage): boolean {
       // Access the content field from the underlying message.
       const content = (msg as any).content;
       if (!content) return false;
       if (typeof content === "string") return content.length > 0;
       if (Array.isArray(content)) {
         return content.some(
           (c: any) => c.type === "text" && typeof c.text === "string" && c.text.length > 0,
         );
       }
       return false;
     }

  ADDITIONAL DESIGN NOTE (per REF-2):

  D10: STALE compactParams ON SESSION ROTATION

       multiPassCompact receives compactParams once (a snapshot of
       sessionId, sessionKey, sessionFile at call time) and passes the
       same params to each contextEngine.compact() call. If pass N
       rotates the session (returns a new sessionId/sessionFile in
       CompactResult), adoptTranscript updates the run-scope variables,
       but compactParams retains the stale snapshot for pass N+1.

       For OpenClaw's default IN-PLACE compaction:
         - sessionId/sessionFile do not change → no issue
         - contextEngine re-reads the updated session file on each
           compact() call, seeing the new CompactionEntry from the
           previous pass → correct behavior

       For CONTEXT ENGINE PLUGINS that rotate sessions:
         - Subsequent passes would compact the old session → incorrect
         - Known limitation; such plugins should set maxPasses=1 or
           implement their own multi-pass logic

       This is acceptable for the MVP because:
         - In-place compaction is the default (and most common case)
         - Session rotation is an optional feature used by few plugins
         - maxPasses=1 provides an escape hatch for rotation plugins
