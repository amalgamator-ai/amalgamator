  This plan corrects 5 issues found during code-level verification of the
  V3 test plan against the actual OpenClaw codebase. See the companion
  test_plan_review_summary_V3.txt for full documentation of each issue.

  CORRECTIONS APPLIED:

  FIX-R1:  SUITE G MISSING TEST FOR "mode set, maxPasses absent" SCENARIO.

           V3 tests materializeCompactionConfig with:
             10.1: {} → expects maxPasses=3 (mode absent, defaults applied)
             10.3: {maxPasses:5} → expects maxPasses=5 (user value preserved)
             10.5: {mode:"safeguard",...,maxPasses:2} → all preserved

           MISSING: {mode:"safeguard"} WITHOUT maxPasses → should still get
           maxPasses=3 default. This is critical because the CURRENT
           applyCompactionDefaults has a guard:
             `if (compaction?.mode) return cfg;`
           which returns UNCHANGED when mode is set. The port plan must
           modify this to per-field defaulting (matching applyAgentDefaults
           pattern at defaults.ts:404-450). Without this test, a regression
           where mode-set blocks new defaults would go undetected.

           FIX: Added test 10.5a: materializeCompactionConfig({mode:"safeguard"})
           → expects maxPasses=3 AND minProgressThreshold=0.05 applied
           alongside the already-set mode. Existing test 10.5 renumbered
           to 10.5b. Tests 10.6→10.16 renumbered accordingly.

  FIX-R2:  SUITE E baseCompactParams INCOMPLETE — MISSING runtimeContext
           AND runtimeSettings.

           V3's baseCompactParams (Section 8, line 923-930) contains:
             { sessionId, sessionKey, sessionFile, tokenBudget, force,
               compactionTarget }

           ACTUAL compact() calls in run.ts (lines 2503-2519, 2707-2724)
           ALWAYS include runtimeContext and runtimeSettings. These are
           OPTIONAL in the ContextEngine.compact() type signature
           (types.ts:402-423), so tests compile without them. However:

           1. If multiPassCompact is supposed to thread these fields to
              each compact() call, tests should verify passthrough.
           2. Test 8.15 ("does not use stale compactParams") becomes more
              meaningful when the params actually contain the fields that
              the real code passes.

           FIX: Added minimal runtimeContext and runtimeSettings to
           baseCompactParams. Used simple shapes that satisfy the types
           without complex nested mocks. This aligns the mock with real
           call sites while keeping tests readable.

  FIX-R3:  SUITE E TEST 8.20 SETUP DESCRIPTION INCOMPLETE.

           V3 stated:
             "SETUP: Pass 1: 200000 → 191000 (4.5% reduction — below 5%).
              Do NOT pass minProgressThreshold."

           But the EXPECT clause says "After two consecutive sub-threshold
           passes, anti-thrash triggers." Two passes require two mock
           setups, but only one was described.

           FIX: Added explicit Pass 2 setup description:
             Pass 1: 200000 → 191000 (4.5% — below threshold, counter=1)
             Pass 2: 191000 → 183000 (4.2% — below threshold, counter=2)
           This makes the test implementable without ambiguity.

  FIX-R4:  MultiPassCompactResult TYPE UNDOCUMENTED.

           V3 uses `passesCompleted` field in Suite E expectations (8.1,
           8.2, 8.3, 8.6, 8.7) and Suite F harness mock, but never
           defines the return type of multiPassCompact. CompactResult
           (types.ts:126-141) does NOT have passesCompleted. So
           multiPassCompact returns an EXTENDED type.

           FIX: Added explicit type documentation in Section 3 (N1):

             type MultiPassCompactResult = CompactResult & {
               passesCompleted: number;
             };

           This documents that multiPassCompact returns the standard
           CompactResult fields PLUS passesCompleted. The mock factories
           (makeCompactSuccess etc.) produce CompactResult (for what
           engine.compact returns), while multiPassCompact wraps these
           with passesCompleted.

  FIX-R5:  SUITE D SOURCE FILE AMBIGUITY RESOLVED.

           V3 stated:
             "SOURCE: packages/agent-core/src/harness/compaction/compaction.ts
              (or packages/agent-core/src/harness/messages.ts depending on
              where prefix logic is placed)"

           The "or" clause creates ambiguity for test imports. The existing
           COMPACTION_SUMMARY_PREFIX and COMPACTION_SUMMARY_SUFFIX are in
           messages.ts. The port plan Step 5 adds new constants.

           FIX: Resolved to:
             - ENHANCED prefix constant → messages.ts (alongside existing
               COMPACTION_SUMMARY_PREFIX)
             - End marker constant → messages.ts (alongside existing suffix)
             - wrapCompactionSummary function → messages.ts (same file as
               the constants it uses)

           All Suite D imports now reference "../messages.js" consistently.
           This matches the existing OpenClaw convention: message-related
           constants and helpers live in messages.ts.

  N1: Suite E mock factory (inline in multi-pass-compaction.test.ts)

      multiPassCompact's RETURN TYPE is an extension of CompactResult:

        type MultiPassCompactResult = CompactResult & {
          passesCompleted: number;
        };

      This adds passesCompleted to the standard CompactResult. The
      engine.compact() method returns CompactResult; multiPassCompact
      wraps it with loop metadata.

      CompactResult (types.ts:126-141) is:
        { ok: boolean; compacted: boolean; reason?: string;
          result?: { summary?; firstKeptEntryId?; tokensBefore;
                     tokensAfter?; details?; sessionId?; sessionFile? } }

      Mock factories for engine.compact() return values:

      function createMockContextEngine() {
        return {
          info: { ownsCompaction: false },
          compact: vi.fn(async (): Promise<CompactResult> => ({
            ok: false,
            compacted: false,
            reason: "nothing to compact",
          })),
        };
      }

      function makeCompactSuccess(overrides: {
        tokensAfter?: number;
        tokensBefore?: number;
        summary?: string;
      } = {}): CompactResult {
        return {
          ok: true,
          compacted: true,
          result: {
            summary: overrides.summary ?? "Compacted session",
            tokensBefore: overrides.tokensBefore ?? 200000,
            tokensAfter: overrides.tokensAfter ?? 100000,
            firstKeptEntryId: "entry-5",
          },
        };
      }

      function makeCompactNotCompacted(reason: string): CompactResult {
        return { ok: true, compacted: false, reason };
      }

      function makeCompactFailure(reason: string): CompactResult {
        return { ok: false, compacted: false, reason };
      }
