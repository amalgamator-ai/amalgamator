1. TESTING STRATEGY OVERVIEW
================================================================================

  APPROACH: Pyramid-shaped test distribution.

    ─ Unit Tests (Suites A, B, C, D, G):  Pure-function tests that exercise
      individual modules in isolation. No mocking of the system-under-test;
      only dependencies are stubbed. These form the widest tier of the
      pyramid and execute fastest.

    ─ Component Tests (Suites E, H):  Test a single module (multiPassCompact,
      compaction-safeguard integration) with injected mock dependencies.
      These verify the loop orchestration logic and hook wiring.

    ─ Integration Tests (Suites F, I):  Test multi-module interaction via
      the embedded runner harness. Use vi.doMock() to replace upstream
      modules, then dynamically import the code-under-test. These are the
      narrowest tier but verify end-to-end data flow.

  TEST RUNNER: Vitest (OpenClaw standard). All tests use describe/it blocks,
  vi.fn() for mocks, vi.doMock() for module-level mocking with dynamic import.

  GUIDING PRINCIPLES:

    P1: Every test has exactly ONE assertion focus. Complex scenarios are
        split into multiple it() blocks for clarity.
    P2: Mock factories produce typed objects matching OpenClaw's actual
        type definitions (CompactResult, ToolCall, AgentMessage, etc.).
    P3: Token estimates use the 4-chars-per-token heuristic (OpenClaw's
        ESTIMATED_CHARS_PER_TOKEN = 4) for deterministic math.
    P4: All file imports use ".js" extension suffixes (OpenClaw ESM convention).
    P5: Test files are co-located with source files per OpenClaw convention.
    P6: No vi.mock() for the system-under-test; prefer dependency injection.
    P7: Boundary math is verified inline (comments proving the arithmetic).

  TOTAL PLANNED TESTS: 112 across 9 suites

    Function signature:
      compressionMadeProgress(
        origTokens: number,

    Adapted from Hermes's dual-dimension check (message count + token count).
    In OpenClaw, we only track token reduction because the session tree entry
    count is not directly visible to the multi-pass loop; token count is the
    primary metric from CompactResult.tokensAfter.

    4.1  it("returns true when token reduction exceeds threshold")
         INPUT:  origTokens=200000, newTokens=100000, threshold=0.05
         EXPECT: true (50% reduction >> 5%)

    4.2  it("returns false when token reduction is below threshold")
         INPUT:  origTokens=200000, newTokens=195000, threshold=0.05
         EXPECT: false (2.5% < 5%)
         MATH: 195000 < 200000 * 0.95 = 190000? → 195000 > 190000 → false ✓

    4.3  it("returns false when tokens are unchanged")
         INPUT:  origTokens=200000, newTokens=200000, threshold=0.05
         EXPECT: false (0% reduction)

    4.4  it("returns false when tokens increase")
         INPUT:  origTokens=200000, newTokens=210000, threshold=0.05
         EXPECT: false (negative reduction)

    4.5  it("returns true at exactly the threshold boundary")
         INPUT:  origTokens=200000, newTokens=190000, threshold=0.05
         EXPECT: true
         MATH: 190000 < 200000 * 0.95 = 190000? → NOT strictly less → false
         CORRECTION: Use newTokens=189999 for strict-less-than
         INPUT:  origTokens=200000, newTokens=189999, threshold=0.05
         EXPECT: true
         MATH: 189999 < 190000 → true ✓

    4.6  it("returns false at exactly one token above threshold")
         INPUT:  origTokens=200000, newTokens=190000, threshold=0.05
         EXPECT: false
         MATH: 190000 < 190000? → false ✓

    4.7  it("handles zero origTokens gracefully")
         INPUT:  origTokens=0, newTokens=0, threshold=0.05
         EXPECT: false (degenerate case — no division by zero)

    4.8  it("handles origTokens=1 edge case")
         INPUT:  origTokens=1, newTokens=0, threshold=0.05
         EXPECT: true (100% reduction)

    4.9  it("respects custom threshold of 10%")
         INPUT:  origTokens=100000, newTokens=91000, threshold=0.10
         EXPECT: false (9% < 10%)
         MATH: 91000 < 100000 * 0.90 = 90000? → 91000 > 90000 → false ✓

    4.10 it("respects custom threshold of 1%")
         INPUT:  origTokens=100000, newTokens=98500, threshold=0.01
