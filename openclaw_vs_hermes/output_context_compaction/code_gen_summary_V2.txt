1. CODE PATCH EXPLANATION
================================================================================

The code_gen_V2.patch implements Steps 1-6, 8 from the porting plan
(code_port_plan_review_V4.txt). Step 7 (embedded runner integration into
run.ts) is deferred as it requires careful integration with the 2800+ line
runner and its complex try-catch scoping.

The patch ports Hermes's multi-pass context compaction into OpenClaw:

STEP 1-2: Progress Detection & Anti-Thrashing (compaction-progress.ts)
  - Constants: MAX_COMPACTION_PASSES=3, PROGRESS_THRESHOLD=0.05,
    INEFFECTIVE_SAVINGS_THRESHOLD=0.10, MAX_INEFFECTIVE_COMPRESSIONS=2,
    DEFAULT_COMPACTION_TIMEOUT_MS=180_000
  - compactionMadeProgress(): token-only progress check (>5% threshold)
  - CompactionProgressTracker: tracks consecutive ineffective compressions
    across session lifetime, suppresses compaction after 2 consecutive <10%
    savings

STEP 3: Tool Result Pre-Pruning (pre-compaction-pruning.ts)
  - preCompactionPrune(): 3 sub-passes before LLM summarization:
    1. Deduplicate identical tool results (SHA-256 hash-based)
    2. Replace old tool results with 1-line summaries (per toolName)
    3. Truncate large tool call arguments (Record<string, unknown> values)
  - Uses OpenClaw's correct field names: ToolCall.id/name (not toolCallId/
    toolName) and ToolCall.arguments as Record (not JSON string)
  - Injected into compaction-safeguard.ts at line ~965

STEP 4: Cut Point Enhancement (compaction.ts findCutPoint modification)
  - User message anchoring: ensures last user message stays in tail
  - Assistant message anchoring: ensures last assistant with visible content
    stays in tail (skips tool-call-only assistant messages)
  - hasVisibleContent() uses structural type cast (not `as any`)
  - Safety floor: cutIndex >= startIndex + 1
  - Guard threshold: anchoring only fires when >= 3 entries available

STEP 5: Summary Prefix Disambiguation (messages.ts)
  - Enhanced COMPACTION_SUMMARY_PREFIX with "[COMPACTION — REFERENCE ONLY]"
    directive, "Do NOT answer questions" guidance, and "Respond ONLY to
    latest user message" instruction
  - New COMPACTION_SUMMARY_END_MARKER appended after </summary> tag
  - convertToLlm() updated to include end marker in compactionSummary case

STEP 6: Multi-Pass Compaction Loop (multi-pass-compaction.ts)
  - multiPassCompact(): iterates contextEngine.compact() until threshold met,
    progress stalls, max passes reached, or timeout/abort fires
  - MultiPassCompactionResult: per-pass diagnostics, stopReason, finalTokens
  - MultiPassCompactParams: adoptTranscript, runMaintenance callbacks for
    per-pass lifecycle management
  - Uses AbortSignal.any() for composed timeout (no polyfill needed — Node>=22)
  - Clamps maxPasses to [1, 10] at runtime

STEP 8: Configuration Schema Extension
  - Zod schema: maxPasses (int, 1-10), progressThreshold (float, 0<x<1)
  - TypeScript types: AgentCompactionConfig.maxPasses/progressThreshold
  - applyCompactionDefaults: per-field independent defaults (not blocked by
    existing mode guard)
