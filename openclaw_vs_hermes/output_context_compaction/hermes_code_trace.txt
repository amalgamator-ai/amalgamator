1. ARCHITECTURE OVERVIEW
================================================================================

The context compaction system has five architectural layers:

  ┌──────────────────────────────────────────────────────────┐
  │ LAYER 1: Decision Layer                                  │
  │   should_compress() — checks token count vs threshold    │
  │   should_compress_preflight() — rough pre-API estimate   │
  │   File: agent/context_compressor.py, agent/turn_context  │
  ├──────────────────────────────────────────────────────────┤
  │ LAYER 2: Multi-Pass Loop (Preflight)                     │
  │   Up to 3 iterations, 5% progress threshold             │
  │   File: agent/turn_context.py (lines 384–413)           │
  ├──────────────────────────────────────────────────────────┤
  │ LAYER 3: Orchestrator                                    │
  │   compress_context() — lock, compress, session mgmt      │
  │   File: agent/conversation_compression.py (314–825)      │
  ├──────────────────────────────────────────────────────────┤
  │ LAYER 4: Core Compressor Engine                          │
  │   ContextCompressor.compress() — prune, split, summarize │
  │   File: agent/context_compressor.py (2372–2683)          │
  ├──────────────────────────────────────────────────────────┤
  │ LAYER 5: Auxiliary LLM                                   │
  │   call_llm() for summary generation                      │
  │   File: agent/auxiliary_client.py                        │
  └──────────────────────────────────────────────────────────┘

Inheritance chain:
  ContextEngine (ABC)  →  ContextCompressor (default implementation)
  File: agent/context_engine.py → agent/context_compressor.py

The system supports pluggable engines (e.g., LCM) via the plugin system,
selected by config: context.engine = "compressor" | "<plugin_name>".

2. ENTRY POINTS & TRIGGER CHAIN
================================================================================

There are three distinct trigger paths for compaction:

─── PATH A: Post-Response Auto-Compress ───────────────────────────────────────

  File: agent/conversation_loop.py, lines 4280–4318

  After each LLM API response, the conversation loop checks token usage:

    1. Read last_prompt_tokens from the compressor
       - If > 0: use provider-reported prompt_tokens (most accurate)
       - If == -1: compression just ran, skip (sentinel)
       - If == 0: fall back to estimate_request_tokens_rough(messages, tools=)

    2. Call should_compress(_real_tokens)
       - Returns True when tokens >= threshold_tokens
       - Subject to anti-thrashing guard (_ineffective_compression_count >= 2)

    3. If True, call agent._compress_context(messages, system_message, ...)
       - Single pass; does not loop

─── PATH B: Preflight Compression (Multi-Pass) ────────────────────────────────

  File: agent/turn_context.py, lines 334–413

  Before each API call, the turn prologue runs a preflight check:

    Gate: _should_run_preflight_estimate(messages, protect_first_n,
                                          protect_last_n, threshold_tokens)
      - Passes when message count > protect_first_n + protect_last_n + 1
      - OR when estimate_messages_tokens_rough(messages) >= threshold_tokens

    Step 1: Compute _preflight_tokens via estimate_request_tokens_rough()
            (includes system prompt + tool schemas)
    Step 2: Check should_defer_preflight_to_real_usage(_preflight_tokens)
            - Defers when provider-reported post-compression tokens are known
              to fit and the rough estimate hasn't grown beyond tolerance
    Step 3: If not deferred and should_compress(_preflight_tokens):
            Execute multi-pass compression loop (up to 3 passes)

  This is the KEY multi-pass mechanism. See section 3 below for full detail.

3. MULTI-PASS LOOP (PREFLIGHT COMPRESSION)
================================================================================

File: agent/turn_context.py, lines 384–413

This is the core of the "multi-pass" system that distinguishes Hermes from
single-pass compactors. The loop runs up to 3 iterations, checking for
material progress after each pass.

  for _pass in range(3):
      _orig_len = len(messages)
      _orig_tokens = _preflight_tokens

      # Execute one compression pass
      messages, active_system_prompt = agent._compress_context(
          messages, system_message, approx_tokens=_preflight_tokens,
          task_id=effective_task_id,
      )

      # Re-estimate tokens after compression
      _preflight_tokens = estimate_request_tokens_rough(
          messages,
          system_prompt=active_system_prompt or "",
          tools=agent.tools or None,
      )

      # Check progress: break if no material improvement
      if not _compression_made_progress(
          _orig_len, len(messages), _orig_tokens, _preflight_tokens
      ):
          break  # Cannot compress further

      # Reset housekeeping state between passes
      conversation_history = conversation_history_after_compression(agent, messages)
      agent._empty_content_retries = 0
      agent._thinking_prefill_retries = 0
      agent._last_content_with_tools = None
      agent._last_content_tools_all_housekeeping = False
      agent._mute_post_response = False

      # Exit if below threshold
      if not _compressor.should_compress(_preflight_tokens):
          break

─── PROGRESS DETECTION ────────────────────────────────────────────────────────

  File: agent/turn_context.py, lines 41–61

  def _compression_made_progress(orig_len, new_len, orig_tokens, new_tokens):
      """Return True if compression materially reduced the request."""
      if new_len < orig_len:
          return True
      # Token reduction must be >5% to count as progress
      return orig_tokens > 0 and new_tokens < orig_tokens * 0.95

  Two dimensions of progress:
    1. Message count reduction (any decrease counts)
    2. Token count reduction (>5% decrease counts, even if message count same)
       - This handles "size-only" compression where tool outputs are
         summarized without removing message rows

─── PREFLIGHT GATE ────────────────────────────────────────────────────────────

  File: agent/turn_context.py, lines 64–89

  def _should_run_preflight_estimate(messages, protect_first_n,
                                     protect_last_n, threshold_tokens):
      """Cheap gate for the expensive full preflight token estimate."""
      # Count-based gate (cheap)
      if len(messages) > protect_first_n + protect_last_n + 1:
          return True
      # Char-based estimate (handles few-but-huge messages, issue #27405)
      return estimate_messages_tokens_rough(messages) >= threshold_tokens

  The char-based fallback catches the case where a handful of very large
  messages (e.g., massive tool outputs) don't trip the count gate but
  still exceed the context window.

The compress() method implements the main compaction algorithm in four phases:

  PHASE 1: Prune old tool results (cheap, no LLM call)
  PHASE 2: Determine head/tail boundaries
  PHASE 3: Generate structured LLM summary
  PHASE 4: Assemble compressed message list

    2. Summary message (role chosen to avoid consecutive same-role)
    3. Tail messages (from compress_end to end)

  Post-assembly cleanup:
    - _sanitize_tool_pairs() — fix orphaned tool_call/result references
    - _strip_historical_media() — remove base64 images from older messages

  Compression effectiveness tracking:
    savings_pct = (saved_estimate / display_tokens * 100)
    If savings_pct < 10: _ineffective_compression_count += 1
    Else: _ineffective_compression_count = 0

  See sections 8, 9, 10 for full detail.

5. TOOL OUTPUT PRUNING (CHEAP PRE-PASS)
================================================================================

File: agent/context_compressor.py, lines 990–1150
Method: _prune_old_tool_results()

Signature:
  def _prune_old_tool_results(self, messages, protect_tail_count,
                               protect_tail_tokens=None) -> tuple[list, int]

This is a cheap, LLM-free pre-pass that reduces context before the expensive
summary generation. Three sub-passes:

─── PRUNE BOUNDARY CALCULATION ────────────────────────────────────────────────

  When protect_tail_tokens is provided (default: self.tail_token_budget):
    - Walk backward accumulating msg_tokens per message
    - Stop when accumulated exceeds protect_tail_tokens AND at least
      min(protect_tail_count, len(result)) messages are protected
    - Convert to prune boundary index

  When only protect_tail_count:
    prune_boundary = len(result) - protect_tail_count

─── PASS 1: DEDUPLICATE IDENTICAL TOOL RESULTS ───────────────────────────────

  For each tool result (walking backward from end):
    - Compute MD5 hash of content (first 12 hex chars)
    - If hash seen before (newer copy exists), replace with:
      "[Duplicate tool output — same content as a more recent call]"
    - Only deduplicates content > 200 chars

─── PASS 2: REPLACE OLD TOOL RESULTS WITH 1-LINE SUMMARIES ───────────────────

  For messages BEFORE the prune boundary (old tool results):
    - Multimodal content: strip image parts, replace with placeholder
    - String content > 200 chars: replace with informative summary

  Summary function: _summarize_tool_result(tool_name, tool_args, tool_content)
  Produces strings like:
    [terminal] ran `npm test` -> exit 0, 47 lines output
    [read_file] read config.py from line 1 (1,200 chars)
    [search_files] content search for 'compress' in agent/ -> 12 matches
    [write_file] wrote to config.py (15 lines)
    [web_search] query='React hooks' (3,200 chars result)
    [patch] replace in config.py (450 chars result)

  Tool-specific handling for: terminal, read_file, write_file, search_files,
  patch, browser_*, web_search, web_extract, delegate_task, execute_code,
  skill_view/skills_list/skill_manage, vision_analyze, memory, todo,
  clarify, text_to_speech, cronjob, process.

─── PASS 3: TRUNCATE LARGE TOOL CALL ARGUMENTS ───────────────────────────────

  For assistant messages BEFORE the prune boundary:
    - Tool call arguments > 500 chars are truncated
    - Uses _truncate_tool_call_args_json() which:
      a. Parses as JSON
      b. Shrinks string values > 200 chars (keeps head + "...[truncated]")
      c. Re-serializes with ensure_ascii=False
      d. Preserves JSON validity (critical for strict providers)

6. HEAD/TAIL PROTECTION
================================================================================

─── HEAD PROTECTION ───────────────────────────────────────────────────────────

  File: agent/context_compressor.py

  _protect_head_size(messages) -> int:
    - System prompt (index 0) always protected if role == "system"
    - Plus protect_first_n additional messages (default: 3)
    - DECAYS after first compression: _effective_protect_first_n() returns 0
      when compression_count >= 1 or _previous_summary exists
    - Rationale: after first compaction, early turns are captured in summary

  _align_boundary_forward(messages, idx) -> int:
    - Slides compress_start past any orphan tool results
    - Ensures compression doesn't start mid-tool-group

─── TAIL PROTECTION (TOKEN-BUDGET BASED) ──────────────────────────────────────

  _find_tail_cut_by_tokens(messages, head_end, token_budget=None) -> int:

  Algorithm:
    1. Walk backward from end, accumulating tokens per message
    2. Stop when accumulated > soft_ceiling (1.5x token_budget)
       AND at least min_tail messages protected
    3. min_tail = min(min(protect_last_n, 8), available_tail - 2, available)
       - Capped at _MAX_TAIL_MESSAGE_FLOOR = 8 to prevent large tool outputs
         from making compression ineffective
       - Leaves at least 2 messages for summarization
    4. If entire transcript fits in soft_ceiling:
       - Re-walk with raw budget (no 1.5x) to find meaningful split
    5. Align to avoid splitting tool groups: _align_boundary_backward()

  Token estimation per message: _estimate_msg_budget_tokens(msg)
    - Content length / 4 + 10 (overhead)
    - Plus full tool_call envelope size (id, type, function.name, args)
    - This counts the FULL envelope, not just arguments, preventing
      2-15x undercounting on parallel tool-call turns

─── LAST-MESSAGE ANCHORING ────────────────────────────────────────────────────

  Two anchoring passes ensure critical messages stay in the tail:

  _ensure_last_user_message_in_tail(messages, cut_idx, head_end):
    - Finds the last user-role message at/after head_end
    - If it's in the compressed middle, pulls cut_idx back to include it
    - Prevents active task loss (issue #10896)

  _ensure_last_assistant_message_in_tail(messages, cut_idx, head_end):
    - Finds the last assistant message with visible content (not just tool_calls)
    - If it's in compressed middle, pulls cut_idx back
    - Prevents "can't see the output" bug (issue #29824)
    - Re-runs alignment to avoid splitting tool groups

  Both anchors are monotonic — tail can only grow, never shrink.
  Combined order: align → user anchor → assistant anchor
  Final safety: max(cut_idx, head_end + 1)

─── BOUNDARY ALIGNMENT ────────────────────────────────────────────────────────

  _align_boundary_backward(messages, idx):
    - Walk backward past consecutive tool results
    - If landed on parent assistant with tool_calls, pull boundary before it
    - Keeps entire assistant + tool_results groups together

  _align_boundary_forward(messages, idx):
    - Walk forward past orphan tool results at start of compression window

─── FALLBACK CHAIN ────────────────────────────────────────────────────────────

  On failure, the following fallback chain executes:

  1. If "no llm provider configured" → 600s cooldown, return None
  2. If aux model != main model AND not yet fallen back:
     - Model not found / timeout / JSON decode / streaming close:
       _fallback_to_main_for_compression(e, reason)
       → Clears summary_model, retries immediately with main model
     - Any other error:
       Same fallback to main model
  3. If already fallen back or same model:
     - Short cooldown (30–60s), return None
     - Network errors flagged with _last_summary_network_failure
     - Auth errors flagged with _last_summary_auth_failure

    - Assistant actions (tool call names)
    - Tool results (via _summarize_tool_result)
    - File path mentions (regex extraction)
    - Error/blocker text
    - Last dropped turns (up to 8)

  Capped at _FALLBACK_SUMMARY_MAX_CHARS = 8,000 chars.
  Per-turn cap: _FALLBACK_TURN_MAX_CHARS = 700 chars.

  _derive_auto_focus_topic(messages) -> Optional[str]

  - Skips context summary messages
  - Truncates each at 260 chars (_AUTO_FOCUS_TURN_MAX_CHARS)
  - Combines into "Recent user focus:\n- item1\n- item2..."
  - Total capped at 700 chars (_AUTO_FOCUS_MAX_CHARS)

  Step 2: Insert summary message
    - Role selection algorithm:
      a. If last_head_role is assistant/tool → summary_role = "user"
      b. Otherwise → summary_role = "assistant"
      c. If chosen role collides with first_tail_role, try flipping
      d. If both roles would create consecutive same-role → merge into tail

    - Standalone: append summary + _SUMMARY_END_MARKER as separate message
    - Merged: prepend summary + end marker into first tail message

    - Mark with COMPRESSED_SUMMARY_METADATA_KEY: True

  Step 3: Copy tail messages (indices compress_end to end)

─── POST-ASSEMBLY CLEANUP ─────────────────────────────────────────────────────

  1. _sanitize_tool_pairs(compressed):
     - Remove orphaned tool results (no matching assistant tool_call)
     - Insert stub results for orphaned tool_calls (result was summarized)
     - Stub content: "[Result from earlier conversation — see context summary above]"

  2. _strip_historical_media(compressed):
     - Find the newest user message with image content
     - Replace image parts in ALL messages before that anchor with
       "[Attached image — stripped after compression]"
     - Prevents multi-MB base64 payloads from surviving forever

─── EFFECTIVENESS TRACKING ────────────────────────────────────────────────────

  new_estimate = estimate_messages_tokens_rough(compressed)
  saved_estimate = display_tokens - new_estimate
  savings_pct = (saved_estimate / display_tokens * 100)

  self._last_compression_savings_pct = savings_pct
  if savings_pct < 10:
      self._ineffective_compression_count += 1
  else:
      self._ineffective_compression_count = 0

  self.compression_count += 1

The system supports iterative summary refinement across multiple compactions
within the same session, maintaining a running summary that gets updated

─── STATE ─────────────────────────────────────────────────────────────────────

  self._previous_summary: Optional[str] = None

  Set after successful summary generation.
  Cleared on:

    - on_session_end() — CLI exit, gateway expiry, session rotation

─── ITERATIVE UPDATE PROMPT ───────────────────────────────────────────────────

  When _previous_summary is set, the summarizer receives:

    "You are updating a context compaction summary. A previous compaction
     produced the summary below. New conversation turns have occurred since
     then and need to be incorporated.

     PREVIOUS SUMMARY:
     <previous_summary>

     NEW TURNS TO INCORPORATE:
     <content_to_summarize>

     Update the summary using this exact structure.
     PRESERVE all existing information that is still relevant.
     ADD new completed actions to the numbered list (continue numbering).
     Move items from 'In Progress' to 'Completed Actions' when done.
     Move answered questions to 'Resolved Questions'.
     Update 'Active State' to reflect current state.
     Remove information only if it is clearly obsolete.
     CRITICAL: Update '## Active Task' to reflect the user's most recent
     unfulfilled input..."

─── SUMMARY REHYDRATION ON RESUME ─────────────────────────────────────────────

  When a session is resumed, the compressor searches for existing handoff
  summaries in the message list via _find_latest_context_summary().
  If found, it rehydrates _previous_summary from the stored body.

  This enables continuity even after process restart: a resumed session
  can iteratively update its previous summary rather than generating
  a new one from scratch.

  _effective_protect_first_n():
    - First compaction: protect_first_n (default 3)
    - Subsequent compactions: 0 (decayed)
    - Rationale: early turns are captured in summary, no need to fossilize

11. ANTI-THRASHING & PROGRESS DETECTION
================================================================================

─── ANTI-THRASHING GUARD (SHOULD_COMPRESS) ────────────────────────────────────

  File: agent/context_compressor.py, lines 964–984

  def should_compress(self, prompt_tokens=None) -> bool:
      tokens = prompt_tokens or self.last_prompt_tokens
      if tokens < self.threshold_tokens:
          return False
      if self._ineffective_compression_count >= 2:
          logger.warning("Compression skipped — last %d saved <10%% each...")
          return False
      return True

  _ineffective_compression_count tracks consecutive compressions saving <10%.
  After 2 consecutive ineffective passes, compression is skipped entirely.
  Reset to 0 when a compression saves ≥10%.

─── MULTI-PASS PROGRESS DETECTION ────────────────────────────────────────────

  File: agent/turn_context.py, lines 41–61

  _compression_made_progress(orig_len, new_len, orig_tokens, new_tokens):
    Progress = message count decreased OR tokens decreased by >5%

─── PREFLIGHT DEFERRAL ────────────────────────────────────────────────────────

  should_defer_preflight_to_real_usage(rough_tokens) -> bool:

  Prevents re-compacting from noisy rough estimates after a compressed
  request already fit. Defers when:
    1. Rough estimate >= threshold (would trigger compression)
    2. awaiting_real_usage_after_compression is True (just compressed)
    3. OR last real prompt_tokens < threshold AND rough hasn't grown
       beyond tolerance (5% of threshold or 4096, whichever is larger)

─── NO-OP COMPRESSION GUARD ───────────────────────────────────────────────────

  In compress(), when compress_start >= compress_end:
    - Nothing to compress (transcript fits within tail budget)
    - Records as ineffective: _ineffective_compression_count += 1
    - Returns messages unchanged

  In compress(), when len(messages) <= _min_for_compress:
    - Too few messages to compress
    - Returns messages unchanged

12. SESSION ROTATION VS IN-PLACE COMPACTION
================================================================================

File: agent/conversation_compression.py, lines 486–825

Two modes, controlled by config: compression.in_place (default: False)

─── LEGACY ROTATION MODE (in_place=False) ─────────────────────────────────────

  1. Flush un-persisted messages to OLD session DB
  2. End the old session: _session_db.end_session(session_id, "compression")
  3. Generate new session_id: YYYYMMDD_HHMMSS_<hex>
  4. Update contextvar + env + logging context
  5. Create child session: create_session(parent_session_id=old_id)
  6. Migrate /goal to new session
  7. Auto-number title (e.g., "My Chat #2")
  8. Update system prompt in new session

  Rollback on failure:
    - Roll session_id back to parent
    - Reopen parent session
    - Propagate re-binding to contextvar/env/logging

─── IN-PLACE COMPACTION (in_place=True, #38763) ──────────────────────────────

  1. Call _session_db.archive_and_compact(session_id, compressed)
     - Soft-archives pre-compaction turns (active=0, kept for search)
     - Inserts compressed messages as new active set (active=1)
     - Single session_id for life
  2. Reset flush identity set (_flushed_db_message_ids)
  3. Set compacted_in_place = True flag

  Advantages:
    - No session rotation bugs
    - No parent_session_id chain
    - No title renumbering
    - No contextvar/env/logging re-sync needed
    - Old turns kept for search/recovery

─── POST-COMPACTION CALLBACKS (BOTH MODES) ────────────────────────────────────

  1. Memory extraction: agent.commit_memory_session(messages)
  2. Context engine notification: on_session_start(boundary_reason="compression")
  3. Memory manager notification: on_session_switch(reason="compression")
  4. Compression count warning: if count >= 2, emit degradation warning
  5. Event callback: "session:compress" event
  6. Post-compression token estimation
  7. File-read dedup cache reset
  8. Compression lock release

─── COMPRESSION LOCK ──────────────────────────────────────────────────────────

  SQLite-backed lock per session_id prevents concurrent compression:
  - try_acquire_compression_lock(session_id, holder)
  - release_compression_lock(session_id, holder)
  - Holder format: "pid=<pid>:tid=<tid>:agent=<hex>:nonce=<hex>"
  - If lock not acquired: return messages unchanged (abort)
  - Fail-open on broken lock subsystem (proceed without lock)

─── SIGNATURE ─────────────────────────────────────────────────────────────────

  def compress_context(
      agent: Any,

      system_message: str,
      *,
      approx_tokens: Optional[int] = None,

  1. Lazy feasibility check (first call only):
     check_compression_model_feasibility(agent)
     - Probes auxiliary compression model availability
     - Auto-lowers threshold if aux model context < main threshold
     - Rejects aux models with < 64K context

  2. Emit compaction status: COMPACTION_STATUS

  3. Acquire compression lock on old session_id

  4. Notify memory manager: on_pre_compress(messages)

  6. Check for abort: _last_compress_aborted flag
     - If True, return (messages, existing_system_prompt) unchanged

  7. Check for summary warnings:
     - _last_summary_error → emit fallback warning
     - _last_aux_model_failure_model → emit aux failure warning

  9. Invalidate and rebuild system prompt

  11. Post-compaction callbacks — see section 12

  12. Token estimation & diagnostics

  13. File-read dedup cache reset

  14. Release compression lock

  Callers detect no-op via: len(returned) == len(input)
  This stops retry loops when compression aborted.

  The _last_compress_aborted flag is also checked explicitly after the call.

17. ERROR HANDLING PATTERNS
================================================================================

─── SUMMARY GENERATION FAILURES ───────────────────────────────────────────────

  Cascading fallback:
    1. Aux model fails → retry on main model (one shot)
    2. Main model fails → enter cooldown + return None
    3. None summary:
       a. abort_on_summary_failure=True → abort (preserve messages)
       b. Auth failure → always abort
       c. Network failure → always abort
       d. Otherwise → build static fallback summary

  Cooldown periods:
    - No provider: 600s
    - JSON decode / streaming close: 30s
    - Other transient: 60s
    - Manual /compress bypasses cooldown (force=True)

─── COMPRESSION LOCK FAILURES ─────────────────────────────────────────────────

  - Lock not acquired: return messages unchanged (concurrent compression)
  - Lock subsystem broken (version skew): proceed without lock (fail-open)
  - Lock release failure: log debug, continue

─── SESSION ROTATION FAILURES ─────────────────────────────────────────────────

  - Child session creation fails: roll back to parent session
    - Reopen parent, restore contextvar/env/logging
    - Prevents orphan sessions
  - Goal migration failure: log debug, continue
  - Title propagation failure: log debug, continue

─── COMPRESS() METHOD INVARIANTS ──────────────────────────────────────────────

  - Never returns fewer messages than the protected head + tail
  - Always returns a valid OpenAI-format message list
  - Tool pairs are always sanitized (orphaned results removed, stubs added)
  - compress_start >= compress_end → return unchanged (no-op)
  - Too few messages → return unchanged
  - Summary failure (depending on config) → abort or fallback

─── PREFLIGHT LOOP INVARIANTS ─────────────────────────────────────────────────

  - Maximum 3 iterations (hard cap)
  - Breaks on no progress (neither message count nor >5% token reduction)
  - Breaks when should_compress() returns False (below threshold)
