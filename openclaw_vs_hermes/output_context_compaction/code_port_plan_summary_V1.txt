ITERATION 1 (V1) — Initial Plan:

  This is the initial iteration. The plan was generated from a clean
  analysis of both codebases with no prior iteration to build upon.

  KEY DECISIONS MADE IN V1:

  D1. GATEWAY LAYER PLACEMENT: The multi-pass loop lives in
      src/agents/multi-pass-compaction.ts, not in agent-core. This
      preserves agent-core's portability contract and follows OpenClaw's
      "core provides primitives, gateway provides policies" convention.

  D2. EXTEND, DON'T REPLACE: No existing OpenClaw compaction code is
      deleted or rewritten. The multi-pass loop wraps around the existing
      single-pass infrastructure.

  D3. SHARED TIMEOUT: All passes share one 180s timeout budget, preventing
      multi-pass from exceeding the safety timeout. Each pass gets the
      remaining budget, not a fresh timeout.

  D4. SESSION TREE COMPATIBILITY: Each pass appends a CompactionEntry to
      the session tree. This is safe because prepareCompaction() always
      finds the LAST compaction entry and builds from there.

  D5. PRE-PRUNING ONCE: Tool result pre-pruning runs once before the first
      pass, not per-pass, because subsequent passes operate on already-
      pruned content.

  D6. TOOL NAME ADAPTATION: The summarizeToolResult() function uses
      OpenClaw's tool names (Bash, Read, Write, Edit, Grep, Glob) instead
      of Hermes's (terminal, read_file, write_file, patch, search_files).

  D7. BACKWARD COMPATIBLE CONFIG: All new configuration fields are optional
      with defaults that enable multi-pass. Setting maxPasses=1 or
      multiPass.enabled=false reverts to single-pass behavior.

  SCOPE:
  - 6 new files, 8 modified files
  - 1 new external dependency: node:crypto (built-in, for MD5 hashing)
  - 0 new npm dependencies
  - Estimated implementation effort: 3-5 days

  NO PRIOR ITERATIONS TO COMPARE AGAINST.
