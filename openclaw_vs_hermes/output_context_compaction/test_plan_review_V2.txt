  This plan corrects 7 issues found during code-level verification of the
  V2 test plan against the actual OpenClaw codebase. See the companion
  test_plan_review_summary_V2.txt for full documentation of each issue.

  CORRECTIONS APPLIED:

  FIX-T1:  TEST 4.12 BOUNDARY MATH CORRECTED. V2 NOTE stated Hermes's
           `new_tokens < orig_tokens * 0.95` returns true for exactly 5%
           reduction (950 from 1000). This is WRONG: 950 < 950 is false.
           Exactly 5% reduction is NOT progress; you need >5% (strict <).
           Test expectation corrected to false.

  FIX-T2:  SUITE C MODEL NAME aligned with existing convention. V2 used
           `model: "test-model"` in inline helpers. Existing tests
           (compaction-trailing-toolresult.test.ts, compaction-image-tokens
           .test.ts) consistently use `model: "claude-fable-5"`. Corrected
           to match codebase convention.

  FIX-T3:  CompactResult TYPE DOCUMENTATION corrected. V2 IMP-6 claimed
           CompactResult is a "discriminated union." The actual type
           (context-engine/types.ts:126-141) is a flat type with
           `ok: boolean; compacted: boolean`. NOT a discriminated union
           with literal types. The mock factories produce valid objects
           (using `as const` for narrowing), but the documentation claim
           was inaccurate. Corrected throughout.

  FIX-T4:  SUITE F vi.doMock PATH CORRECTED. V2 specified
           `vi.doMock("../../multi-pass-compaction.js", ...)` in the
           harness extension. From the harness at
           `src/agents/embedded-agent-runner/run.overflow-compaction.harness.ts`:
             `../../` = `src/` (TWO levels up)
             `../` = `src/agents/` (ONE level up)
           The target module `src/agents/multi-pass-compaction.ts` is
           at `src/agents/`, so the correct path is
           `"../multi-pass-compaction.js"`, not `"../../..."`.
           Verified against 25+ existing vi.doMock paths in the harness:
             `../defaults.js` = `src/agents/defaults.js`
             `../auth-profiles.js` = `src/agents/auth-profiles.js`
           Pattern: one `../` from the harness reaches `src/agents/`.

  FIX-T5:  SUITE G CLAMPING LOCATION CLARIFIED. V2 tests 10.5 and 10.6
           assumed clamping in applyCompactionDefaults. Existing OpenClaw
           convention: applyCompactionDefaults ONLY sets missing defaults
           (currently only mode:"safeguard"). It does NOT clamp values.
           Range enforcement uses two layers:
             Layer 1: Zod schema `.min()/.max()` REJECTS out-of-range
             Layer 2: Runtime code clamps as belt-and-suspenders
           Tests 10.5/10.6 restructured: defaults section tests missing-
           value defaulting (10.1-10.4, 10.7-10.8); schema section tests
           range rejection (10.5a/10.6a added to Zod block); runtime
           clamping remains in Suite E (8.20).

  FIX-T6:  TESTS 4.15 AND 8.16/8.17 CONTRADICTION RESOLVED. V2 had:
           - Test 4.15: progressMade=false → continue: false (immediate)
           - Test 8.17: Loop continues after first sub-5% pass (tolerant)
           These are contradictory. Resolution: shouldContinueMultiPass
           does NOT check progressMade directly. It checks
           consecutiveNoProgress (a counter maintained by the caller).
           Test 4.15 removed. Test 4.18 remains as the sole no-progress
           exit test. New test 4.15 added for "continue when counter
           below threshold." Alignment with Hermes behavior clarified:
           Hermes breaks immediately; OpenClaw adds tolerance via the
           consecutiveNoProgress counter, which is an INTENTIONAL
           enhancement documented in the port plan.

  FIX-T7:  SUITE G materializeCompactionConfig TYPING improved. V2 used
           `Record<string, unknown>` with `as any`. Corrected to use the
           existing pattern from config.compaction-settings.test.ts which
           uses `NonNullable<...>` type narrowing on `OpenClawConfig`.

    4.12 it("returns false for exactly 5% token reduction (strict < threshold)")
         WHAT: Hermes uses `new_tokens < orig_tokens * 0.95`, which is a
               STRICT less-than. Exactly 5% reduction (950 from 1000) means

  -- describe("shouldContinueMultiPass") -------------------------------------------

    CHANGE FROM V2 (FIX-T6):

    The shouldContinueMultiPass function does NOT receive progressMade
    directly. It receives the consecutiveNoProgress counter maintained
    by the caller (multiPassCompact). The function's decision tree is:

      1. Check abortSignal.aborted → false, "aborted"
      2. Check passNumber >= maxPasses → false, "max_passes_reached"
      3. Check tokensAfter <= targetTokens → false, "target_reached"
      4. Check consecutiveNoProgress >= 2 → false, "anti_thrash"
      5. Otherwise → true (continue)

    The caller (multiPassCompact) runs compressionMadeProgress after each
    pass, increments/resets the counter, and passes it here.

    4.13 it("returns false when maxPasses reached")
         INPUT: { passNumber: 3, maxPasses: 3,
                  tokensAfter: 120000, targetTokens: 100000,
                  consecutiveNoProgress: 0 }
         EXPECT: { continue: false, reason: "max_passes_reached" }

    4.14 it("returns false when tokens are at or below target")
         INPUT: { passNumber: 1, maxPasses: 3, tokensAfter: 80000,
                  targetTokens: 100000, consecutiveNoProgress: 0 }
         EXPECT: { continue: false, reason: "target_reached" }

    4.15 it("returns true when counter below anti-thrash threshold")
         WHAT: A single no-progress pass does NOT stop the loop. The
               counter must reach 2 for anti-thrash exit. This is an
               INTENTIONAL enhancement over Hermes (which stops
               immediately) — it gives the compactor a second chance.
         INPUT: { passNumber: 1, maxPasses: 5,
                  tokensAfter: 120000, targetTokens: 100000,
                  consecutiveNoProgress: 1 }
         EXPECT: { continue: true }

    4.16 it("returns true when tokens above target and counter is zero")
         WHAT: Happy path: keep going.
         INPUT: { passNumber: 1, maxPasses: 3,
                  tokensAfter: 120000, targetTokens: 100000,
                  consecutiveNoProgress: 0 }
         EXPECT: { continue: true }

    4.17 it("returns false on abort signal")
         SETUP: const ac = new AbortController(); ac.abort();
         INPUT: { passNumber: 1, maxPasses: 3,
                  tokensAfter: 120000, targetTokens: 100000,
                  consecutiveNoProgress: 0, abortSignal: ac.signal }
         EXPECT: { continue: false, reason: "aborted" }

    4.18 it("returns false when consecutive no-progress count reaches 2")
         INPUT: { passNumber: 2, maxPasses: 5,
                  tokensAfter: 120000, targetTokens: 100000,
                  consecutiveNoProgress: 2 }
         EXPECT: { continue: false, reason: "anti_thrash" }
