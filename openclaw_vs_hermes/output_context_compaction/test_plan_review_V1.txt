1. TESTING STRATEGY OVERVIEW
================================================================================

  FRAMEWORK:     Vitest (matches OpenClaw's existing test infrastructure)
  RUNNER CONFIG: Existing vitest shard configs; new tests slot into shards
                 per Section 15.
  CO-LOCATION:   Test files placed adjacent to source files (OpenClaw
                 convention)
  NAMING:        {module}.test.ts for unit/integration
  MOCKING:       vi.hoisted() for module-level mocks, vi.fn() for function
                 stubs, vi.mock() with vi.importActual() for partial module
                 overrides, testing export pattern for dependency injection.

  COVERAGE GOALS:
    - Every new exported function has at least one happy-path and one error test
    - Every Hermes regression test that has a corresponding concept in the port
      has a mapped test case in OpenClaw
    - Every corrected property path (FIX-1 through FIX-5 in port plan Review V4)
      has an explicit assertion verifying the correct path
    - Configuration defaults and boundary values are tested
    - Abort/timeout propagation is tested at every async boundary

  DESIGN PRINCIPLES:
    DP-1: Test behavior, not implementation. Mock at module boundaries
          (LLM calls, contextEngine.compact, session I/O), not internal
          helpers.
    DP-2: Use OpenClaw's existing fixture factories (makeAgentAssistantMessage,
          makeAgentUserMessage, castAgentMessage from
          src/agents/test-helpers/agent-message-fixtures.ts) wherever possible.
          Only add new helpers for genuinely new patterns.
    DP-3: Token estimation mocks use the standard OpenClaw formula:
          Math.max(1, Math.ceil(textLength / 4)). For agent-core package tests,
          use the REAL estimateTokens (deterministic char/4 heuristic) matching
          existing compaction test conventions.
    DP-4: Each test suite is independently runnable.
    DP-5: No external service dependencies. All LLM calls are mocked.
    DP-6: No nested describe blocks. Use flat, sequential top-level describe
          blocks (matching OpenClaw convention).
    DP-7: Reuse existing harness infrastructure. New integration tests extend
          run.overflow-compaction.harness.ts rather than building a new harness.
