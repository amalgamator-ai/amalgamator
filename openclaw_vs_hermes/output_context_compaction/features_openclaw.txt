FEATURE #1: ACP Control Plane (Agent Session Lifecycle)
================================================================================
Category:       Core / Agent Runtime
Type:           Core (fundamental to operation)
Maturity:       MATURE

Description:
    The ACP (Agent Client Protocol) Control Plane is the central orchestrator
    for all agent session lifecycle, prompt execution, failover, and streaming.
    AcpSessionManager is the core public facade managing session initialization,
    turn execution, status queries, cancellation, and closure. It maintains
    per-session actor queues for serialized execution, LRU runtime handle
    caches with idle TTL eviction, and comprehensive observability snapshots
    (active sessions, turn latency, error counts).

Key Implementation Files:
    - src/acp/control-plane/manager.core.ts         (AcpSessionManager)
    - src/acp/control-plane/manager.turn-runner.ts   (turn orchestration)
    - src/acp/control-plane/manager.turn-stream.ts   (stream normalization)
    - src/acp/control-plane/manager.turn-timeout.ts  (timeout enforcement)
    - src/acp/control-plane/manager.backend-failover.ts (failover planning)
    - src/acp/control-plane/manager.runtime-handle-cache.ts (LRU cache)
    - src/acp/control-plane/manager.identity-reconcile.ts (session identity)
    - src/acp/control-plane/manager.types.ts         (type definitions)
    - src/acp/control-plane/session-actor-queue.ts   (serial execution)

Architecture Notes:
    - AcpSessionManager: initializeSession(), runTurn(), getSessionStatus(),
      setSessionRuntimeMode(), cancelSession(), closeSession()
    - SessionActorQueue prevents concurrent turns on same session
    - ManagerRuntimeHandleCache: LRU with idle TTL eviction
    - Turn pipeline: background task creation -> failover planning -> turn
      execution -> timeout handling -> cancellation -> completion recording
    - AcpTurnStreamOutcome: {sawOutput, sawTerminalEvent} for diagnosis
    - AcpManagerObservabilitySnapshot: {runtimeCache, turns, errorsByCode}
    - Backend failover with candidate planning and attempt tracking
    - Session identity reconciliation on startup and on-demand

Known Limitations:
    - None apparent from code; mature and well-tested

Quality: Working well

FEATURE #3: Context Engine System (Pluggable Context Management)
================================================================================
Category:       Core / Context Management
Type:           Core (fundamental to operation)
Maturity:       MATURE

Description:
    Pluggable context management system with support for windowing, compression,
    and compaction. ContextEngine interface defines bootstrap, maintain, ingest,
    assemble, compact, and subagent lifecycle methods. Legacy engine provides
    simple windowing; pluggable engines can be registered via the engine
    registry with fallback to "legacy".

Key Implementation Files:
    - src/context-engine/types.ts      (ContextEngine interface)
    - src/context-engine/legacy.ts     (legacy windowing engine)
    - src/context-engine/registry.ts   (engine resolution)

Architecture Notes:
    - ContextEngine interface: bootstrap?, maintain?, ingest, ingestBatch?,
      afterTurn?, assemble, compact, prepareSubagentSpawn?, onSubagentEnded?,
      dispose?
    - AssembleResult: {messages, estimatedTokens, promptAuthority, systemPromptAddition,
      contextProjection}
    - CompactResult tracks token reduction and summary
    - Legacy engine: simple windowing
    - Registry resolves engine by ID with fallback to "legacy"
    - Plugin-provided engines can replace the default
    - Context projection modes: "per_turn" | "thread_bootstrap"

Known Limitations:
    - Legacy engine is basic; advanced compression requires plugins
    - No built-in multi-pass summarization (unlike Hermes)

Quality: Working well (basic), extensible via plugins

FEATURE #8: Streaming Architecture
================================================================================
Category:       Core / UX
Type:           Core (fundamental to operation)
Maturity:       MATURE

Description:
    Message-based block streaming (not token-delta) with channel-specific
    chunking strategies. Coarse-grained output chunking as assistant writes.
    Configurable boundaries (text_end vs message_end), min/max character bounds
    with break preferences (paragraph, newline, sentence). Code fence
    preservation during splits. Coalescing to merge consecutive blocks.
    Human-like pacing delays between blocks.

Key Implementation Files:
    - docs/concepts/streaming.md               (streaming documentation)
    - src/agents/embedded-agent-runner/stream-wrapper.ts (stream wrapping)
    - src/agents/embedded-agent-runner/stream-resolution.ts (source strategy)
    - src/llm/utils/event-stream.ts            (EventStream class)
    - src/llm/anthropic-transport-stream.ts     (Anthropic streaming)
    - src/llm/openai-transport-stream.ts        (OpenAI streaming)

Architecture Notes:
    - Block streaming: coarse-grained chunks, not individual tokens
    - Preview streaming: platform-specific (Telegram, Discord, Signal)
    - EventStream<E, R>: events + result pattern
    - Streaming events: text_delta, text_end, tool_call, thinking_delta, done
    - Channel config: blockStreaming, textChunkLimit, chunkMode
    - Message-based: send + edit (not raw token deltas)
    - Discord: 17-line wrap protection (default)
    - Coalescing: merge consecutive blocks before sending
    - Human-like pacing: configurable delays between blocks
    - Code fence preservation during splits

Known Limitations:
    - Block-level streaming is coarser than token-level
    - Preview streaming limited to platforms that support message editing

Quality: Working well
