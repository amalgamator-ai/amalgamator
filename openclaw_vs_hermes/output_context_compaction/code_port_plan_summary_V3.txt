NEW ISSUES IDENTIFIED AND RESOLVED IN V3:

  V3-1: INJECTION POINT REFINED
    Previous iterations settled on "after line ~960" but did not account
    for the first splitPreservedRecentTurns at line 953. V3 places the
    injection at line ~965 (after structuredInstructions at ~964, before
    the provider path at ~970) and documents why the interaction with
    the prior split is benign.

  V3-2: COMPACTRESULT IMPORT PATH
    V2's compaction-progress.ts used the import path
    "../../../context-engine/types.js" for CompactResult. This path
    crosses package boundaries (from packages/agent-core to the gateway's
    src/context-engine/). V3 corrects this to "../types.js" (within
    agent-core's harness directory, where CompactResult is also defined).

  V3-3: TOOLCALL ADDITIONAL FIELDS
    ToolCall has thoughtSignature?: string and executionMode?: "sequential"
    | "parallel" fields not mentioned in prior iterations. V3 explicitly
    documents that these must be preserved during argument truncation.

  V3-4: THINKINGCONTENT EXCLUSION
    AssistantMessage.content includes ThinkingContent blocks. Prior
    iterations didn't explicitly mention excluding these when iterating
    for ToolCall blocks or checking for "visible text content" in
    anchoring. V3 adds explicit exclusion documentation.

  V3-5: TOOLRESULTMESSAGE DETAILS FIELD
    ToolResultMessage has a generic details?: TDetails field. V3
    explicitly documents preserving this field during content replacement
    in sub-pass 2.

  V3-6: baseMessagesToSummarize BRANCH FALLBACK
    baseMessagesToSummarize has a reassignment at line 898 for branch
    message fallback. V3 documents that pre-pruning at line ~965 operates
    on whatever value the variable holds at that point, regardless of
    which code path assigned it.

     generic `<T>`, meaning it returns whatever contextEngine.compact()
