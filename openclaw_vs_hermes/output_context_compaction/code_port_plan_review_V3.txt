REVIEW CHANGE LOG (V3 -> Review V3)
================================================================================

  This plan corrects 3 issues found during code-level verification of the
  V3 plan against the actual OpenClaw source code. Fixes:

  FIX-1:  CompactResult TYPE MISMATCH resolved. Two DIFFERENT types named
          "CompactResult" exist in the codebase:

            (A) Harness CompactResult (packages/agent-core/src/harness/types.ts:733)
                Fields: summary, firstKeptEntryId, tokensBefore, details
                Purpose: The result data that goes into a CompactionEntry
                         in the session tree.

            (B) Context Engine CompactResult (src/context-engine/types.ts:126)
                Fields: ok, compacted, reason?, result? { summary?,
                        firstKeptEntryId?, tokensBefore, tokensAfter?,
                        details?, sessionId?, sessionFile? }
                Purpose: The return type of ContextEngine.compact() and
                         compactContextEngineWithSafetyTimeout().

          V3 defined MultiPassCompactionResult.lastCompactResult in
          agent-core's compaction-progress.ts with:
            import type { CompactResult } from "../types.js";
          This imports the HARNESS CompactResult (A).

          But multiPassCompact() in the gateway layer works exclusively
          with the CONTEXT ENGINE CompactResult (B) — it checks .ok,
          .compacted, accesses .result?.tokensAfter, and passes results
          to adoptCompactionTranscript() which expects
          Awaited<ReturnType<typeof contextEngine.compact>>.

          These types are structurally INCOMPATIBLE:
            - (A) has .summary at top level; (B) has .ok at top level
            - (A) has no .ok or .compacted fields
            - (B) nests summary inside .result?

          Assigning a context-engine CompactResult to a field typed as
          harness CompactResult would cause a TypeScript compilation error.

          FIX: Move MultiPassCompactionResult to the gateway layer's
          multi-pass-compaction.ts, where it can correctly import the
          context-engine CompactResult type. MultiPassCompactionState
          (which has NO external type dependencies) stays in agent-core.
          Remove MultiPassCompactionResult from agent-core's index.ts
          exports — callers (run.ts) get it from the gateway import.

  FIX-2:  Variable scoping for timeoutCompactResult corrected. The
          existing code declares timeoutCompactResult with `let` OUTSIDE
          the try-catch so both the try body and catch body can assign it:

            let timeoutCompactResult: CompactResult;
            try {
              timeoutCompactResult = await compactContextEngine...(...);
            } catch (compactErr) {
              timeoutCompactResult = { ok: false, compacted: false, ... };
            }
            // use timeoutCompactResult below

          V3's replacement uses `const` INSIDE the try block:
            const timeoutMultiPassResult = await multiPassCompact({...});
            const timeoutCompactResult = ...;

          This breaks: if multiPassCompact unexpectedly throws, the catch
          block tries to assign timeoutCompactResult which isn't declared
          in its scope (it's const-scoped inside the try).

          FIX: Keep timeoutMultiPassResult as const inside the try, but
          assign to the existing `let timeoutCompactResult` variable
          (already declared before the try-catch). Same fix for the
          effectiveness tracking — keep it inside the try.

  FIX-3:  Agent-core index.ts exports corrected. Since
          MultiPassCompactionResult moves to the gateway layer, remove
          it from agent-core exports. Only export types/classes that
          belong in agent-core:
            - MultiPassCompactionState (no external deps)    KEEP
            - CompactionProgressTracker                      KEEP
            - compactionMadeProgress                         KEEP
            - Constants (MAX_COMPACTION_PASSES, etc.)         KEEP
            - CompactionProgressTrackerState                 KEEP
            - MultiPassCompactionResult                      REMOVE

  P10 DISTINGUISH THE TWO CompactResult TYPES
      OpenClaw has TWO incompatible types named "CompactResult":

        (A) Harness CompactResult (packages/agent-core/src/harness/types.ts:733)
            = { summary, firstKeptEntryId, tokensBefore, details? }
            Used in CompactionEntry storage.

        (B) Context Engine CompactResult (src/context-engine/types.ts:126)
            = { ok, compacted, reason?, result?: { tokensBefore,
                tokensAfter?, sessionId?, sessionFile?, ... } }
            Returned by ContextEngine.compact() and by
            compactContextEngineWithSafetyTimeout().

      The multi-pass system works with type (B) exclusively. Any code
      that crosses the agent-core / gateway boundary must reference
      the correct variant. Types that include CompactResult as a field
      MUST live in the same layer as their CompactResult import.

     import type { CompactResult } from "../context-engine/types.js";
     import type { MultiPassCompactionState } from "@openclaw/agent-core";

     /**
      * Result of a multi-pass compaction invocation.
      *
      * Lives in the gateway layer (not agent-core) because
      * lastCompactResult is typed as the context-engine CompactResult,
      * which is only importable from the gateway layer.
      */
     export interface MultiPassCompactionResult {
       /** All per-pass diagnostic states. */
       passes: MultiPassCompactionState[];
       /** Total passes executed. */
       totalPasses: number;
       /** Final token count after all passes. */
       finalTokens: number;
       /** Whether compaction brought context below the threshold. */
       metThreshold: boolean;
       /** Reason the loop stopped. */
       stopReason:
         | "threshold_met"
         | "no_progress"
         | "max_passes"
         | "timeout"
         | "aborted"
         | "anti_thrash";
       /** Total elapsed time across all passes in ms. */
       totalElapsedMs: number;
       /**
        * The CompactResult from the last successful pass.
        * This is the CONTEXT ENGINE CompactResult (with .ok, .compacted,
        * .result?.tokensAfter, .result?.sessionId, etc.).
        * Callers use this for post-loop lifecycle (token tracking, hooks).
        */
       lastCompactResult?: CompactResult;
     }

           result?: { tokensBefore, tokensAfter?, sessionId?, sessionFile?, ... }

  5. HELPER: buildResult()

     CHANGE FROM V3: Return type now references the gateway-local
     MultiPassCompactionResult (defined in this same file), NOT the
     agent-core version. Since both the type definition and the function
     are in the same file, the types are trivially compatible.

     function buildResult(
       passes: MultiPassCompactionState[],
       lastCompactResult: CompactResult | undefined,
       stopReason: MultiPassCompactionResult["stopReason"],
       startTime: number,
     ): MultiPassCompactionResult {
       const lastPass = passes[passes.length - 1];
       const finalTokens = lastPass?.tokensAfter ?? 0;
       return {
         passes,
         totalPasses: passes.length,
         finalTokens,
         metThreshold: stopReason === "threshold_met",
         stopReason,
         totalElapsedMs: Date.now() - startTime,
         lastCompactResult,
       };
     }

       - `lastCompactResult` parameter: CompactResult from context-engine ✓
       - Return type MultiPassCompactionResult.lastCompactResult:
         CompactResult from context-engine (same file) ✓
