1. CODE PATCH EXPLANATION
================================================================================

The V4 patch implements the Multi-Pass Context Compaction feature from
Hermes Agent, porting it to OpenClaw's TypeScript architecture. The
implementation follows the code_port_plan_review_V4.txt plan exactly,
covering Steps 1-9 (except Step 7: Embedded Runner Integration, which
is a larger integration deferred for separate work).

Key components:

  1. COMPACTION PROGRESS MODULE (agent-core layer)
     - compaction-progress.ts: Constants (MAX_COMPACTION_PASSES=3,
       PROGRESS_THRESHOLD=0.05, etc.), compactionMadeProgress() function,
       CompactionProgressTracker class for anti-thrashing
     - 24 tests covering boundary conditions, tracker state, constants

  2. PRE-COMPACTION PRUNING (gateway layer)
     - pre-compaction-pruning.ts: Three sub-passes:
       * Sub-pass 1: Hash-based deduplication of identical tool results
       * Sub-pass 2: 1-line summaries for old tool results (per-tool format)
       * Sub-pass 3: Truncation of large ToolCall arguments (Record-based)
     - Integrated into compaction-safeguard.ts at line ~965
     - 20 tests covering all sub-passes, boundary conditions

  3. CUT POINT ENHANCEMENT (agent-core layer)
     - findCutPoint() enhanced with user message anchoring and assistant
       message anchoring (monotonic tail growth)
     - findLastMessageIndex() and hasVisibleContent() helpers added
     - Uses correct property paths: (entry.message as HarnessMessage).role

  4. SUMMARY PREFIX DISAMBIGUATION (agent-core layer)
     - COMPACTION_SUMMARY_PREFIX enhanced with [COMPACTION -- REFERENCE ONLY]
       directive and "respond only to latest user message" instruction
     - COMPACTION_SUMMARY_END_MARKER added
     - convertToLlm() updated to include end marker
     - 8 tests for prefix content and wrapping behavior

  5. MULTI-PASS COMPACTION LOOP (gateway layer)
     - multi-pass-compaction.ts: multiPassCompact() function with:
       * Anti-thrashing gate (shouldSuppressCompaction check)
       * Composed AbortSignal (external + timeout via AbortSignal.any())
       * Per-pass lifecycle (adoptTranscript + runMaintenance)
       * Progress detection (compactionMadeProgress)
       * tracker.recordCompaction() called per-pass (V3 review fix)
       * maxPasses clamped to [1, 10]
     - 27 tests covering single-pass, multi-pass, abort, error, progress,
       configuration, anti-thrashing, and per-pass lifecycle

  6. CONFIGURATION SCHEMA EXTENSION
     - AgentCompactionConfig: maxPasses?, progressThreshold? added
     - Zod schema: maxPasses z.number().int().min(1).max(10),
       progressThreshold z.number().gt(0).lt(1)
     - applyCompactionDefaults: per-field defaults (not blocked by mode guard)
     - 16 tests covering defaults, schema validation, backward compatibility

  7. EXPORTS
     - CutPointResult added to agent-core index.ts
     - CompactionProgressTracker, compactionMadeProgress, and all constants
       exported from agent-core index.ts

================================================================================
5. KEY DESIGN DECISIONS
================================================================================

D1: Token-only progress detection (no message count dimension)
    Rationale: Multi-pass loop lacks direct access to message counts.
    Any meaningful compaction reducing messages also reduces tokens.

D2: Single timeout budget across all passes (not per-pass)
    Rationale: Matches Hermes behavior. AbortSignal.any() composes
    external abort + timeout into one signal.

D3: tracker.recordCompaction() called per-pass in the loop
    Rationale: V3 review found this was missing, making anti-thrash
    dead code in production. Each pass's effectiveness is recorded.

D4: maxPasses clamped to [1, 10] at runtime
    Rationale: Prevents configuration errors. Floor of 1 ensures at
    least one compaction attempt. Ceiling of 10 prevents runaway loops.

D5: Stale compactParams on session rotation (known limitation)
    Rationale: Default in-place compaction is unaffected. Session-rotation
    plugins should set maxPasses=1.
