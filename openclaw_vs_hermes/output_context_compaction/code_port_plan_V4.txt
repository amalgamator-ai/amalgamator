1. EXECUTIVE SUMMARY
================================================================================

  Port Hermes's multi-pass context compaction into OpenClaw, replacing
  single-pass compaction with an iterative loop that re-compacts until
  the token count meets the threshold or progress stalls. The port
  additionally brings over:

    - Progress detection with a 5% token-reduction threshold
    - Anti-thrashing guard (stop after consecutive ineffective passes)
    - Tool result pre-pruning before summarization
    - Enhanced summary prefix with disambiguation directives
    - Cut-point message anchoring (user/assistant tail protection)

  Core design constraints:
    - Agent-core (packages/agent-core/) stays dependency-free; types with
      gateway-layer deps must NOT live in agent-core
    - TWO structurally incompatible types share the name "CompactResult":
        (A) Harness CompactResult  — packages/agent-core/src/harness/types.ts:733
        (B) Context Engine CompactResult — src/context-engine/types.ts:126
      The multi-pass system exclusively uses type (B)
    - All run.ts modifications must preserve the existing `let` variable
      scoping for try-catch blocks

3. PORTING STRATEGY & PRINCIPLES
================================================================================

  P1  PRESERVE OPENCLAW'S COMPACTION STRENGTHS
      Keep: quality guard, staged summarization, recent-turns preservation,
      context pruning (cache-TTL), workspace context, identifier policies,
      context engine plugin system, safety timeout.

  P2  EXTEND, DON'T REPLACE
      The multi-pass loop wraps the existing single-pass compact() call.
      It does NOT modify the compaction-safeguard hook or the agent-core
      compaction internals. The hook still does the heavy lifting; the
      loop just iterates.

  P3  AGENT-CORE STAYS DEPENDENCY-FREE
      No imports from src/context-engine/ or src/agents/ into
      packages/agent-core/. Types that reference context-engine
      CompactResult MUST live in the gateway layer (src/agents/).

  P4  RESPECT EXISTING VARIABLE SCOPING
      run.ts declares timeoutCompactResult and compactResult with `let`
      before try-catch blocks. Replacements must ASSIGN to these existing
      variables, not create new `const` declarations that shadow them.

  P5  USE OPENCLAW FIELD NAMES AND PATTERNS
      - ToolResultMessage.toolCallId (not tool_use_id)
      - ToolResultMessage.toolName (not tool_call.function.name lookup)
      - ToolCall.toolName and ToolCall.arguments (not function.name/input)
      - Result<T, E> pattern for error returns
      - retryAsync for LLM call retries

  P6  IDIOMATIC TYPESCRIPT
      - Interfaces for data shapes, classes only where statefulness is needed
      - const enums / string unions for discriminated types
      - Readonly arrays for immutable data
      - Template literal types where useful

  P7  SINGLE TIMEOUT FOR ALL PASSES
      The 180s safety timeout covers the ENTIRE multi-pass invocation,
      not each individual pass. This prevents unbounded compaction time
      while allowing later passes (which process smaller context) to
      complete quickly.

  P8  PER-PASS LIFECYCLE CALLBACKS
      After each successful pass, call adoptTranscript and optionally
      runMaintenance before deciding whether to iterate. This ensures
      session state is consistent between passes.

  P9  REUSE shouldCompact FOR THRESHOLD CHECKS
      Import shouldCompact from @openclaw/agent-core as a STATIC import
      (not dynamic). Use it inside the loop to check if tokens are still
      above the compaction threshold.

  P10 DISTINGUISH THE TWO CompactResult TYPES
      Harness CompactResult (A) = { summary, firstKeptEntryId, tokensBefore }
      Context-Engine CompactResult (B) = { ok, compacted, reason?, result? }
      The multi-pass system works exclusively with type (B).
      MultiPassCompactionResult lives in the GATEWAY layer where it can
      import the correct type (B) from src/context-engine/types.ts.

STEP 2: Progress Detection & Anti-Thrashing Module
────────────────────────────────────────────────────────────────────────────────

PURPOSE: Port Hermes's _compression_made_progress() and
_ineffective_compression_count tracking into a reusable module.

─── FILE: packages/agent-core/src/harness/compaction/compaction-progress.ts

  (Same file as Step 1 — constants and types were added above.)

  4. FUNCTION: compactionMadeProgress

     Ported from: agent/turn_context.py lines 41-61

     /**
      * Returns true if a compaction pass materially reduced the context.
      *
      * Progress = message count decreased OR tokens decreased by more
      * than the configured threshold (default 5%). A sub-threshold
      * wobble does not count as progress and stops the multi-pass loop.
      *
      * @see https://github.com/nousresearch/hermes-agent — issue #39548
      */
     export function compactionMadeProgress(
       tokensBefore: number,
       tokensAfter: number,
       threshold: number = PROGRESS_THRESHOLD,
     ): boolean {
       if (tokensBefore <= 0) return false;
       return tokensAfter < tokensBefore * (1 - threshold);
     }

     DESIGN NOTE: Hermes's function also checks message count reduction
     (new_len < orig_len). In OpenClaw, the multi-pass loop does not have
     direct access to message counts (it calls contextEngine.compact() which
     returns token counts). Token-only progress detection is sufficient
     because:
       - Any meaningful compaction that reduces message count ALSO reduces
         token count
       - Token count is the metric that matters for context window fitting
       - Simplifies the interface (no need to pass message counts)

  5. CLASS: CompactionProgressTracker

     Ported from: ContextCompressor._ineffective_compression_count tracking

     /**
      * Tracks compaction effectiveness across invocations within a session.
      *
      * Records whether each compaction achieved meaningful savings (>= 10%
      * token reduction). After MAX_INEFFECTIVE_COMPRESSIONS (2) consecutive
      * passes below the threshold, the tracker signals that further
      * compaction should be suppressed to prevent thrashing.
      */
     export class CompactionProgressTracker {
       private consecutiveIneffective = 0;
       private lastSavingsPct = 0;
       private totalCompactions = 0;

       /**
        * Record the outcome of a compaction pass.
        * @param tokensBefore - Token count before compaction.
        * @param tokensAfter  - Token count after compaction.
        */
       recordCompaction(tokensBefore: number, tokensAfter: number): void {
         this.totalCompactions++;
         if (tokensBefore <= 0) {
           this.lastSavingsPct = 0;
           this.consecutiveIneffective++;
           return;
         }
         this.lastSavingsPct = (tokensBefore - tokensAfter) / tokensBefore;
         if (this.lastSavingsPct < INEFFECTIVE_SAVINGS_THRESHOLD) {
           this.consecutiveIneffective++;
         } else {
           this.consecutiveIneffective = 0;
         }
       }

       /**
        * Returns true if compaction should be suppressed due to
        * consecutive ineffective passes.
        */
       shouldSuppressCompaction(): boolean {
         return this.consecutiveIneffective >= MAX_INEFFECTIVE_COMPRESSIONS;
       }

       /** Reset tracker state (e.g., on session reset or /new). */
       reset(): void {
         this.consecutiveIneffective = 0;
         this.lastSavingsPct = 0;
         this.totalCompactions = 0;
       }

       /** Snapshot for diagnostics. */
       getState(): CompactionProgressTrackerState {
         return {
           consecutiveIneffective: this.consecutiveIneffective,
           lastSavingsPct: this.lastSavingsPct,
           totalCompactions: this.totalCompactions,
         };
       }
     }

STEP 3: Tool Result Pre-Pruning (Compaction-Safeguard Integration)
────────────────────────────────────────────────────────────────────────────────

PURPOSE: Add a cheap pre-pruning step before LLM summarization that replaces
old tool results with compact 1-line summaries. This reduces the input size
for summary generation, making each compaction pass more effective.

─── FILE: src/agents/agent-hooks/pre-compaction-pruning.ts (NEW)

  Ported from: agent/context_compressor.py lines 990-1150
  (_prune_old_tool_results)

  Adapts to OpenClaw's AgentMessage type system.

  1. FUNCTION: preCompactionPrune

     import type { AgentMessage, ToolResultMessage } from "@openclaw/agent-core";

     /**
      * Pre-compaction pruning: replaces old tool result contents with
      * informative 1-line summaries before LLM summarization.
      *
      * Three sub-passes:
      *   1. Deduplicate identical tool results (hash-based)
      *   2. Replace old tool results with 1-line summaries
      *   3. Truncate large tool call arguments
      *
      * @param messages - Messages to prune (will NOT be mutated).
      * @param protectTailCount - Number of recent messages to protect.
      * @returns A new message array with pruned content.
      */
     export function preCompactionPrune(
       messages: readonly AgentMessage[],
       protectTailCount: number,
     ): { pruned: AgentMessage[]; prunedCount: number }

  2. SUB-PASS 1: Deduplicate identical tool results

     For each ToolResultMessage, compute a content hash (first 12 hex chars
     of MD5 or SHA-256). Walk backward from end. If the same hash was seen
     already (newer copy exists), replace content with:
       "[Duplicate tool output — same content as a more recent call]"

     Only deduplicate content > 200 chars.

     Use OpenClaw field names:
       - message.role === "toolResult" (not "tool")
       - message.toolCallId (not tool_call_id / tool_use_id)
       - message.toolName (not looked up from assistant tool_calls)
       - message.content (ContentBlock[])

  3. SUB-PASS 2: Replace old tool results with 1-line summaries

     For messages BEFORE the prune boundary (old tool results):

     Build per-tool summaries using ToolResultMessage.toolName:
       - "Bash": ran `<command>` → exit <code>, <N> lines
       - "Read": read <path> (<N> chars)
       - "Write": wrote <path>
       - "Grep": searched for '<pattern>' → <N> matches
       - "Glob": searched for '<pattern>' → <N> results
       - "Edit": edited <path>
       - "WebFetch": fetched <url> (<N> chars)
       - Default: [<toolName>] (<N> chars result)

     Only summarize content > 200 chars.

  4. SUB-PASS 3: Truncate large tool call arguments

     For AssistantMessage messages BEFORE the prune boundary:
       - Walk message.content blocks looking for type "toolCall"
       - If ToolCall.arguments is a string > 500 chars:
         a. Parse as JSON
         b. Truncate string values > 200 chars (keep head + "...[truncated]")
         c. Re-serialize
         d. On JSON parse failure: truncate raw string with head + "...[truncated]"

     Use OpenClaw field names:
       - Content block: { type: "toolCall", toolCallId, toolName, arguments }
       - NOT { type: "tool_use", id, name, input }

     function findLastIndex(
       entries: SessionTreeEntry[],
       start: number,
       end: number,
       predicate: (entry: SessionTreeEntry) => boolean,
     ): number {
       for (let i = end - 1; i >= start; i--) {
         if (predicate(entries[i])) return i;
       }
       return -1;
     }

     function hasVisibleContent(entry: SessionTreeEntry): boolean {
       if (entry.type !== "message") return false;
       const msg = entry as any;
       if (!msg.content) return false;
       if (typeof msg.content === "string") return msg.content.length > 0;
       if (Array.isArray(msg.content)) {
         return msg.content.some((c: any) =>
           c.type === "text" && typeof c.text === "string" && c.text.length > 0
         );
       }
       return false;
     }

  5. FUNCTION: multiPassCompact

     /**
      * Execute multi-pass compaction: iterate until the token count
      * drops below the threshold or progress stalls.
      *
      * On each pass:
      *   1. Call contextEngine.compact()
      *   2. If successful, call adoptTranscript + runMaintenance
      *   3. Check progress (>5% token reduction)
      *   4. Check anti-thrashing
      *   5. Check if tokens are below threshold
      *
      * The loop is bounded by:
      *   - settings.maxPasses (default 3)
      *   - Total timeout across all passes
      *   - Progress stall detection
      *   - Anti-thrashing guard
      *   - External abort signal
      */
     export async function multiPassCompact(
       params: MultiPassCompactParams,
     ): Promise<MultiPassCompactionResult> {
       const {
         contextEngine,
         compactParams,
         settings,
         contextWindow,
         tracker,
         adoptTranscript,
         runMaintenance,
         timeoutMs = DEFAULT_COMPACTION_TIMEOUT_MS,
         abortSignal,
         logger: log,
       } = params;

       const maxPasses = settings.maxPasses ?? MAX_COMPACTION_PASSES;
       const progressThreshold = settings.progressThreshold ?? PROGRESS_THRESHOLD;
       const passes: MultiPassCompactionState[] = [];
       let lastCompactResult: CompactResult | undefined;
       const startTime = Date.now();

       // ── Anti-thrashing gate ──
       if (tracker.shouldSuppressCompaction()) {
         log?.warn?.(
           "[multi-pass] compaction suppressed by anti-thrashing guard " +
             `(${tracker.getState().consecutiveIneffective} consecutive ineffective passes)`,
         );
         return buildResult(passes, lastCompactResult, "anti_thrash", startTime);
       }

       // ── Create composed timeout signal ──
       const timeoutController = new AbortController();
       const timeoutId = setTimeout(() => timeoutController.abort(), timeoutMs);
       const composedSignal = abortSignal
         ? AbortSignal.any([abortSignal, timeoutController.signal])
         : timeoutController.signal;

       try {
         for (let pass = 0; pass < maxPasses; pass++) {
           const passStart = Date.now();

           // Check for abort/timeout before each pass
           if (composedSignal.aborted) {
             return buildResult(
               passes, lastCompactResult,
               abortSignal?.aborted ? "aborted" : "timeout",
               startTime,
             );
           }

           // ── Execute one compaction pass ──
           let compactResult: CompactResult;
           try {
             compactResult = await contextEngine.compact({
               ...compactParams,
               abortSignal: composedSignal,
             });
           } catch (err) {
             // Compaction threw — check if it was a timeout or abort
             if (composedSignal.aborted) {
               return buildResult(
                 passes, lastCompactResult,
                 abortSignal?.aborted ? "aborted" : "timeout",
                 startTime,
               );
             }
             throw err; // Re-throw unexpected errors
           }

           // ── Evaluate pass result ──
           if (!compactResult.ok || !compactResult.compacted) {
             // Pass did not compact — record and stop
             passes.push({
               pass,
               tokensBefore: compactResult.result?.tokensBefore ?? 0,
               tokensAfter: compactResult.result?.tokensAfter ?? compactResult.result?.tokensBefore ?? 0,
               madeProgress: false,
               elapsedMs: Date.now() - passStart,
             });
             return buildResult(passes, compactResult, "no_progress", startTime);
           }

           // ── Pass succeeded ──
           const tokensBefore = compactResult.result?.tokensBefore ?? 0;
           const tokensAfter = compactResult.result?.tokensAfter ?? tokensBefore;

           passes.push({
             pass,
             tokensBefore,
             tokensAfter,
             madeProgress: true,
             elapsedMs: Date.now() - passStart,
           });

           lastCompactResult = compactResult;

           // ── Per-pass lifecycle ──
           adoptTranscript(compactResult);
           if (runMaintenance) {
             await runMaintenance();
           }

           // ── Check if below threshold ──
           if (!shouldCompact(tokensAfter, contextWindow, settings)) {
             return buildResult(passes, lastCompactResult, "threshold_met", startTime);
           }

           // ── Check progress ──
           if (!compactionMadeProgress(tokensBefore, tokensAfter, progressThreshold)) {
             // Update pass state to reflect no progress
             passes[passes.length - 1].madeProgress = false;
             return buildResult(passes, lastCompactResult, "no_progress", startTime);
           }
         }

         // ── Exhausted max passes ──
         return buildResult(passes, lastCompactResult, "max_passes", startTime);
       } finally {
         clearTimeout(timeoutId);
       }
     }

  6. HELPER: buildResult

     function buildResult(
       passes: MultiPassCompactionState[],
       lastCompactResult: CompactResult | undefined,
       stopReason: MultiPassCompactionResult["stopReason"],
       startTime: number,
     ): MultiPassCompactionResult {
       const lastPass = passes[passes.length - 1];
       const finalTokens = lastPass?.tokensAfter ?? 0;
       return {
         passes,
         totalPasses: passes.length,
         finalTokens,
         metThreshold: stopReason === "threshold_met",
         stopReason,
         totalElapsedMs: Date.now() - startTime,
         lastCompactResult,
       };
     }

─── KEY DESIGN DECISIONS:

  D1: The loop calls contextEngine.compact() directly, NOT through
      compactContextEngineWithSafetyTimeout. The multi-pass function
      manages its own timeout via AbortSignal.any(). This:
        - Gives a single timeout budget across all passes
        - Avoids nested timeout wrappers
        - Allows later passes (operating on smaller context) more time

  D2: adoptTranscript is called after EACH successful pass (not just
      the last one). This ensures session state is consistent between
      passes. adoptCompactionTranscript in run.ts is idempotent (just
      updates session IDs/files), so multiple calls are safe.

  D3: runMaintenance is optional because:
      - The timeout path does NOT call runContextEngineMaintenance
      - The overflow path DOES call it
      - Providing it as an optional callback handles both call sites

  D4: shouldCompact is a STATIC import from @openclaw/agent-core.
      Verified: OpenClaw has no precedent for dynamic imports of
      @openclaw/agent-core. The function is pure (no side effects).

  D5: The tracker's shouldSuppressCompaction() is checked BEFORE the
      loop starts (gate). It is NOT checked per-pass (that's what
      compactionMadeProgress is for).

  D6: AbortSignal.any() is used to compose the timeout and external
      abort signals. This is a modern API (Node 20+). If OpenClaw
      targets older Node versions, a polyfill or manual composition
      would be needed.

  D7: The function does NOT re-estimate tokens between passes. Instead
      it relies on contextEngine.compact() to report tokensAfter in its
      result. This is simpler and more accurate than external estimation.

  D8: The progress threshold is configurable via settings.progressThreshold
      (default 5%), matching Hermes's 0.95 multiplier.

  D9: The anti-thrashing tracker is SHARED across invocations (passed
      in by the caller). This allows it to track consecutive ineffective
      compressions across the session lifetime, not just within one
      multi-pass invocation.

7. RISK ANALYSIS & MITIGATION
================================================================================

  RISK 1: Compaction loop runs too long under timeout
    Severity: Medium
    Mitigation: Single AbortSignal-based timeout covers all passes. Later
    passes operate on smaller context and are faster. Default 180s timeout
    is unchanged. maxPasses=3 caps iterations.

  RISK 2: Anti-thrashing false positives suppress needed compaction
    Severity: Low
    Mitigation: Tracker is per-session (reset on /new). Only triggers after
    2 consecutive ineffective passes. maxPasses=1 config restores single-pass.

  RISK 3: Per-pass adoptTranscript called multiple times
    Severity: Low
    Mitigation: adoptCompactionTranscript is verified idempotent — it only
    updates session IDs/files, and subsequent calls with the same values
    are no-ops.

  RISK 4: Pre-pruning modifies messages used by later stages
    Severity: Low
    Mitigation: preCompactionPrune returns a NEW array (no mutation). The
    compaction-safeguard hook uses the pruned copy; original messages are
    not modified.

  RISK 5: AbortSignal.any() compatibility
    Severity: Low-Medium
    Mitigation: AbortSignal.any() requires Node 20+. OpenClaw likely
    already targets this (check engines field). If not, use manual
    signal composition with listeners.

  RISK 6: Two CompactResult types cause confusion
    Severity: Medium (ongoing maintenance risk)
    Mitigation: MultiPassCompactionResult lives in gateway layer. Comments
    explicitly name "context-engine CompactResult" vs "harness CompactResult".
    Add a lint comment or documentation note.

  RISK 7: Enhanced summary prefix changes model behavior
    Severity: Medium
    Mitigation: The enhanced prefix adds only 3 core directives (shorter
    than Hermes's full prefix). Test with multiple models to ensure the
    disambiguation doesn't cause over-suppression. The original prefix
    structure (<summary>...</summary>) is preserved.

  RISK 8: findCutPoint anchoring makes compaction too conservative
    Severity: Low-Medium
    Mitigation: Anchoring is monotonic (tail only grows). Safety floor
    ensures at least 1 message is compressible. If anchoring prevents any
    compaction, the no-progress detection stops the loop cleanly.
