1. EXECUTIVE SUMMARY
================================================================================

This plan ports Hermes's multi-pass context compaction system into OpenClaw.
The core improvement: instead of a single compaction pass with a rigid 180s
timeout, wrap compaction in an iterative loop that:

  (a) runs up to MAX_COMPACTION_PASSES (3) sequential compaction passes,
  (b) measures progress after each pass (>5% token reduction),
  (c) stops early when context fits within the token budget OR progress
      stalls,
  (d) guards against thrashing via consecutive ineffective-compression
      tracking.

The plan also ports three complementary subsystems that make multi-pass
effective:

  - Pre-compaction tool result pruning with informative 1-line summaries
    (cheap LLM-free pass that shrinks context before expensive summarization)
  - Message anchoring in the tail (ensure last user/assistant messages
    survive compaction, preventing active-task loss)
  - Summary prefix disambiguation (prevent the model from treating
    compacted summaries as active instructions)

DESIGN PRINCIPLE: Extend, don't replace. OpenClaw's existing compaction
safeguard hook, quality guard, staged summarization, context pruning, and
session tree model are PRESERVED. The new multi-pass logic wraps AROUND
the existing single-pass infrastructure.

LAYER ASSIGNMENT:

  The multi-pass loop lives in the GATEWAY LAYER (src/agents/), NOT in
  agent-core. Rationale:

  1. agent-core's compact() is a stateless, single-pass primitive designed
     for portability across hosts (CLI, Copilot, Codex extensions). Making
     it multi-pass would break that contract.

  2. The gateway layer (embedded-agent-runner) already manages retry loops,
     timeout accounting, and session state — multi-pass is a natural
     extension of the existing retry infrastructure.

  3. The compaction-safeguard hook already overrides compact() behavior
     from the gateway layer — multi-pass wraps that same hook path.

  4. OpenClaw's architecture convention: agent-core provides primitives,
     gateway provides orchestration policies.

  Pre-compaction pruning lives INSIDE the compaction-safeguard hook
  (src/agents/agent-hooks/compaction-safeguard.ts), because:

  - Compaction reads from the session tree, not in-memory messages.
    Pruning in run.ts would have no effect on what gets summarized.
  - The safeguard hook receives preparation.messagesToSummarize and
    modifies it before sending to the summarizer.
  - Verified: the safeguard hook flow at lines 884-1278 applies multiple
    transformations (stripRuntimeContextCustomMessages, history pruning,
    preserved turn splitting) before summarization. Pre-pruning fits
    naturally AFTER strip (line 884) and BEFORE history pruning (line 1077).

COMPACTION CALL SITES (verified against actual source):

  OpenClaw has exactly TWO compactContextEngineWithSafetyTimeout() calls

  SITE 1: Timeout recovery          (run.ts line 2503)

    - Followed by runOwnsCompactionAfterHook (line 2749)

      into this overflow path — there is NO separate compaction call in
      attempt.ts

3. PORTING STRATEGY & PRINCIPLES
================================================================================

  P1  EXTEND, DON'T REPLACE
      - Existing compaction-safeguard hook, quality guard, staged
        summarization, context pruning, and session tree model are
        PRESERVED unchanged.
      - Multi-pass wraps around existing infrastructure.

  P2  IDIOMATIC TYPESCRIPT
      - Python classes -> TypeScript classes/interfaces
      - Python dicts -> TypeScript Record<string, unknown> or typed interfaces
      - Python Optional -> TypeScript `| undefined`
      - Python tuples -> TypeScript named return types or objects
      - Python f-strings -> TypeScript template literals
      - Python `for _pass in range(3)` -> TypeScript `for (let pass = 0; ...)`
      - Python `re.search` -> TypeScript `RegExp.exec()` or `.match()`
      - Python `json.loads/dumps` -> TypeScript `JSON.parse/stringify`
      - Python `hashlib.md5` -> Node.js `crypto.createHash('md5')`

  P3  FOLLOW OPENCLAW CONVENTIONS
      - Result<T, E> pattern for fallible operations
      - Structured logging via subsystem loggers
      - AbortSignal threading for cancellation
      - Worker threads for CPU-heavy planning
      - Hook-based extension points
      - Constants at module top, exported when cross-module

  P4  INCREMENTAL BUILDABILITY
      - Each step produces a compilable, testable increment
      - Steps 1-5 are independent leaf modules
      - Steps 6-7 integrate them into the run loop
      - Step 8 adds configuration
      - Step 9 adds tests

  P5  PRESERVE TIMEOUT SAFETY
      - The existing 180s safety timeout must encompass ALL passes, not
        reset per pass. Multi-pass shares one AbortSignal + one timeout
        window.

  P6  SESSION TREE COMPATIBILITY
      - Each compaction pass appends a CompactionEntry to the session tree
        (existing behavior via harness.compact() or the hook). Multi-pass
        means multiple CompactionEntry appends per invocation — this is
        safe because prepareCompaction() always finds the LAST compaction
        entry and builds from there.

  P7  PER-PASS LIFECYCLE
      - After each successful compaction pass:
        a. Call adoptCompactionTranscript() to update session ID/file
        b. Call runContextEngineMaintenance() for context engine sync
        c. Record effectiveness in CompactionProgressTracker
      - This matches OpenClaw's existing post-compaction lifecycle
        observed in the overflow recovery path (run.ts lines 2726-2738).

  P8  HOOK BOUNDARY PRESERVATION
      - runOwnsCompactionBeforeHook fires ONCE before multiPassCompact
      - runOwnsCompactionAfterHook fires ONCE after multiPassCompact
      - These remain at the caller level (run.ts), NOT inside the loop

  1. FUNCTION: compactionMadeProgress()

     Ported from: agent/turn_context.py lines 41-61

     /**
      * Determine whether a compaction pass materially reduced the context.
      *
      * Progress is detected when token count decreased by more than the
      * progress threshold (default 5%). This catches both content-reduction
      * (tool outputs summarized) and message-removal scenarios.
      *
      * Unlike Hermes, we do NOT check message count reduction as a separate
      * dimension. In OpenClaw's session tree model, "message count" requires
      * assembling context from tree entries — expensive and unnecessary when
      * token-based detection is sufficient.
      *
      * Ported from Hermes issue #39548 fix: size-only wins (same row count,
      * lower token count) were false-negatives with count-only detection.
      */
     export function compactionMadeProgress(
       origTokens: number,
       newTokens: number,
       progressThreshold: number = PROGRESS_THRESHOLD,
     ): boolean {
       if (origTokens <= 0) return false;
       return newTokens < origTokens * (1 - progressThreshold);
     }

  2. CLASS: CompactionProgressTracker

     Ported from: ContextCompressor._ineffective_compression_count and
     related tracking in agent/context_compressor.py lines 964-984.

     /**
      * Tracks compaction effectiveness across invocations within a session.
      *
      * Anti-thrashing: after MAX_INEFFECTIVE_COMPRESSIONS (2) consecutive
      * compaction invocations that each save < INEFFECTIVE_SAVINGS_THRESHOLD
      * (10%), shouldAttemptCompaction() returns false.
      *
      * Lifecycle: one instance per embedded-agent-runner session lifetime.
      * Reset on session clear/new session.
      */
     export class CompactionProgressTracker {
       private _ineffectiveCount = 0;
       private _lastSavingsPct = 0;
       private _compressionCount = 0;

       /** Record the outcome of a compaction invocation (all passes). */
       recordCompaction(tokensBefore: number, tokensAfter: number): void {
         this._compressionCount++;
         const savingsPct =
           tokensBefore > 0
             ? (tokensBefore - tokensAfter) / tokensBefore
             : 0;
         this._lastSavingsPct = savingsPct;
         if (savingsPct < INEFFECTIVE_SAVINGS_THRESHOLD) {
           this._ineffectiveCount++;
         } else {
           this._ineffectiveCount = 0;  // Reset on effective compression
         }
       }

       /** Anti-thrashing check: should we attempt compaction? */
       shouldAttemptCompaction(): boolean {
         return this._ineffectiveCount < MAX_INEFFECTIVE_COMPRESSIONS;
       }

       /** Reset tracker (session clear / new session). */
       reset(): void {
         this._ineffectiveCount = 0;
         this._lastSavingsPct = 0;
         this._compressionCount = 0;
       }

       /** Current state snapshot (for diagnostics/logging). */
       getState(): CompactionProgressTrackerState {
         return {
           ineffectiveCompressionCount: this._ineffectiveCount,
           lastCompressionSavingsPct: this._lastSavingsPct,
           compressionCount: this._compressionCount,
         };
       }
     }

  1. FUNCTION: summarizeToolResult()

     /**
      * Create an informative 1-line summary of a tool call + result.
      *
      * Replaces large tool outputs with a short description, e.g.:
      *   [Bash] ran `npm test` -> exit 0, 47 lines output
      *   [Read] read config.ts from line 1 (1,200 chars)
      *   [Write] wrote to config.ts (15 lines)
      *   [Grep] searched for 'compress' -> 12 matches
      *
      * Uses OpenClaw tool names and input field conventions.
      */
     export function summarizeToolResult(
       toolName: string,
       toolInput: Record<string, unknown> | string,
       resultContent: string,
     ): string

     Tool-specific handlers for OpenClaw's tool set:
       - "Bash" / "bash":
         `[Bash] ran \`{cmd}\` -> exit {code}, {n} lines output`
         cmd from input.command; exit code parsed from result with regex
         cmd truncated at 80 chars
       - "Read":
         `[Read] read {path} from line {offset} ({n} chars)`
         path from input.file_path; offset from input.offset ?? 1
       - "Write":
         `[Write] wrote to {path} ({n} lines)`
         path from input.file_path; line count from input.content
       - "Edit":
         `[Edit] edited {path} ({n} chars result)`
         path from input.file_path
       - "Grep":
         `[Grep] searched for '{pattern}' -> {n} matches`
         pattern from input.pattern; match count from result lines
       - "Glob":
         `[Glob] matched '{pattern}' -> {n} files`
         pattern from input.pattern; file count from result lines
       - "WebFetch":
         `[WebFetch] fetched {url} ({n} chars)`
         url from input.url
       - "WebSearch":
         `[WebSearch] searched '{query}' ({n} chars result)`
         query from input.query
       - "Agent":
         `[Agent] delegated: {description} ({n} chars result)`
         description from input.description (truncated 60 chars)
       - "NotebookEdit":
         `[NotebookEdit] edited {path} cell {n}`
         path from input.notebook_path
       - Default:
         `[{toolName}] ({n} chars result)`

     IMPLEMENTATION:
       - Parse toolInput with try/catch (may be string JSON)
       - Compute line count via resultContent.split('\n').length
       - Compute content length via resultContent.length
       - Return formatted string

  2. FUNCTION: pruneMessagesForCompaction()

     Ported from: _prune_old_tool_results(), adapted for AgentMessage[].

     /**
      * Cheap LLM-free pre-pass that reduces messagesToSummarize before
      * the expensive LLM summarization call.
      *
      * Three sub-passes:
      *   1. Deduplicate identical tool results (MD5 hash, keep newest)
      *   2. Replace old tool results with 1-line summaries
      *   3. Truncate large tool call arguments in assistant messages
      *
      * Operates on messages extracted from the session tree
      * (preparation.messagesToSummarize), NOT on the tree itself.
      *
      * @param messages       Messages to prune (from preparation)
      * @param keepRecentCount  Number of messages to protect at the end
      * @returns { messages: pruned list, prunedCount: count of pruned items }
      */
     export function pruneMessagesForCompaction(
       messages: AgentMessage[],
       keepRecentCount: number,
     ): { messages: AgentMessage[]; prunedCount: number }

     SUB-PASS 1: Deduplication
       - Walk backward through messages
       - For each message with role "toolResult":
         - Extract text content from content blocks
         - Skip if text length < 200 chars
         - Compute MD5 hash (first 12 hex chars)
         - If hash seen before (newer copy exists), replace all text
           content blocks with:
           "[Duplicate tool output — same content as a more recent call]"
       - Uses: import { createHash } from "node:crypto";

       TEXT EXTRACTION from OpenClaw AgentMessage:
         ToolResultMessage has: { role: "toolResult", tool_use_id, content }
         content is ContentBlock[]; extract text via:
           msg.content
             .filter(b => b.type === "text")
             .map(b => b.text)
             .join("")

     SUB-PASS 2: Old Tool Result Replacement
       - Protection boundary: keepRecentCount messages from the end
       - For messages BEFORE boundary with role "toolResult":
         - Find the corresponding assistant message (walking backward)
           that contains a tool_use block with matching id
         - Extract tool name and input from the tool_use block
         - Call summarizeToolResult(toolName, toolInput, textContent)
         - Replace content blocks with single text block containing summary
         - Only replace when text content > 200 chars

     SUB-PASS 3: Tool Call Argument Truncation
       - For assistant messages BEFORE boundary:
         - For each tool_use content block (type === "tool_use"):
           - Serialize input to JSON
           - If serialized length > 500 chars:
             - Deep-clone the input object
             - Call truncateToolCallInput(clone) to shorten string values
             - Replace the content block's input with the truncated clone

  3. FUNCTION: truncateToolCallInput()

     /**
      * JSON-aware truncation of tool call arguments.
      * Preserves JSON structure (critical for API wire format).
      * Truncates string values > maxStringValueChars with head + "...[truncated]".
      * Works on the parsed object, not raw JSON strings.
      */

  3. FUNCTION: multiPassCompact()

     import {
       compactionMadeProgress,
       MAX_COMPACTION_PASSES,
       PROGRESS_THRESHOLD,
       DEFAULT_COMPACTION_TIMEOUT_MS,
       type MultiPassCompactionResult,
       type MultiPassCompactionState,
     } from "@openclaw/agent-core";
     import { compactWithSafetyTimeout } from
       "./embedded-agent-runner/compaction-safety-timeout.js";

     /**
      * Run up to maxPasses sequential compaction passes, checking for
      * material progress after each. Stops when:
      *   - Token count is below the compaction threshold, OR
      *   - Progress stalls (<5% token reduction), OR
      *   - maxPasses exhausted, OR
      *   - Safety timeout fires, OR
      *   - AbortSignal is triggered, OR
      *   - Anti-thrashing guard blocks.
      *
      * Wraps the existing single-pass infrastructure.
      * The compaction-safeguard hook, quality guard, staged summarization,
      * and all existing features are preserved per-pass.
      *
      * LIFECYCLE PER PASS:
      *   1. Call compactWithSafetyTimeout → contextEngine.compact()
      *   2. adoptTranscript (session ID/file update)
      *   3. runMaintenance (context engine sync, if provided)
      *   4. Record effectiveness in tracker
      *   5. Check progress threshold
      */
     export async function multiPassCompact(
       params: MultiPassCompactParams,
     ): Promise<MultiPassCompactionResult> {

       const {
         contextEngine, compactParams, settings, contextWindow,
         tracker, adoptTranscript, runMaintenance,
         abortSignal, logger,
       } = params;

       const maxPasses = settings.maxPasses ?? MAX_COMPACTION_PASSES;
       const progressThreshold = settings.progressThreshold ?? PROGRESS_THRESHOLD;
       const timeoutMs = params.timeoutMs ?? DEFAULT_COMPACTION_TIMEOUT_MS;

       const passes: MultiPassCompactionState[] = [];
       const startTime = Date.now();
       let lastCompactResult: CompactResult | undefined;

       // ── Anti-thrashing gate ──
       if (!tracker.shouldAttemptCompaction()) {
         logger?.warn(
           "[multi-pass-compaction] skipped — last %d compressions saved <10%% each",
           tracker.getState().ineffectiveCompressionCount,
         );
         return buildResult(passes, lastCompactResult, "anti_thrash", startTime);
       }

       // ── Mutable copy of compactParams for session ID updates ──
       let currentParams = { ...compactParams };

       for (let pass = 0; pass < maxPasses; pass++) {
         // Check timeout budget — need at least 15s for a meaningful pass
         const elapsed = Date.now() - startTime;
         const remainingMs = timeoutMs - elapsed;
         if (remainingMs < 15_000) {
           logger?.warn(
             "[multi-pass-compaction] stopping — only %dms remaining (need 15s minimum)",
             remainingMs,
           );
           return buildResult(passes, lastCompactResult, "timeout", startTime);
         }

         // Check abort signal
         if (abortSignal?.aborted) {
           return buildResult(passes, lastCompactResult, "aborted", startTime);
         }

         const passStart = Date.now();

         // ── Run one compaction pass with remaining timeout budget ──
         let compactResult: CompactResult;
         try {
           compactResult = await compactWithSafetyTimeout(
             (signal) =>
               contextEngine.compact(
                 signal
                   ? { ...currentParams, abortSignal: signal }
                   : currentParams,
               ),
             remainingMs,
             abortSignal ? { abortSignal } : undefined,
           );
         } catch (err) {
           // Timeout or abort — exit loop
           logger?.warn(
             "[multi-pass-compaction] pass %d threw: %s",
             pass + 1, String(err),
           );
           return buildResult(
             passes,
             lastCompactResult,
             abortSignal?.aborted ? "aborted" : "timeout",
             startTime,
           );
         }

         const passElapsed = Date.now() - passStart;

         // ── Handle non-compaction result ──
         if (!compactResult.ok || !compactResult.compacted) {
           passes.push({
             pass,
             tokensBefore: compactResult.result?.tokensBefore ?? 0,
             tokensAfter: compactResult.result?.tokensBefore ?? 0,
             madeProgress: false,
             elapsedMs: passElapsed,
           });
           return buildResult(passes, lastCompactResult, "no_progress", startTime);
         }

         // ═══════════════════════════════════════════════════════════
         // PER-PASS LIFECYCLE (matches OpenClaw post-compaction pattern)
         // ═══════════════════════════════════════════════════════════

         // Step A: Update session ID/file if rotated
         adoptTranscript(compactResult);

         // Step B: Update params for next pass with potentially new session info
         if (compactResult.result?.sessionId) {
           currentParams = {
             ...currentParams,
             sessionId: compactResult.result.sessionId,
           };
         }
         if (compactResult.result?.sessionFile) {
           currentParams = {
             ...currentParams,
             sessionFile: compactResult.result.sessionFile,
           };
         }

         // Step C: Run context engine maintenance (if callback provided)
         if (runMaintenance) {
           await runMaintenance();
         }

         // Step D: Extract token counts
         const tokensBefore = compactResult.result?.tokensBefore ?? 0;
         const tokensAfter = compactResult.result?.tokensAfter ?? tokensBefore;

         // Step E: Record pass outcome
         lastCompactResult = compactResult;

         const madeProgress = compactionMadeProgress(
           tokensBefore, tokensAfter, progressThreshold,
         );

         passes.push({
           pass,
           tokensBefore,
           tokensAfter,
           madeProgress,
           elapsedMs: passElapsed,
         });

         logger?.info(
           "[multi-pass-compaction] pass %d: %d -> %d tokens (%.1f%% reduction, %dms)",
           pass + 1, tokensBefore, tokensAfter,
           tokensBefore > 0
             ? ((tokensBefore - tokensAfter) / tokensBefore) * 100
             : 0,
           passElapsed,
         );

         // ── Check if we're below the compaction threshold ──
         // Use agent-core's shouldCompact to check (simple threshold check)
         const { shouldCompact } = await import("@openclaw/agent-core");
         if (!shouldCompact(tokensAfter, contextWindow, settings)) {
           return buildResult(passes, lastCompactResult, "threshold_met", startTime);
         }

         // ── Check if progress stalled ──
         if (!madeProgress) {
           return buildResult(passes, lastCompactResult, "no_progress", startTime);
         }

         // ── Anti-thrashing check for next pass ──
         // NOTE: Don't record in tracker here; caller records overall
         // invocation effectiveness. This check is for cross-invocation.
         if (!tracker.shouldAttemptCompaction()) {
           return buildResult(passes, lastCompactResult, "anti_thrash", startTime);
         }
       }

       return buildResult(passes, lastCompactResult, "max_passes", startTime);
     }

  4. HELPER: buildResult()

     function buildResult(
       passes: MultiPassCompactionState[],
       lastCompactResult: CompactResult | undefined,
       stopReason: MultiPassCompactionResult["stopReason"],
       startTime: number,
     ): MultiPassCompactionResult {
       const lastPass = passes[passes.length - 1];
       const finalTokens = lastPass?.tokensAfter ?? 0;
       return {
         passes,
         totalPasses: passes.length,
         finalTokens,
         metThreshold: stopReason === "threshold_met",
         stopReason,
         totalElapsedMs: Date.now() - startTime,
         lastCompactResult,
       };
     }

─── KEY DESIGN DECISIONS:

  D1. TIMEOUT SHARING: The total timeout budget (default 180s) is
      SHARED across all passes. Each pass gets `remainingMs`, not a
      fresh timeout. Minimum 15s reserved per pass.

  D2. ABORT PROPAGATION: The external AbortSignal is threaded into each
      pass via compactWithSafetyTimeout. If the user cancels mid-loop,
      the current pass aborts and the loop exits cleanly.

  D3. TOKEN ESTIMATION: After each pass, tokens come from
      compactResult.result.tokensAfter (populated by OpenClaw's
      embedded compact.ts via estimateTokensAfterCompaction()). This
      is the PRIMARY source. Verified: compact.ts populates this field.

  D4. SESSION CONSISTENCY: Each pass appends a CompactionEntry to the
      session tree. On the next pass, prepareCompaction() finds this
      entry and builds from it. Multiple entries per invocation is safe.

  D5. PER-PASS LIFECYCLE: adoptTranscript() and runMaintenance() are
      called after EACH successful pass (not just once at the end).
      This ensures session ID/file updates propagate to the next pass
      and the context engine remains synchronized.

  D6. PRE-PRUNING SCOPE: Pre-pruning happens INSIDE the compaction-
      safeguard hook (Step 3), not in this module. Each pass fires the
      hook independently, and each hook invocation gets its own
      preparation.messagesToSummarize from the session tree.

  D7. TRACKER SCOPE: The tracker's recordCompaction is called by the
      CALLER (run.ts) after multiPassCompact returns, using the
      overall before/after tokens. The multi-pass loop only READS
      tracker.shouldAttemptCompaction() for the anti-thrashing gate.

  D8. shouldCompact IMPORT: Uses the agent-core shouldCompact function
      (line 236 in compaction.ts) which is a simple threshold check:
      contextTokens > contextWindow - settings.reserveTokens. This is
      correct for post-pass threshold checking — it answers "should we
      still compact?" not "should we preemptively compact?"

  D9. HOOK BOUNDARY: runOwnsCompactionBeforeHook and
      runOwnsCompactionAfterHook fire at the CALLER level (run.ts),
      once per multiPassCompact invocation. They are NOT invoked
      inside the multi-pass loop. This preserves the existing hook
      contract: one before/after notification per compaction event.

7. RISK ANALYSIS & MITIGATION
================================================================================

─── RISK 1: Timeout Exhaustion ────────────────────────────────────────────────

  RISK: Multi-pass consumes the entire 180s timeout budget, causing
  compaction to time out when it wouldn't have with single-pass.

  PROBABILITY: MEDIUM
  IMPACT: MEDIUM (compaction fails, context continues to grow)

  MITIGATION:
  a. Reserve minimum 15s per remaining pass before starting
  b. Log per-pass timing in MultiPassCompactionResult
  c. Default maxPasses=3 with typical 20-40s per pass = 60-120s total,
     well within the 180s budget
  d. Configurable timeoutMs per deployment
  e. Conditional fallback: isMultiPassEnabled(config) = false reverts to
     single-pass behavior

─── RISK 2: Session Tree Bloat ────────────────────────────────────────────────

  RISK: Each pass appends a CompactionEntry to the session tree.
  3 passes = 3 entries per compaction invocation.

  PROBABILITY: LOW
  IMPACT: LOW (entries are small, buildSessionContext uses only the LAST)

  MITIGATION:
  a. prepareCompaction() already skips entries before the last compaction
  b. Monitor session file growth in production telemetry
  c. CompactionEntry is compact (summary + metadata, no raw messages)

─── RISK 3: Pre-Pruning Summary Quality Impact ──────────────────────────────

  RISK: Tool result pruning replaces content that the summarizer needs,
  degrading summary quality.

  PROBABILITY: LOW
  IMPACT: MEDIUM (degraded summary quality)

  MITIGATION:
  a. Pre-pruning modifies messagesToSummarize (extracted from the session
     tree), NOT the persisted tree itself. Original content recoverable.
  b. Tail protection ensures recent tool results are never pruned
  c. 1-line summaries preserve key info (tool name, args, exit code, size)
  d. Pre-pruning can be disabled: prePruning.enabled = false in config
  e. Only tool results > 200 chars are pruned; small results kept intact

─── RISK 4: Message Anchoring Over-Protection ────────────────────────────────

  RISK: Message anchoring pulls too many messages into the tail, leaving
  insufficient content for the summarizer.

  PROBABILITY: LOW
  IMPACT: MEDIUM (compaction becomes a no-op)

  MITIGATION:
  a. Anchoring only activates when target message is NOT already in tail
  b. The existing minimum-for-compression check (too few messages guard)
     catches the case where anchoring leaves nothing to summarize
  c. Both anchors are monotonic — tail can only grow
  d. Re-alignment prevents orphaned tool pairs at the boundary

─── RISK 5: Anti-Thrashing False Positives ────────────────────────────────────

  RISK: Anti-thrashing guard blocks compaction prematurely, leading to
  context overflow.

  PROBABILITY: LOW
  IMPACT: HIGH (context overflow, potential data loss)

  MITIGATION:
  a. Overflow recovery uses force=true — but anti-thrashing gate is
     at the MULTI-PASS level, not the compaction call level. Even when
     the tracker blocks, the existing retry loop counter eventually
     exhausts and surfaces the error.
  b. Tracker resets on session switch/clear
  c. Anti-thrashing threshold (2 consecutive ineffective) matches
     Hermes's proven value
  d. Configurable: maxPasses=1 effectively disables multi-pass without
     disabling the tracker

─── RISK 6: Per-Pass Hook Invocations ────────────────────────────────────────

  RISK: The compaction-safeguard hook fires multiple times per multi-pass
  invocation.

  PROBABILITY: CERTAIN (by design)
  IMPACT: LOW (hook is designed for independent invocations)

  MITIGATION:
  a. Each pass gets its own CompactionPreparation from the session tree
  b. The hook's quality guard runs per-pass (desirable)
  c. Extension consumers get per-pass notifications (more granular data)
  d. The hook is idempotent — multiple invocations are safe

─── RISK 7: Summary Prefix Regression ────────────────────────────────────────

  RISK: Enhanced disambiguation prefix is longer and may affect model
  behavior (e.g., some models may handle longer prefixes differently).

  PROBABILITY: LOW
  IMPACT: LOW (prefix adds ~300 tokens, negligible vs 200K context)

  MITIGATION:
  a. COMPACTION_SUMMARY_PREFIX_MINIMAL available for fallback
  b. End marker can be independently tested
  c. Both variants are well-tested strings (Hermes has shipped the
     enhanced prefix through multiple iterations)

─── RISK 8: Result Mapping Correctness ────────────────────────────────────────

  RISK: Mapping MultiPassCompactionResult back to CompactResult for
  existing post-compaction code may miss edge cases (e.g., the
  two-branch adoption pattern at lines 2725 and 2767).

  PROBABILITY: LOW
  IMPACT: MEDIUM (incorrect session state or missing token tracking)

  MITIGATION:
  a. lastCompactResult preserves the FULL CompactResult from the final
     pass, compatible with all existing field accesses
  b. Both adoption branches (ok && compacted, compacted only) are
     subsumed by per-pass adoption in multiPassCompact
  c. Comprehensive test coverage for result mapping
  d. The conditional fallback (isMultiPassEnabled) provides a safe
     escape hatch if mapping issues surface
