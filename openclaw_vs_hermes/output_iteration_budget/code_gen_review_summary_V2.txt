ISSUE #1 [MEDIUM] — Type error: resolveAgentConfig(params.config, ...) with optional config
--------------------------------------------------------------------------
AFFECTED CODE:
  src/agents/embedded-agent-runner/run.ts, line 1586:
    resolveAgentConfig(params.config, sessionAgentId)?.iterationBudget

WHAT IS WRONG:
  `params.config` has type `OpenClawConfig | undefined` (from
  RunEmbeddedAgentParams, where `config?: OpenClawConfig`).
  `resolveAgentConfig` takes `cfg: OpenClawConfig` (non-optional).
  Under TypeScript strict mode (tsconfig.json has `"strict": true`),
  passing `undefined` to a non-optional parameter is a type error.

WHY IT MATTERS:
  While vitest's esbuild transformer doesn't do full type checking
  (and the full tsc OOMs in this environment), this would fail a
  production CI build with `tsc --noEmit`. The existing codebase's
  usage pattern (e.g. `resolveToolLoopDetectionConfig`) always guards
  the call: `params.cfg ? resolveAgentConfig(params.cfg, ...) : undefined`.

HOW FIXED:
  Added a ternary guard matching the codebase pattern:
    (params.config
      ? resolveAgentConfig(params.config, sessionAgentId)?.iterationBudget
      : undefined) ?? params.config?.agents?.defaults?.iterationBudget


ISSUE #2 [LOW] — Escaped backticks in JSDoc comment
--------------------------------------------------------------------------
AFFECTED CODE:
  packages/agent-core/src/types.ts, line 310:
    * The \`round\` parameter is a 1-based counter

WHAT IS WRONG:
  The backticks around `round` are unnecessarily escaped with
  backslashes (\`round\`). In a TypeScript JSDoc comment (not a
  template literal), backticks do not need escaping.

WHY IT MATTERS:
  The escaped backslashes appear literally in generated JSDoc
  documentation and IDE hover tooltips, showing "\`round\`"
  instead of "`round`". This is a cosmetic issue that reduces
  documentation readability.

HOW FIXED:
  Removed the backslash escapes:
    * The `round` parameter is a 1-based counter

ISSUE #6 [LOW] — Duplicate file entries in V2 patch
--------------------------------------------------------------------------
AFFECTED CODE:
  code_gen_V2.patch (the patch file itself)

WHAT IS WRONG:
  The V2 patch was generated by concatenating `git diff --cached HEAD`
  (staged new files) with `git diff HEAD` (all unstaged changes). The
  4 new files that were staged appeared in BOTH sections, creating
  duplicate diff entries. Applying this patch with `git apply` would
  fail on the second occurrence of each duplicate file.

WHY IT MATTERS:
  The patch is not safely applicable. `git apply code_gen_V2.patch`
  would error on the duplicate hunks for the 4 new files.

HOW FIXED:
  The review patch uses separate git diff commands that exclude the
  new files from the unstaged diff, preventing duplication. Each
  of the 18 files appears exactly once.
