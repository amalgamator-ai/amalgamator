  [FIX #1] RESTRUCTURED: Default value tests separated from merge tests.

  V3 ERROR: V3's section 3.1 "Default Values" called resolveAgentConfig()
  and expected per-field defaults to be filled in:

    const cfg = { agents: { defaults: { iterationBudget: { enabled: true } },
                             list: [{ id: "main" }] } };
    const resolved = resolveAgentConfig(cfg, "main");
    expect(resolved?.iterationBudget?.maxIterations).toBe(90); // WRONG

  ACTUAL: resolveAgentConfig() does SHALLOW MERGE only, matching the
  existing pattern for runRetries and contextLimits. Verified at
  agent-scope-config.ts lines 147-158:

    runRetries:
      typeof entry.runRetries === "object" && entry.runRetries
        ? { ...agentDefaults?.runRetries, ...entry.runRetries }
        : agentDefaults?.runRetries,

  The merge spreads defaults + override. It does NOT fill in per-field
  hardcoded defaults. If defaults only has { enabled: true }, the
  resolved object will be { enabled: true } — no maxIterations field.

  Per-field defaults (like base: 24 for runRetries) are applied at the
  CONSUMPTION SITE by a separate function (e.g., resolveMaxRunRetryIterations
  in run/helpers.ts lines 112-128):

    const base = Math.max(1, configRetries?.base ?? BASE_RUN_RETRY_ITERATIONS);

  The existing test at agent-scope.test.ts lines 152-180 confirms this:
  it provides ALL 4 runRetries fields in defaults and overrides only one
  in the per-agent entry. It tests MERGE, not default-filling.

  CORRECTED APPROACH: Split section 3.1 into two groups:

    Group A (Step 4 — in agent-scope.test.ts): Test MERGE behavior only.
      Provide all iterationBudget fields in defaults, override one or more
      in per-agent entry, verify merge produces correct result.
      Import: resolveAgentConfig from "./agent-scope.js"

    Group B (Step 5 — in a separate test or in FILE 4): Test per-field
      defaults. Import and test the Step 5 resolution function that applies
      hardcoded defaults (analogous to resolveMaxRunRetryIterations).
      Import: resolveIterationBudgetConfig from implementation location

  1-10: [UNCHANGED from V3.]

  11. [FIX #1] CONFIG RESOLUTION TWO-LAYER PATTERN:

    OpenClaw applies config defaults in TWO layers:

    Layer 1 (resolveAgentConfig): Shallow merge of defaults + per-agent
      overrides. Does NOT fill in hardcoded per-field defaults. Returns
      the merged config as-is.

    Layer 2 (consumption-site resolution): A function at the call site
      applies hardcoded defaults for missing fields. Example:
        resolveMaxRunRetryIterations() in run/helpers.ts:
          const base = configRetries?.base ?? BASE_RUN_RETRY_ITERATIONS;

    For iterationBudget, the port plan Step 5 creates the Layer 2 function.
    Tests must target the correct layer:
      - Merge tests (Step 4): call resolveAgentConfig, provide all fields
        in defaults, test override merging
      - Default tests (Step 5): call the consumption-site resolution
        function, test that missing fields get hardcoded values

  12. [FIX #2] emptyAssistantReplyIsSilent COMPUTATION:

    emptyAssistantReplyIsSilent is computed by
    shouldTreatEmptyAssistantReplyAsSilent() in run/incomplete-turn.ts.
    To trigger it in tests, set:
      - params.allowEmptyAssistantReplyAsSilent = true
      - attempt.assistantTexts = ["NO_REPLY"]
      - payloadCount = 0
      - attempt stopReason !== "error"
      - Not aborted, timed out, yielded, or with clientToolCalls

    When true, the result gets meta.terminalReplyKind = "silent-empty".

  13. VERIFIED ATTEMPT RESULT FIELDS:

    EmbeddedRunAttemptResult (run/types.ts) includes:
      - yieldDetected?: boolean (line 239) ← for yield guard test
      - clientToolCalls?: Array<{name, params}> (line 237) ← for client tool guard test
      - timedOut: boolean ← for timeout guard test
      - aborted: boolean ← for abort guard test
      - promptError: unknown ← for prompt error guard test
      - assistantTexts: string[] ← for payload count computation

    All fields are overridable via makeAttemptResult({ ...overrides }).

  14. CONFIG FIELD ON RUN PARAMS:

    RunEmbeddedAgentParams has `config?: OpenClawConfig` (run/params.ts
    line 134). overflowBaseRunParams does NOT include config. Budget tests
    add it via: { ...baseParams, config: makeBudgetConfig() }.
