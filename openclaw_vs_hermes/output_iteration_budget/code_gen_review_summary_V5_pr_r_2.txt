## Review Analysis

### Comment 1: [P1] Do not refund the budget before the forced summary turn

**Fix reviewed:** Removed `iterationBudget.refund()` at run.ts:3896, replaced
with a 5-line comment block explaining the fail-closed design.

**Assessment:** CORRECT. Verified end-to-end fail-closed behavior:
1. When the budget is exhausted, `budgetExhaustedSummaryPending` is set to
   true and the loop continues to the next iteration.
2. On the next iteration, the model receives the budget exhaustion summary
   instruction appended to the prompt (run.ts:1962).
3. If the model responds with text only: `onBeforeToolCallingRound` is never
   called, the summary text is extracted, and `buildBudgetExhaustedResult`
   returns the final result.
4. If the model ignores the no-tool instruction and requests tools:
   `onBeforeToolCallingRound` calls `consume()` which returns `false`
   (budget exhausted, remaining = 0). agent-loop.ts (line 363-367) then
   emits `turn_end` + `agent_end` and returns without executing any tools.
5. In both cases, no tools can execute after budget exhaustion. The budget
   is a hard cap.
