## PR Review Comments — Round 2

### Comment 1: [P1] Do not refund the budget before the forced summary turn

**Reviewer said:** When `forceSummaryOnExhaustion` is enabled, the refund at
`run.ts:3896` makes the next summary attempt pass `onBeforeToolCallingRound`
if the model ignores the no-tool instruction. The summary path should be
tool-disabled or fail closed. (Confidence: 0.89)

**Category:** Bug fix
**Priority:** Must-fix

**What was done:** Removed `iterationBudget.refund()` from the
`forceSummaryOnExhaustion` branch in `run.ts`. Replaced with a comment block
explaining the fail-closed design.

**Why this works:** The `onBeforeToolCallingRound` callback in agent-loop.ts
calls `iterationBudget.consume()`. With the budget exhausted (remaining = 0):
  - If the model responds text-only → `onBeforeToolCallingRound` is never
    called → summary completes normally → budget_exhausted result returned.
  - If the model ignores the instruction and requests tools →
    `consume()` returns `false` → agent-loop.ts emits `turn_end` + `agent_end`
    and returns without executing any tools → budget_exhausted result returned.

In both cases, no tools can execute after exhaustion. The budget is a hard cap
that cannot be bypassed.

**Added regression test:** Two new tests in `iteration-budget.test.ts` under
`"IterationBudget — summary path fail-closed"`:
  1. "blocks tools during forced summary when no refund is given" — proves
     `consume()` returns false after full exhaustion.
  2. "a refund before summary would incorrectly allow tool execution" —
     documents the anti-pattern that was fixed.
