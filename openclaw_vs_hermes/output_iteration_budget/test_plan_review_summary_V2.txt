FIX #6: FILE 6 runAgentLoop call signature wrong
  SEVERITY: Critical (would fail to compile -- wrong argument order)

  V2 BUG: All 4 tests in FILE 6 used:
    await runAgentLoop([], context, loopConfig, streamFn)
  Passing 4 arguments with streamFn as the 4th argument.

  ACTUAL: runAgentLoop has 7 parameters. The 4th is emit: AgentEventSink,
  NOT streamFn. streamFn is the 6th parameter. Verified at
  packages/agent-core/src/agent-loop.ts lines 172-196:

    export async function runAgentLoop(
      prompts: AgentMessage[],
      context: AgentContext,
      config: AgentLoopConfig,
      emit: AgentEventSink,       // <-- 4th is event callback
      signal?: AbortSignal,
      streamFn?: StreamFn,        // <-- 6th is stream function
      runtime?: AgentCoreStreamRuntimeDeps,
    ): Promise<AgentMessage[]>

  All 7 existing test calls (verified at lines 354, 426, 492, 571, 677,
  924, 988) use this pattern:
    runAgentLoop(messages, context, config, (_event) => {}, undefined, streamFn)

  FIX: Corrected all 4 test calls to pass 6 arguments:
    await runAgentLoop(
      [{ role: "user", content: "test", timestamp: Date.now() }],
      { systemPrompt: "test", messages: [], tools: [tool] },
      configWithCallback,
      (_event: AgentEvent) => {},    // 4th: emit (no-op)
      undefined,                      // 5th: signal
      streamFn,                       // 6th: stream function
    )


--- MODERATE ISSUES ---

FIX #4: FILE 4 makeBudgetConfig returns wrong config shape
  SEVERITY: Moderate (would produce invalid config at runtime)

  V2 BUG: V2's makeBudgetConfig returned:
    { iterationBudget: { enabled: true, maxIterations: 10, ... } }

  This is NOT a valid OpenClawConfig shape. The config field on
  RunEmbeddedAgentParams is typed as `config?: OpenClawConfig`.
  OpenClawConfig nests agent settings under `agents.defaults` and
  per-agent entries in `agents.list`.

  Verified: run.ts does NOT currently call resolveAgentConfig() directly
  (grep returned 0 hits). The port plan Step 8 will add budget config
  resolution. The config shape must be valid OpenClawConfig regardless
  of which resolution approach is used.

  FIX: Changed makeBudgetConfig to return correctly nested shape:
    {
      agents: {
        defaults: {
          iterationBudget: { enabled: true, maxIterations: 10, ... }
        }
      }
    } as OpenClawConfig


FIX #8: FILE 7 DEFAULT_LOOP_DETECTION_CONFIG is not exported
  SEVERITY: Moderate (test cannot import the constant directly)

  ACTUAL: DEFAULT_LOOP_DETECTION_CONFIG is declared as `const` (NOT

  Only exported items:

    - 4 functions (hashToolCall, detectToolCallLoop, recordToolCall,
      recordToolCallOutcome)

  FIX: Added OPTION A (preferred: Step 14 adds `export` to the constant)

--- Iteration 2 (V2) -> Iteration 2 Review (THIS DOCUMENT) ---

  Targeted verification against actual source code revealed 8 issues:
    3 Critical, 2 Moderate, 3 Minor

  Root causes of remaining issues:

  A) INCOMPLETE FILE DISCOVERY: V2 searched for "agent-scope-config.test.ts"
     and didn't find it, concluding no test file exists. But the actual
     test file has a slightly different name: "agent-scope.test.ts".
     Lesson: When checking if a test file exists, search for the
     function name being tested, not just the assumed file name.

  B) FUNCTION SIGNATURE NOT VERIFIED: V2 described runAgentLoop() calls
     with 4 arguments but the function actually takes 7 (with emit as
     4th). Lesson: Always read the actual function signature and verify
     against existing test call patterns.

  C) EXPORT STATUS NOT VERIFIED: V2 assumed DEFAULT_LOOP_DETECTION_CONFIG
     was importable. It's not exported. Lesson: Verify `export` keyword
     on constants before writing import-based tests.

  D) CONFIG SHAPE NOT VERIFIED: V2's makeBudgetConfig returned a flat
     structure that doesn't match OpenClawConfig's nested agents.defaults
     shape. Lesson: Check the actual type definition for config parameters,
     not just the existence of the config field.
