1. EXPLANATION OF THE TEST PLAN
================================================================================

The test plan covers all 16 implementation steps from the corrected V3 code
port plan, organized into 6 test files plus 2 supporting infrastructure files
(harness + fixtures). The plan targets an estimated 77-92 individual test
cases across unit and integration test levels.

--- Design Decisions ---

A) TEST ARCHITECTURE: LAYERED, MIRRORING THE PORT PLAN

  The tests follow the same 6-layer architecture as the port plan:

    Layer 1 (Core Module):     IterationBudget unit tests
    Layer 2 (Configuration):   Zod schema + config resolution tests
    Layer 3 (Agent-Core):      onBeforeToolCallingRound callback tests
    Layer 4 (Runner):          Run loop integration tests
    Layer 5 (Defaults):        Covered by config schema defaults tests
    Layer 6 (Testing):         The tests themselves

  This alignment ensures every implementation step has traceable test
  coverage, and tests can be written incrementally as each layer is built.

B) TESTING FRAMEWORK: VITEST (OpenClaw's standard)

  All tests use Vitest 4.1.8 with OpenClaw's established conventions:
    - *.test.ts colocated with source files
    - import { describe, it, expect, vi } from "vitest"
    - vi.fn() / vi.mock() / vi.doMock() for mocking
    - expect().toBe() / toEqual() / toHaveLength() assertions
    - beforeEach() for per-test isolation
    - Helper functions (not fixtures) for test data construction

C) HERMES TEST PORTING STRATEGY

  Hermes has 5 unit tests for IterationBudget and 22 tests for guardrails.
  The ported tests are adapted as follows:

    Ported directly:
      - consume-returns-false-when-exhausted (Hermes -> OpenClaw)
      - refund-restores-consume (Hermes -> OpenClaw)
      - used-reflects-consume-and-refund (Hermes -> OpenClaw)
      - remaining (Hermes -> OpenClaw)

    Dropped (not applicable):
      - Thread-safety test (Node.js is single-threaded)

    Added (OpenClaw-specific):
      - Zero-budget edge case (maxTotal=0)
      - Zod schema validation (OpenClaw uses Zod, Hermes uses YAML)
      - Config resolution with per-agent overrides (OpenClaw pattern)
      - Integration with run.ts retry mechanisms
      - Budget metadata in EmbeddedAgentRunResult
      - Regression scenarios from V3 review corrections (FIX #1-6)

D) INTEGRATION TEST STRATEGY

  The run.iteration-budget.test.ts file uses OpenClaw's established harness
  pattern (modeled on run.overflow-compaction.harness.ts). This pattern:
    - Uses vi.doMock() to replace ~40 module dependencies
    - Provides mockedRunEmbeddedAttempt for LLM attempt simulation
    - Uses makeAttemptResult() fixtures for standardized test responses
    - Queues multiple attempt results with .mockImplementationOnce()

  This allows testing the full budget lifecycle (creation -> consumption ->
  exhaustion -> summary -> result) without any real LLM calls or I/O.

E) COVERAGE OF V3 REVIEW CORRECTIONS

  Each correction from the V3 review has dedicated test coverage:

    FIX #1 (Harness property access):
      -> FILE 6: CoreAgentHarness.createLoopConfig maps its own property

    FIX #2 (!timedOut guard):
      -> FILE 4: "does NOT trigger budget exhaustion when attempt timed out"

    FIX #3 (!emptyAssistantReplyIsSilent, !yieldDetected):
      -> FILE 4: Two dedicated tests for silent completion and yield

      -> FILE 4: "fresh budget on failover model retry" (regression R3)
