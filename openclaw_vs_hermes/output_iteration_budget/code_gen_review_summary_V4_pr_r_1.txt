--- Fix 2: Count each budgeted tool round once ---
  STATUS: CORRECT

  Verification of removal:
  - The removed block (4 lines at original line 1941-1946) consumed budget
    on every outer-loop iteration — including non-productive retries
    (compaction, auth, timeout, empty-response, reasoning-only)
  - The onBeforeToolCallingRound callback (line 2167) remains as the sole
    consumption point: iterationBudget.consume() is called once per
    tool-calling round inside the agent-core inner loop

  Flow verification:
  1. Tool-calling rounds: Consumed once via onBeforeToolCallingRound. When
     consume() returns false, the inner loop checks shouldContinue === false
     and emits agent_end, returning control to the outer loop. ✅
  2. Non-tool iterations (compaction, auth, timeout retries): Not consumed.
     Each retry type has its own independent limit
     (MAX_OVERFLOW_COMPACTION_ATTEMPTS, maxReasoningOnlyRetryAttempts, etc.).
     In Hermes, analogous non-productive iterations are explicitly
     refunded via budget.refund(). ✅
  3. Budget exhaustion detection (line 3883): Fires when
     iterationBudget.remaining <= 0 after an attempt completes. Since the
     inner loop stops tool execution when budget is exhausted, the attempt
     returns with payloadCount=0, triggering the detection correctly. ✅
  4. Budget summary attempt (line 3895-3909): refund() gives back 1 unit.
     Summary attempt should produce text (no tool calls), so
     onBeforeToolCallingRound is not called. If the model unexpectedly
     requests tools, 1 call is allowed, then consume() returns false and
     the inner loop stops. ✅

  No issues found.
