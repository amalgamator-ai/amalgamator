1. V3 TEST PLAN EXPLANATION
================================================================================

The V3 test plan is a from-scratch rewrite that incorporates all lessons
learned across four previous iterations (V1, V1 Review, V2, V2 Review).
All prior corrections are incorporated as baseline — no FIX markers remain
because every issue from prior iterations has been absorbed into the plan's
foundation.

--- What V3 tests cover ---

7 test files (~81 tests total) across 3 NEW files and 4 EXTENDED files:

  FILE 1 (14 tests): IterationBudget class unit tests
    - Constructor, consume(), refund(), used/remaining properties
    - Edge cases: maxTotal=0, maxTotal=1, refund below 0
    - Complex interleaved consume/refund sequences
    - No thread-safety tests (Node.js single-threaded — intentional omission)

  FILE 2 (12 tests): Zod schema validation for iterationBudget config
    - Valid configurations (all fields, partial, empty, per-agent entries)
    - Boundary values (min=1, max=500, rejects 0/negative/non-integer)
    - Invalid inputs (wrong types, unknown properties)
    - Tests BOTH AgentDefaultsSchema AND AgentEntrySchema

  FILE 3 (11 tests): Config resolution / merge logic
    - Default value application (90/50/true/false)
    - Missing config handling (undefined, unknown agent)
    - Per-agent override + merge semantics (override replaces, unset inherits)
    - Case-insensitive agent ID resolution

  FILE 4 (32 tests): Integration tests for budget in run.ts main loop
    - Budget creation (enabled/disabled/absent)
    - Budget consumption per productive attempt
    - Budget exhaustion detection with 9-guard condition
    - Forced summary on exhaustion (with/without, refund, failure, stale instruction clearing)
    - Budget refund on compaction restart
    - Budget metadata in successful/exhaustion/disabled results
    - onBeforeToolCallingRound callback threading
    - Error kind extension (budget_exhausted in union type)
    - Interaction with existing retry mechanisms
    - Failover behavior (fresh budget on model failover)
    - Regression: runaway loop termination

  FILE 5 (7 tests): Budget-exhaustion result builder and instruction
    - Summary instruction content validation
    - Result builder output shape, metadata, summary/fallback payloads

  FILE 6 (4 tests): onBeforeToolCallingRound in agent-core inner loop
    - Callback invoked before tool-calling rounds
    - Callback return false stops execution
    - Undefined callback = no interference
    - Incrementing round number passed to callback

  FILE 7 (1 test): Tool loop detection default enabled change
    - Verifies DEFAULT_LOOP_DETECTION_CONFIG.enabled flipped to true

--- What is new in V3 vs V2 ---

V3 adds 7 new tests and refines 2 existing tests in FILE 4, driven by
the V3 port plan's corrected budget exhaustion condition:

  1. !timedOut guard test (4.3.7): Verifies budget exhaustion does NOT
     fire when the attempt timed out. Timeout handling takes priority.

  2. !emptyAssistantReplyIsSilent guard test (4.3.8): Verifies silent
     successful completions are NOT misclassified as budget failures.

  3. !attempt.yieldDetected guard test (4.3.9): Verifies voluntary
     agent yield is NOT overridden by budget exhaustion.

  4. Positive-path guard test (4.3.10): Confirms budget exhaustion
     DOES fire when all 9 exclusion guards are false.

  5. Stale instruction clearing test (4.4.5): Verifies that reasoning-only
     retry instructions are cleared before the summary attempt, preventing
     conflicting prompt content.

  6. Failover fresh budget test (4.10.1): Verifies budget resets to a
     fresh instance after FailoverError (not carried over from failed model).

  7. Failover metadata test (4.10.2): Verifies result metadata reflects
     only the successful post-failover budget usage.

All 7 new tests address specific scenarios identified in the V3 port plan
review (FIX #2 through FIX #5) that were NOT covered by V2.
