# Hybrid Backport Adapter

**pluggable resolver (tested: [synthmerge](https://gitlab.com/aarcange/synthmerge)) → deterministic gate → amalgamator → arbiter** — the hybrid backport flow: a fast conflict resolver does the bulk of the work, deterministic git-grep checks catch its mistakes, and the full agentic pipeline in this repo ([`auto_bug_fix`](../auto_bug_fix/README.md)) runs only for the cases that need it — seeded with the prior resolver's output, never from zero.

The adapter is the entire contract between two independent systems:

- **synthmerge** ([gitlab.com/aarcange/synthmerge](https://gitlab.com/aarcange/synthmerge))
  — a fast per-conflict LLM resolver (~seconds per case) with no
  tree-wide verification. It is the **tested implementation of the
  adapter's pluggable resolver front-end** (see below), not a hard
  dependency.
- **amalgamator** (`auto_bug_fix/` in this repo) — a full agentic
  backport pipeline (triage → seeded resolution → verification → blind
  review), ~13 min per escalated case

The adapter itself is two files in this directory. It needs only bash,
git, grep, and a python with this repo's dependencies.

## How it works

```
git worktree at base ──► git cherry-pick -x <upstream>
                                 │
                    clean ──► ship it                      (seconds)
                                 │
                    conflicts ──► conflict resolver — PLUGGABLE
                                  (tested: synthmerge)
                                 │
                                 ▼
                 check-backport.py — deterministic gate ($0, seconds)
                 · dead symbols in touched headers
                 · used-but-undefined symbols (hallucination detector)
                 · Makefile obj-* entries with no source
                                 │
                 clean ──► ship the resolver's commit       (fast path)
                                 │
                 findings ──► external-context.md + case yaml (generated
                              deterministically by this adapter)
                                 │
                                 ▼
                 amalgamator, seeded with the above         (~13 min)
                                 │
                                 ▼
                 B1 arbiter — re-run the same scans + diff-shape rule
                 · keep   → amalgamator result stands
                 · reject → fall back to the resolver's tree
```

**No LLM judgment in any decision boundary.** Escalation (finding count),
finding severity, and arbitration are all `git grep` / `git diff`
arithmetic. LLMs only write code. The gate's findings carry upstream
ground truth ("upstream still references this symbol in … — port it from
there" vs "not present upstream either — likely hallucinated, remove the
call"), which is what makes the escalation seed evidence rather than
suspicion.

Both artifacts the amalgamator consumes are generated by this adapter in
code — there is no manual or agent-authored step:

- the **case yaml**: a heredoc in `hybrid-backport.sh` (every key comes
  from the driver's arguments/state, including `external_context_file:`)
- the **external-context.md**: `check-backport.py
  --emit-external-context` (metadata regexed from the resolver's stdout,
  findings verbatim, per-file diffs of every file NOT named in a finding)

The consumer-side contract (how the amalgamator parses the MD into
per-phase prompt sections): [`docs/external-context.md`](
../docs/external-context.md).

## Pluggable resolver front-end

The conflict resolver is **pluggable, not baked in**. The gate, the
escalation, and the arbiter are resolver-agnostic: their only contract
with the resolver is **the git commit it leaves behind** — a completed
cherry-pick on top of the base (HEAD ≠ base, no unmerged paths).
Everything downstream is derived from `git diff base..HEAD`; nothing
asks who or what produced the tree.

What works against that contract:

| Front-end | Status |
|---|---|
| **plain git** (clean cherry-pick) | fully supported end-to-end today — no resolver involved at all; the gate and escalation run over git's own merge result |
| **a human** | supported at the component level: resolve and commit in a worktree, run `check-backport.py` on it, escalate with the generated MD + yaml. (The unattended driver cannot pause mid-run to wait for a human; wiring a pause/resume mode is the one missing convenience.) |
| **any tool** (mechanical applier, merge tool, other LLM resolver) | supported — anything that finishes the cherry-pick with a commit; swap the marked resolver seam in `hybrid-backport.sh` |
| **synthmerge** — [gitlab.com/aarcange/synthmerge](https://gitlab.com/aarcange/synthmerge) | **the tested implementation** and the default for the unattended path; all validation numbers below were produced with it |

Two design facts make this more than a claim:

- the **B1 arbiter already re-scans the amalgamator's own result tree**
  with the same checker — the spine is exercised over a second
  resolver's output on every escalation;
- the resolver's captured stdout is **optional provenance**: when it is
  absent or unrecognized, the external-context Metadata section degrades
  to `resolver: unknown` instead of claiming a tool that was not there.

Synthmerge-specific pieces, all confined to the driver's conflict phase:
its binary/config/LMDB-cache options, the `merge.conflictStyle=diff3`
environment it requires (scoped to that phase, unset before the
amalgamator), and the stdout regexes that recognize its log format.

## Usage

`--amalgamator-root` defaults to this repo's root (the parent of
`adapter/`), so from an amalgamator checkout the invocation is:

```bash
./adapter/hybrid-backport.sh \
    --repo /path/to/downstream/repo \
    --upstream <fix-commit-sha> \
    --base <ref> \
    --issue-id tc446 \
    --workdir /var/hybrid/tc446 \
    --gitscratch /var/hybrid/scratch \
    --synthmerge-bin /usr/local/bin/synthmerge \
    --synthmerge-config endpoints.yaml \
    --synthmerge-cache /var/hybrid/lmdb \
    --python /path/to/venv/with/this/repo/deps/bin/python \
    --model openai/<model-id> \
    --api-base https://endpoint/v1 \
    --api-key-file /secrets/key \
    --context-length 393216
```

Every flag also has an env equivalent (`MODEL`, `API_BASE`, `API_KEY_FILE`,
`CONTEXT_LENGTH`, `SYNTHMERGE_BIN`, `SYNTHMERGE_CONFIG`, `SYNTHMERGE_CACHE`,
`PYTHON`, `AMALGAMATOR_ROOT`); flags win.

| Flag | Required | Default |
|---|---|---|
| `--repo` | yes | — |
| `--upstream` | yes | — |
| `--synthmerge-config` | yes* | — |
| `--synthmerge-cache` | yes* | — |
| `--model` | yes | — (`openai/<model-id>` form) |
| `--api-base` | yes | — |
| `--api-key-file` | yes | — (dummy file works for unauthenticated endpoints) |
| `--amalgamator-root` | no | this repo's root (parent of `adapter/`) |
| `--base` | no | `HEAD` of `--repo` |
| `--issue-id` | no | `hybrid-<first 12 of upstream>` |
| `--workdir` | no | `mktemp -d` |
| `--gitscratch` | no | same as `--workdir` |
| `--python` | no | `python3` |
| `--synthmerge-bin` | no* | `synthmerge` on PATH |
| `--context-length` | no | `128000` |

\* the three `--synthmerge-*` flags exist only because the default/tested
resolver is [synthmerge](https://gitlab.com/aarcange/synthmerge); a
different resolver plugged into the driver's marked seam would carry its
own options instead.

### What you get

Branches created in the source repo:

| Branch | Contents |
|---|---|
| `hybrid/<issue-id>` | the pre-gate resolver result — **the deliverable on the fast path or after an arbiter rejection** |
| `amalgamator/<issue-id>` | the escalated result — **the deliverable when the arbiter keeps it** |
| `amalgamator-rejected/<issue-id>` | a rejected escalation, preserved for study only |

Artifacts under `--workdir` (full audit trail): `cherry-pick.log`,
`synthmerge-stdout.txt` / `-stderr.txt`, `ai.diff` (the resolver's result
as a diff), `checker-pre.log`, `external-context.md`, `<issue-id>.yaml`,
`amalgamator-runs/`, `checker-post.log`.

The user's checkout is never touched — all git operations happen in
detached worktrees under `--gitscratch`, and the result branches are the
only writes to the source repo.

## The two files

### `hybrid-backport.sh` — the driver

Orchestrates everything, dies loudly on anything suspicious:

- **hard-failure guard**: a failed cherry-pick with *zero* unmerged paths
  (bad sha, missing alternates, empty patch) aborts — running the resolver on
  a broken worktree yields "No conflicts found" and an empty result that
  would sail through the gate
- **resolver contract** (pluggable; tested with
  [synthmerge](https://gitlab.com/aarcange/synthmerge)): on conflict, the
  marked resolver seam finishes the cherry-pick —
  `merge.conflictStyle=diff3` and deterministic diff settings are injected
  via `GIT_CONFIG_*` and **scoped to the resolver phase only** (unset
  before the amalgamator runs — it must see vanilla conflict markers); a
  resolver exit 0 that leaves `HEAD == base` aborts
- **gate invocation** and branching on the checker's exit code
- **escalation**: writes the case yaml, runs
  `python -m auto_bug_fix.run_bug_fix` with a clean git env
- **stray-file stripping**: untracked junk in the amalgamator's result is
  removed (`ls-tree` / `mktree` / `commit-tree`) before acceptance
- **B1 arbiter**: re-runs the identical checker on the escalated tree,
  applies the shape rule, keep/reject

**Arbitration rule** (deterministic, errs toward the pre-gate tree):

```
keep    iff  POST_STRONG <= PRE_STRONG  (no NEW undefined symbols /
                                          broken Makefile entries)
        and  shape ok (result <= 3x upstream changed lines,
                       or within +100 lines of it)
reject  otherwise → amalgamator/<id> := hybrid/<id>,
                rejected tree → amalgamator-rejected/<id>
```

A result that merely kept the same advisory findings is kept: the arbiter
prevents harm, it does not punish wasted escalations.

### `check-backport.py` — the gate

Deterministic, zero LLM:

```
check-backport.py --worktree <wt> --base <sha> [--upstream <sha>] \
    [--synthmerge-stdout <file>] [--ai-diff-out <file>] \
    [--emit-external-context <out.md>]
```

Used twice per run by the driver: on the resolver's worktree (pre-gate)
and on the amalgamator's result tree (arbiter re-scan). Exit code:
`0` = ship, `1` = findings (escalate).

The checker's only contract with the resolver is **the git commit it
leaves behind**: touched files and added lines are derived from
`git diff base..HEAD`; the resolver's captured stdout is parsed for five
metadata regexes (conflict count, retries, duration, endpoint) that land
in the MD's resolver-metadata section — never for findings.

## How it was validated

**Scale run:** the same 400 real Linux-kernel backport cases (RHEL 7/8/9/10
trees, upstream fixes, known human-maintainer results), run twice — the
resolver alone vs the full hybrid — with the **same model at every stage**
(DeepSeek V4 Flash via an OpenAI-compatible endpoint; resolver front-end:
[synthmerge](https://gitlab.com/aarcange/synthmerge)):

| | resolver solo | **hybrid (this adapter)** |
|---|---|---|
| Matches the human backport (byte-exact or whitespace-only diff) | 142/400 (35.5%) | **170/400 (42.5%)** |
| Fast path | — | 231 cases (57.8%), ~30 s median |
| Escalated | — | 158, 13.3 min median |
| Escalation effect | — | 37 fixed / 114 unchanged / 7 worse |
| Arbiter decisions | — | 20 kept / 4 rejected (all four wholesale-replacement blowups; no legitimate result rejected) |

**Real-world single-commit runs** (one container, one upstream commit, no
harness): representative rescue — an ACPICA header-restoration fix where
the resolver restored the macros but never wired up their uses (2 hunks
off the human result). The gate caught it with five "introduced by the
patch but has zero references" findings; the amalgamator repaired it with
a **2-line change** → **byte-exact vs the human maintainer, 12.8 minutes
end to end**. A same-day corroboration case (xen hypercall header) also
rescued to byte-exact.

**Known limit, stated honestly:** the gate's false-negative floor. 56% of
fast-path cases still differ from the human result, 69 of them by a single
hunk — clean mismerges and style drift are invisible to symbol/Makefile
scans by construction.

## Requirements & gotchas

- `--gitscratch` must be on a **case-sensitive filesystem** — kernel trees
  contain `Makefile`/`makefile` and `xt_DSCP.h`/`xt_dscp.h` pairs that
  clobber each other on case-insensitive filesystems and produce phantom
  diffs
- `--python` must have this repo's dependencies installed
  (`pip install -e .` from the repo root)
- repos that reference git alternates by absolute path (e.g. RHEL kernel
  clones) must have those alternates reachable at the same path
- on macOS / any host without native synthmerge, run the whole pipeline
  in a Linux container that mounts this repo and the resolver binary
