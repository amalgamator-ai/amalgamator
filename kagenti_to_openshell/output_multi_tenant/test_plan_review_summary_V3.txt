1.1 HIGH ISSUES (1)
────────────────────

  R3-1: Wiremock OIDC tests incorrectly remove discovery mock

    PROBLEM: The V3 test plan's wiremock setup (Section 17) mocks ONLY the
    JWKS endpoint and explicitly states "Mock ONLY the JWKS endpoint — NOT
    .well-known/openid-configuration. JwksCache constructs the JWKS URL
    directly from the issuer, not from OIDC discovery."

    This is factually wrong. Verified against oidc.rs:

      Line 170: JwksCache::new() is documented as "discovering the JWKS URI
                and fetching the initial key set"
      Line 177: Constructs discovery URL:
                format!("{}/.well-known/openid-configuration", ...)
      Lines 183-190: Fetches discovery URL, parses as OidcDiscovery
      Lines 192-199: Validates discovery.issuer matches config.issuer
      Line 205: Stores discovery.jwks_uri as self.jwks_uri
      Lines 222-233: refresh_keys() fetches from self.jwks_uri

    ROOT CAUSE: The V2-R1 review (Issue R2-7) incorrectly claimed that
    "JwksCache does NOT fetch the OIDC discovery document." V3 incorporated
    this incorrect correction. The V2-R1 reviewer apparently examined a
    different code path or misread the JwksCache implementation.

    IMPACT: All 4 wiremock tests would fail at JwksCache::new() because
    the discovery endpoint returns a connection error instead of JSON.

    FIX: The wiremock setup now mocks TWO endpoints:
      1. /.well-known/openid-configuration → returns
         {"issuer": "<uri>", "jwks_uri": "<uri>/certs"}
      2. /certs → returns {"keys": [jwk]}

    The discovery response must include "issuer" matching config.issuer
    because JwksCache validates this (lines 192-199).

1.2 MEDIUM ISSUES (3)
──────────────────────

  R3-2: stamp_owner_labels() uses tenant_id from OwnershipConfig, but
        tenant_id is on Config

    PROBLEM: Section 6.2 tests set "config.tenant_id = Some("team1")"
    when testing stamp_owner_labels(), but OwnershipConfig (defined in
    Section 7) only has `enabled` and `allow_unowned_providers`. The
    tenant_id field is on Config (set in test_server_state_with_ownership).

    FIX: Added tenant_id as a separate parameter to stamp_owner_labels:
      stamp_owner_labels(principal, config, tenant_id, existing_labels)

    In handler code, tenant_id comes from state.config.tenant_id.
    In unit tests, it's passed explicitly as Some("team1") or None.

  R3-3: check_ownership() references config.admin_role, but OwnershipConfig
        has no admin_role field

    PROBLEM: Section 6.3 test admin_bypasses_ownership_check sets
    "config.admin_role = 'openshell-admin'" but OwnershipConfig has no
    such field.

    FIX: Added admin_role to OwnershipConfig:
      pub struct OwnershipConfig {
          pub enabled: bool,
          pub allow_unowned_providers: bool,
          pub admin_role: String,  // default: "openshell-admin"
      }

    Added corresponding tests: one for config.rs default (Section 7)
    and one for TOML parsing (Section 8).

  R3-4: SandboxIndex tests assume APIs that don't exist

    PROBLEM: Section 15 tests use index.insert(name, id, owner) and
    index.get_owner(id), but the actual SandboxIndex has
    update_from_sandbox(&sandbox) and sandbox_id_for_sandbox_name(&name).

    FIX: Corrected tests to use the existing API pattern:
      - update_from_sandbox(&sandbox) with Sandbox proto containing
        LABEL_OWNER in metadata.labels
      - New method: get_owner_for_sandbox(sandbox_id) -> Option<String>
      - Tests construct full Sandbox protos matching existing patterns
