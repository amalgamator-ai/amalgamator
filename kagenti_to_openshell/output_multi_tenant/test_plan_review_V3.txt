ISSUE R3-1 (HIGH): Wiremock OIDC tests remove discovery mock, but
  JwksCache DOES use OIDC discovery

  PROBLEM: Section 17 says:
    "Mock ONLY the JWKS endpoint — NOT .well-known/openid-configuration.
    JwksCache constructs the JWKS URL directly from the issuer, not from
    OIDC discovery."

  This is WRONG. Verified against the actual code at oidc.rs:

    Line 170: JwksCache::new() is documented "discovering the JWKS URI
              and fetching the initial key set"
    Lines 177-178:
      let discovery_url = format!(
          "{}/.well-known/openid-configuration",
          config.issuer.trim_end_matches('/')
      );
    Lines 183-190: Fetches the discovery URL as OidcDiscovery struct
    Line 192-199: Validates discovery.issuer matches config.issuer
    Line 205: Stores discovery.jwks_uri as self.jwks_uri
    Lines 222-233: refresh_keys() fetches from self.jwks_uri (discovered URI)

    The OidcDiscovery struct (line 71) has fields: issuer, jwks_uri.

  ROOT CAUSE: The V2-R1 review (Issue R2-7) incorrectly claimed that
  "JwksCache does NOT fetch the OIDC discovery document." This was wrong.
  V3 incorporated this incorrect correction by design.

  IMPACT: All 4 wiremock OIDC tests (Section 17) would fail at setup
  time because JwksCache::new() cannot fetch the discovery document.

  FIX: The wiremock setup MUST mock TWO endpoints:
    1. /.well-known/openid-configuration → returns {"issuer": "<uri>",
       "jwks_uri": "<uri>/certs"}
    2. /certs → returns {"keys": [jwk]}

  Additionally, JwksCache::new() validates that the discovery document's
  issuer matches config.issuer (lines 192-199). The mock discovery
  response MUST include the correct issuer field.

ISSUE R3-3 (MEDIUM): check_ownership() test references config.admin_role,
  but OwnershipConfig has no admin_role field

  PROBLEM: Section 6.3 test admin_bypasses_ownership_check says:
    "config.admin_role = "openshell-admin""

  But OwnershipConfig (Section 7) has no admin_role field. The
  admin_role is defined on OidcConfig (config.rs line 477):
    pub admin_role: String,    // default: "openshell-admin"

  The check_ownership function needs to know the admin role to
  implement admin bypass, but it only receives &OwnershipConfig.

  IMPACT: The test description specifies a field that doesn't exist on
  the struct. The admin bypass logic needs a way to determine if a
  principal has the admin role.

  FIX: The simplest approach is for check_ownership to determine admin
  status from the principal's roles directly, using a well-known role
  name. Add admin_role to OwnershipConfig:
    pub struct OwnershipConfig {
        pub enabled: bool,
        pub allow_unowned_providers: bool,
        pub admin_role: String,          // ← ADDED, default: "openshell-admin"
    }

  Alternatively, check_ownership can accept a separate admin_role
  parameter. The test's intent (admin bypasses ownership) is correct;
  only the mechanism needs specification.

  Corrected test setup uses OwnershipConfig { admin_role: "openshell-admin".into(), .. }.

  update_from_sandbox(), not an insert() method.

  SandboxIndex design. An implementer following these tests would create

ISSUE R3-6 (LOW): Cross-resource test sandbox_with_another_users_provider_denied
  assumes provider ownership enforcement during sandbox creation that is
  not described in the port plan

  PROBLEM: Section 16.3 test sandbox_with_another_users_provider_denied
  assumes that when User-B creates a sandbox referencing User-A's
  provider "my-llm", the creation fails because User-B can't see
  User-A's provider.

  But the sandbox creation handler validates providers by calling
  store.get_message_by_name::<Provider>(name) at sandbox.rs line 168,
  which is a direct store lookup that BYPASSES ownership filtering.
  The provider would be found, and the sandbox would be created
  successfully, even though User-B shouldn't be able to use User-A's
  provider.

  For this test to work, the sandbox creation handler's provider
  validation would need additional modification (not described in
  the port plan) to check provider ownership.

  IMPACT: Test expects behavior that isn't implemented. Would fail
  because the sandbox creation would succeed when it should fail.

  FIX: Added a NOTE to the test documenting that this requires
  additional implementation beyond the port plan:
    - Provider validation during sandbox create must be modified to
      use ownership-aware provider lookup (either via label selector
      or by calling check_ownership after the direct lookup)
    - This is a gap in the port plan, not a gap in the test plan
