2. KEY ARCHITECTURAL DECISIONS
================================================================================

Decision 1: Two-Layer Multi-Tenancy (UNCHANGED from V1)
  Layer 1 (per-user ownership) handles application-level user isolation
  within a gateway instance via the openshell.ai/owner label.
  Layer 2 (gateway-per-tenant) handles organizational isolation via
  Kubernetes namespaces and RBAC. Both compose without coupling.

Decision 2: Owner-Label Approach (UNCHANGED from V1)
  V2 stores ownership in the existing labels JSON column, leveraging
  list_with_selector() for efficient filtering. No database schema
  migrations. Future iteration can add owner column for name-scoped
  uniqueness.

Decision 3: Zero Breaking Changes (UNCHANGED from V1)
  All behavior gated behind OwnershipSettings.enabled (config) and
  OIDC being configured. Default values disable all new behavior.

Decision 4: Minimal Protobuf Changes (UNCHANGED from V1)
  No changes to protobuf definitions. Owner carried in existing
  ObjectMeta.labels map.

Decision 5: OwnershipSettings vs OwnershipEnforcement (NEW in V2)
  Clean separation between serializable config (OwnershipSettings in
  config.rs) and runtime enforcement logic (OwnershipEnforcement in
  auth/ownership.rs). Connected by ServerState.ownership_config() method.

Decision 6: Comprehensive Access Control (EXPANDED in V2)
  All sandbox access operations (create, list, get, delete, watch, exec,
  interactive exec, SSH, attach provider, detach provider) are ownership-
  gated. V1 initially missed watch/exec/SSH.
