1. EXPLANATION OF THE CODE PATCH
================================================================================

This patch implements per-user ownership enforcement for OpenShell, porting
Kagenti's multi-tenant ownership model to Rust. The core capability: when
ownership is enabled, every sandbox and provider object is stamped with an
`openshell.ai/owner` label derived from the caller's OIDC subject, and all
CRUD operations are scoped to the owning user. Admin principals bypass
ownership checks. The feature is disabled by default for backward compatibility.

The implementation covers Steps 1–11 of the V4 code porting plan:

STEP 1 — Identity groups field:
  Added `pub groups: Vec<String>` to the Identity struct, enabling group
  membership to flow from OIDC claims into the gateway's identity model.
  Updated all 16 Identity construction sites across production code and
  test helpers with `groups: vec![]`.

STEP 2 — OIDC groups extraction:
  Added `groups_claim` (default: "groups") to OidcConfig with serde default.
  Added `extract_groups()` method to OidcClaims following the same dot-path
  traversal pattern as `extract_roles()`. Wired into `validate_token()` so
  the Identity returned carries group memberships from the JWT.

STEP 3 — Label constants:
  Added `LABEL_OWNER` ("openshell.ai/owner") and `LABEL_TENANT`
  ("openshell.ai/tenant") constants to openshell-core's driver_utils.rs,
  alongside existing sandbox label constants.

STEP 4 — Ownership module:
  Created `auth/ownership.rs` with four core functions:
  - `sanitize_label_value()` — K8s label value sanitization (63-char max,
    valid charset, trimmed leading/trailing non-alphanumeric)
  - `stamp_owner_labels()` — strips client-supplied openshell.ai/* labels
    (anti-spoofing), stamps owner from principal subject, stamps tenant
    if configured
  - `check_ownership()` — verifies principal owns the object, with admin
    bypass, anonymous backward-compat, and shared-object allowance
  - `owner_label_selector()` — builds label selector string for list filtering
  Includes 27 unit tests covering all functions and edge cases.

STEP 5 — OwnershipConfig in core config:
  Added `OwnershipConfigCore` struct (enabled, tenant_id) to openshell-core
  config.rs with Default (disabled). Added to Config struct. Added to
  GatewayFileSection for TOML config support. Re-exported from lib.rs.

STEP 6 — ServerState helper:
  Added `ownership_config()` method to ServerState that builds an
  OwnershipConfig from the server's Config, reading admin_role from OIDC
  config when available with fallback to "openshell-admin".

STEP 7 — Sandbox create (owner stamping):
  Modified `handle_create_sandbox_inner` to extract Principal before
  `into_inner()`, stamp owner labels on BOTH ObjectMeta.labels (for
  persistence/queries) AND SandboxTemplate.labels (for compute drivers).
  Fixed label serialization in compute/mod.rs `create_sandbox()` — changed
  `put_if` from `None` to serialized labels JSON, matching the existing
  pattern used in the delete path. This also fixes a pre-existing issue
  where user-supplied labels weren't queryable via label selectors.

STEP 8 — Sandbox list (owner filtering):
  Modified `handle_list_sandboxes` to extract Principal, generate owner
  label selector via `owner_label_selector()`, and combine it with any
  user-provided label_selector before querying the store.

STEP 9 — Sandbox get/delete (ownership enforcement):
  Modified `handle_get_sandbox` and `handle_delete_sandbox_inner` to
  extract Principal and call `check_ownership()` after fetching the
  sandbox but before returning/deleting it.

STEP 10 — Watch/exec/SSH handlers:
  Left unchanged in this iteration. These handlers operate on sandbox IDs
  and are accessed by sandbox principals (supervisors), not directly by
  users. Step 10 is lower priority per the plan.

STEP 11 — Provider CRUD ownership:
  Modified provider handlers in grpc/mod.rs and grpc/provider.rs:
  - 11A: Stamp owner labels on provider create. Ensured metadata exists
    before stamping. Modified `create_provider_record` to serialize labels
    to DB (was passing None).
  - 11B: Filter provider list by owner using `list_messages_with_selector`.
    Added `list_provider_records_with_selector` helper.
  - 11C: Added ownership checks to get, update, and delete handlers.
  - 11D: Changed create/update/delete provider roles from "admin" to "user"
    (users can now manage their own providers). Profile/credential admin
    operations remain admin-only.

CLI FLAGS:
  Added --ownership-enabled and --tenant-id CLI arguments with corresponding
  environment variables (OPENSHELL_OWNERSHIP_ENABLED, OPENSHELL_TENANT_ID)
  and TOML config file support.
