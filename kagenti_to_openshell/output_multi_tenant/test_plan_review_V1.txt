ISSUE R1-1 (CRITICAL): OidcConfig test helper uses wrong field names

  PROBLEM: The test_server_state_with_ownership helper constructs OidcConfig
  with incorrect field names that would cause compilation failures:
    - Uses `jwks_ttl: 300` — actual field is `jwks_ttl_secs`
    - Uses `ca_cert_path: None` — this field does NOT exist on OidcConfig
      (it belongs to TlsConfig)
    - Uses `groups_claim: "groups"` — this field does not exist yet
      (being added by Step 2), but the name is correct

  VERIFICATION: The actual OidcConfig struct at config.rs:463-493 has:
    pub issuer: String,
    pub audience: String,
    pub jwks_ttl_secs: u64,       // <-- NOT jwks_ttl
    pub roles_claim: String,
    pub admin_role: String,
    pub user_role: String,
    pub scopes_claim: String,
    // NO ca_cert_path field

  Also: OidcConfig uses #[serde(deny_unknown_fields)], so any extra
  fields in struct literals will cause compile errors.

  FIX: Corrected field names in test helper. See Section 2.

ISSUE R1-2 (HIGH): Provider shared access contradicts check_ownership

  PROBLEM: Section 3.3 tests that check_ownership returns
  PermissionDenied for resources with NO owner label (pre-ownership
  migration scenario). But Section 10.3 tests that shared providers
  (admin-created, no owner label) are accessible to ANY user.

  These are contradictory. If check_ownership denies access for
  unlabeled resources, then shared providers are inaccessible to
  non-admin users.

  ROOT CAUSE: The port plan (Step 4D) says "resources with no owner
  label require admin access" for sandboxes. But for providers (Step 11B),
  it says "users see own providers + shared (admin-created) providers."
  Shared providers have no owner label and must be accessible to all.

  FIX: check_ownership needs a parameter to differentiate behavior:
    - Sandboxes: no owner label → PermissionDenied (migration safety)
    - Providers: no owner label → Ok (shared provider access)

  The solution is to add an `allow_unowned: bool` parameter to
  check_ownership():
    check_ownership(principal, config, labels, resource_type, name,
                    allow_unowned: bool)
    - For sandboxes: allow_unowned = false
    - For providers: allow_unowned = true

  Updated tests in Sections 3.3 and 10.3.

ISSUE R1-3 (HIGH): Integration test file can't call private handlers

  PROBLEM: Section 15 proposes tests in
  `tests/ownership_integration.rs` that call handle_create_sandbox_inner()
  and handle_list_sandboxes() directly. But:
    - handle_create_sandbox_inner is PRIVATE (no pub modifier, line 119)
    - handle_list_sandboxes is pub(super) (line 256)
    - handle_get_sandbox is pub(super) (line 235)
    - handle_delete_sandbox_inner is PRIVATE (line 496)

  Tests in tests/ (integration test crate) can only access pub items
  from the openshell-server crate. They CANNOT call private or
  pub(super) functions.

  VERIFICATION: Confirmed at sandbox.rs lines 61, 119, 235, 256, 496.

  FIX: Section 15 E2E tests are redesigned to:
    Option A: Place all handler-level tests INSIDE the source file
              #[cfg(test)] modules (Sections 9-10), which CAN access
              private functions.
    Option B: Create pub(crate) test wrapper functions that expose
              the create→list→get→delete workflow for integration tests.

  Adopted Option A: All handler-invocation tests are consolidated into
  Sections 9-10 (in-source test modules). Section 15 is restructured to
  contain only multi-step LIFECYCLE tests that use pub(crate) helper
  functions or exercise the Store layer directly, avoiding private
  handler calls.

ISSUE R1-4 (HIGH): Provider role change tests test the wrong gate

  PROBLEM: The port plan changes #[rpc_auth] from role="admin" to
  role="user" for provider create/update/delete. But #[rpc_auth] is
  enforced at the gRPC service routing layer (in the tonic service
  trait implementation), NOT in handle_create_provider(). Calling
  handle_create_provider() directly BYPASSES the #[rpc_auth] check.

  The port plan Step 11E adds a RUNTIME guard inside the handler:
  "when ownership is disabled, check that the caller has admin role."
  This IS testable by calling the handler directly.

  But the "user can create when ownership enabled" test would ALWAYS
  pass when calling the handler directly, regardless of whether
  #[rpc_auth] was changed, because the handler has no role checking
  of its own (only the runtime guard for the disabled case).

  FIX: Tests that verify the #[rpc_auth] change must go through the
  full gRPC service interface (tonic::transport::Server). Tests for the
  runtime guard CAN call the handler directly. Updated Section 10.1 to:
    - Test the runtime guard (handler-level, direct call)
    - Document that #[rpc_auth] change is verified by compilation
      and existing auth integration tests
    - Add a note that full gRPC-level role testing requires the
      service stack and is covered by Kagenti-style E2E tests

ISSUE R1-5 (MEDIUM): OIDC groups extraction tests assume wrong mechanism

  PROBLEM: Section 5.1 tests direct JSON deserialization of groups from
  JWT claims. But the port plan adds `groups` to OidcClaims with
  `#[serde(skip)]`, meaning groups are NOT deserialized by serde.

  VERIFICATION: The existing roles field has #[serde(skip)] at
  oidc.rs:103-104 and is extracted post-deserialization via
  extract_roles() which walks the `extra` field (serde(flatten)).
  Groups will use the identical pattern: extract_groups() walking
  the extra field via the configurable groups_claim path.

  FIX: Section 5 tests are rewritten to exercise the extract_groups()
  method (following the extract_roles() pattern) instead of direct
  JSON deserialization.

ISSUE R1-7 (MEDIUM): Streaming handler "allowed" tests need clarification

  PROBLEM: Section 9.5 tests like watch_sandbox_allowed_for_owner
  assume the handler returns Ok on success. But for the "allowed" case,
  the handler proceeds past the ownership check into streaming setup,
  which requires a running sandbox in the compute runtime. With
  NoopTestDriver, the handler may fail AFTER the ownership check
  with a different error (e.g., sandbox not found in compute, status
  not running).

  FIX: "Allowed" tests for streaming handlers should verify the
  response is NOT PermissionDenied (ownership check passed), rather
  than asserting full Ok. Updated Section 9.5 test expectations.
