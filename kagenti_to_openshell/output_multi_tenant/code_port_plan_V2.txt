1. EXECUTIVE SUMMARY
================================================================================

This plan ports Kagenti's multi-tenant deployment support to OpenShell. The
feature operates at two complementary layers:

  Layer 1 — Per-User Ownership (Rust gateway code changes):
    Within a single gateway instance, enforce per-user isolation via the
    openshell.ai/owner label. This is the core Rust work: owner stamping
    on create, per-user filtering on list, ownership checks on get/delete/
    exec/watch/SSH, admin bypass, and anti-spoofing.

  Layer 2 — Gateway-Per-Tenant (Helm/infrastructure changes):
    Each tenant (team/organization) gets a dedicated Kubernetes namespace
    with an isolated gateway stack, namespace-scoped RBAC, per-tenant
    OIDC audience scoping, ResourceQuota, LimitRange, and TLS certs.
    This is primarily Helm chart and deployment tooling work.

Both layers compose: Layer 2 isolates tenants at the Kubernetes boundary,
while Layer 1 isolates users within a tenant at the application layer.

The plan preserves backward compatibility: when OIDC is disabled or
ownership config is absent, all ownership logic is bypassed
(Anonymous principal => no owner stamping, no filtering).

V2 improvements over V1:
  - All 11 issues from V1-R1 review incorporated from the start
  - Fresh source code verification against actual OpenShell HEAD
  - Corrected Helm chart structure (actual chart name, actual templates)
  - Better step ordering with explicit dependency chains
  - Expanded coverage: all sandbox access operations (exec/watch/SSH)
  - Cleaner separation of config (OwnershipSettings) vs runtime
    (OwnershipEnforcement) structs
  - More realistic effort estimates based on verified code complexity
  - Edge case handling for legacy data (pre-ownership objects)

2. ARCHITECTURAL DECISION
================================================================================

DECISION: Adopt the Kagenti "owner-label" approach for Layer 1 and the
"gateway-per-tenant Helm deployment" approach for Layer 2.

Rationale:

  1. Owner-label approach leverages EXISTING OpenShell infrastructure:
     - labels column in objects table (present since migration 001)
     - list_with_selector() API (implemented for both SQLite and Postgres;
       Postgres uses JSONB @> operator for efficient filtering)
     - ObjectMeta.labels in protobuf (defined in datamodel.proto)
     - Identity.subject from OIDC JWT (extracted in oidc.rs validate_token)
     - Principal inserted into request extensions by multiplex.rs (line 623:
       req.extensions_mut().insert(principal))
     No schema changes to protobuf messages are needed.

  2. Gateway-per-tenant avoids invasive single-gateway multi-tenant changes:
     - No tenant column needed in the database (each gateway has its own DB)
     - No tenant-aware connection pooling
     - No cross-tenant broadcast filtering on SandboxWatchBus
     - Tenant isolation enforced by Kubernetes namespace RBAC
     - Clean lifecycle management (deploy/destroy per-tenant independently)

  3. OIDC audience scoping per gateway instance is already supported:
     - OidcConfig.audience is a single configurable value
     - Each gateway instance in its own namespace gets its own audience
     - No code change needed for audience-per-tenant; it's config-per-deploy

  Alternatives considered and rejected:

  A. Single gateway, tenant column in DB:
     Would require invasive schema changes, all queries must carry tenant,
     SandboxWatchBus must filter by tenant, SandboxIndex must partition
     by tenant. Much higher complexity for marginal benefit.

  B. Virtual tenants via gateway configuration:
     Would require multi-audience OIDC validation, per-request tenant
     resolution, and query-level tenant partitioning. Breaks the clean
     separation that gateway-per-tenant provides.

    impl OidcClaims {
        /// Extract groups from the JWT claims using a dot-separated path.
        /// Keycloak groups are paths like "/team1", "/team2"; we strip
        /// the leading slash for cleaner values.
        fn extract_groups(&self, groups_claim: &str) -> Vec<String> {
            if groups_claim.is_empty() {
                return vec![];
            }
            let mut value = &self.extra;
            for segment in groups_claim.split('.') {
                match value.get(segment) {
                    Some(v) => value = v,
                    None => return vec![],
                }
            }
            if let Some(arr) = value.as_array() {
                arr.iter()
                    .filter_map(|v| v.as_str())
                    .map(|s| s.trim_start_matches('/').to_string())
                    .collect()
            } else {
                vec![]
            }
        }
    }

  This follows the EXACT same pattern as extract_roles (oidc.rs lines
  119-133) which uses the same dot-path traversal over the extra field.

  //! Per-user ownership enforcement for multi-tenant deployments.
  //!
  //! When OIDC is enabled, each object (sandbox, provider) is stamped with
  //! `openshell.ai/owner = <identity.subject>` at creation time. List, get,
  //! delete, exec, watch, and SSH operations enforce that users can only
  //! access their own objects, unless the caller has the admin role.
  //!
  //! When OIDC is disabled (Anonymous principal), ownership is not enforced.

  use super::identity::Identity;
  use super::principal::Principal;
  use openshell_core::driver_utils::{LABEL_OWNER, LABEL_TENANT};
  use std::collections::HashMap;
  use tonic::Status;
  use tracing::{debug, info};

  /// Reserved label key prefix. Client-supplied labels starting with this
  /// prefix are stripped at creation time to prevent spoofing.
  const RESERVED_LABEL_PREFIX: &str = "openshell.ai/";

  /// Runtime configuration for ownership enforcement.
  ///
  /// Built from OwnershipSettings (config) + OidcConfig at handler call
  /// time. DISTINCT from config::OwnershipSettings which is the
  /// serializable TOML/Helm config struct.
  #[derive(Debug, Clone)]
  pub struct OwnershipEnforcement {
      /// When true, ownership enforcement is active.
      pub enabled: bool,

      /// Role name that grants admin access (ownership bypass).
      pub admin_role: String,
  }

  impl OwnershipEnforcement {
      /// Create from admin role string. Returns enabled=false when the
      /// role string is empty (ownership cannot be enforced without roles).
      pub fn from_authz(admin_role: &str) -> Self {
          Self {
              enabled: !admin_role.is_empty(),
              admin_role: admin_role.to_string(),
          }
      }

      /// Disabled ownership (for backward compatibility).
      pub fn disabled() -> Self {
          Self {
              enabled: false,
              admin_role: String::new(),
          }
      }
  }

  /// Determine whether ownership enforcement should be applied for
  /// the given principal. Returns the owner's subject string when
  /// ownership applies, `None` when it doesn't (anonymous, disabled,
  /// admin bypass).
  pub fn resolve_owner(
      config: &OwnershipEnforcement,
      principal: &Principal,
  ) -> Option<String> {
      if !config.enabled {
          return None;
      }
      match principal {
          Principal::User(user) => {
              if is_admin(&user.identity, &config.admin_role) {
                  None // Admin callers bypass ownership
              } else {
                  Some(user.identity.subject.clone())
              }
          }
          Principal::Sandbox(_) | Principal::Anonymous => None,
      }
  }

  /// Stamp owner label onto a mutable label map, stripping any
  /// client-supplied openshell.ai/* keys first (anti-spoofing).
  pub fn stamp_owner_labels(
      labels: &mut HashMap<String, String>,
      owner: Option<&str>,
  ) {
      // Strip ALL client-supplied reserved labels (anti-spoofing).
      labels.retain(|key, _| !key.starts_with(RESERVED_LABEL_PREFIX));

      // Stamp owner if applicable.
      if let Some(owner_id) = owner {
          let sanitized = sanitize_label_value(owner_id);
          labels.insert(LABEL_OWNER.to_string(), sanitized);
          debug!(owner = %owner_id, "stamped owner label on object");
      }
  }

  /// Build a label selector string for the owner filter.
  /// Returns `None` when no filtering is needed (admin/anonymous/disabled).
  pub fn owner_label_selector(
      config: &OwnershipEnforcement,
      principal: &Principal,
  ) -> Option<String> {
      let owner = resolve_owner(config, principal)?;
      Some(format!("{}={}", LABEL_OWNER, sanitize_label_value(&owner)))
  }

  /// Combine an optional user-provided label selector with the owner
  /// filter. Returns the merged selector string.
  pub fn merge_label_selectors(
      user_selector: &str,
      owner_selector: Option<&str>,
  ) -> String {
      match (user_selector.is_empty(), owner_selector) {
          (true, None) => String::new(),
          (true, Some(owner)) => owner.to_string(),
          (false, None) => user_selector.to_string(),
          (false, Some(owner)) => format!("{},{}", user_selector, owner),
      }
  }

  /// Check ownership of an existing object. Returns `Ok(())` if the
  /// caller is the owner, an admin, or if ownership is disabled.
  /// Returns `Err(Status::not_found)` for non-owners to avoid leaking
  /// object existence.
  ///
  /// `object_labels` is the label map from the protobuf ObjectMeta.
  #[allow(clippy::result_large_err)]
  pub fn enforce_ownership(
      config: &OwnershipEnforcement,
      principal: &Principal,
      object_labels: &HashMap<String, String>,
      object_kind: &str,
  ) -> Result<(), Status> {
      if !config.enabled {
          return Ok(());
      }
      match principal {
          Principal::User(user) => {
              if is_admin(&user.identity, &config.admin_role) {
                  return Ok(());
              }
              let caller_subject = &user.identity.subject;
              match object_labels.get(LABEL_OWNER) {
                  Some(owner) if owner == caller_subject => Ok(()),
                  Some(owner) => {
                      info!(
                          caller = %caller_subject,
                          owner = %owner,
                          kind = %object_kind,
                          "ownership check failed: caller is not owner"
                      );
                      // NotFound (not PermissionDenied) to prevent
                      // leaking object existence to non-owners.
                      Err(Status::not_found(format!("{object_kind} not found")))
                  }
                  None => {
                      // Object has no owner label (admin-created / legacy).
                      // Non-admin users CAN access shared objects.
                      Ok(())
                  }
              }
          }
          // Sandbox principals use sandbox-scoped guards (guard.rs),
          // not user ownership. Anonymous principals bypass ownership.
          Principal::Sandbox(_) | Principal::Anonymous => Ok(()),
      }
  }

  /// Extract the Principal from a tonic Request, returning Anonymous
  /// if not present (backward compatibility for unauthenticated paths).
  ///
  /// MUST be called BEFORE request.into_inner() which consumes the
  /// Request and its extensions.
  pub fn extract_principal<T>(request: &tonic::Request<T>) -> Principal {
      request
          .extensions()
          .get::<Principal>()
          .cloned()
          .unwrap_or(Principal::Anonymous)
  }

  /// Returns `true` if the identity has the admin role.
  fn is_admin(identity: &Identity, admin_role: &str) -> bool {
      !admin_role.is_empty() && identity.roles.iter().any(|r| r == admin_role)
  }

  /// Sanitize a string for use as a Kubernetes label value.
  ///
  /// Kubernetes label values must be <= 63 chars and match:
  ///   ([A-Za-z0-9][-A-Za-z0-9_.]*)?[A-Za-z0-9]
  ///
  /// Keycloak UUID subjects satisfy this natively, but other OIDC
  /// providers may use email addresses or other formats.
  pub fn sanitize_label_value(value: &str) -> String {
      let sanitized: String = value
          .chars()
          .filter(|c| c.is_ascii_alphanumeric() || *c == '-' || *c == '_' || *c == '.')
          .take(63)
          .collect();
      // V1-R1 FIX: Trim leading/trailing non-alphanumeric chars.
      // K8s label values must start and end with alphanumeric.
      let trimmed = sanitized
          .trim_start_matches(|c: char| !c.is_ascii_alphanumeric())
          .trim_end_matches(|c: char| !c.is_ascii_alphanumeric());
      if trimmed.is_empty() {
          "unknown".to_string()
      } else {
          trimmed.to_string()
      }
  }

7. RISK ANALYSIS
================================================================================

HIGH RISK:

  1. Backward Compatibility (CRITICAL)
     Risk: Existing single-user deployments break when upgrading.
     Mitigation: ALL ownership behavior gated on TWO flags:
                  config.ownership.enabled=true AND OIDC configured.
                  Default config disables ownership. Anonymous principals
                  bypass all ownership checks.
     Validation: Step 20 includes test_ownership_disabled_shows_all().

  2. Provider Resolution Correctness (HIGH)
     Risk: User-owned > shared resolution could bind unexpected provider.
     Mitigation: Resolution is deterministic. Users see which providers
                  they own via list. Admin sees all providers.
     Validation: Step 20 includes test_sandbox_resolves_user_owned_provider_first().

  3. Provider Role Change Side Effect (MEDIUM-HIGH)
     Risk: Changing CreateProvider from role=admin to role=user affects
           ALL deployments, not just multi-tenant ones.
     Mitigation: Runtime guard in handle_create_provider falls back to
           admin-only behavior when ownership is disabled (Step 11D).
     Validation: Test both ownership-enabled and ownership-disabled.

MEDIUM RISK:

  4. Principal Extraction Ordering
     Risk: Must extract Principal BEFORE request.into_inner().
     Mitigation: extract_principal helper makes this pattern explicit.
                  Code review catch: any handler calling into_inner()
                  before extract_principal is a bug.

  5. Label Selector Performance (Postgres)
     Risk: Owner-based label filtering on every list query.
     Mitigation: Postgres already uses JSONB @> operator with GIN index
                  for label filtering. Single additional key has minimal
                  performance impact.

  6. Helm Chart Values Schema
     Risk: New tenant.* values could break existing Helm deployments.
     Mitigation: All tenant values under a new section with defaults.
                  Existing deployments that don't set tenant.id continue
                  working identically.

  7. Name Uniqueness in Shared Gateway
     Risk: Two users cannot create same-named sandboxes in shared mode.
     Mitigation: V2 uses global name uniqueness (no DB migration).
                  Acceptable in gateway-per-tenant (each gateway has own DB).
                  Future iteration can add owner-scoped name uniqueness.

LOW RISK:

  8. OIDC Group Claim Compatibility
     Risk: Not all OIDC providers use same claim path for groups.
     Mitigation: groups_claim is configurable (same as roles_claim).
                  Default empty = groups extraction disabled.

  9. Label Value Sanitization
     Risk: Non-UUID OIDC subjects need sanitization for K8s labels.
     Mitigation: sanitize_label_value() strips non-compliant chars,
                  truncates to 63 chars, trims start/end. Test coverage.

  10. Legacy Data Access
      Risk: Objects created before ownership was enabled have no owner.
      Mitigation: enforce_ownership allows access to objects without an
                  owner label (treated as shared). Test coverage.

  11. Streaming RPC Ownership Staleness
      Risk: Ownership checked at stream start, not per-message.
      Mitigation: Owner changes are extremely rare. Reconnection resets.
                  Acceptable tradeoff for performance.
