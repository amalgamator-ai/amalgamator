## Failures Found

### 1. openshell-server Excluded from V1 Testing (Environment Issue)
- The V1 runtime logs showed 2,111 tests passing, but openshell-server
  (which contains the bulk of the multi-tenant code) was excluded from
  testing due to a missing z3-sys/libclang system dependency.
- Root cause: The z3-sys crate requires libclang for bindgen and z3.h
  headers for compilation. Neither was on the default PATH.
- Resolution: Located libclang.so from a Python clang package and z3.h
  from a Python z3-solver package. Set environment variables:
    LIBCLANG_PATH, Z3_SYS_Z3_HEADER, Z3_LIBRARY_PATH_OVERRIDE,
    BINDGEN_EXTRA_CLANG_ARGS, LD_LIBRARY_PATH

### 2. RBAC Role Regression (2 Test Failures)
- Tests: auth::authz::tests::user_cannot_access_admin_methods
         auth::authz::tests::openshell_all_with_user_role
- Root cause: The V3 patch incorrectly downgraded three provider CRUD
  methods from admin-only to user-accessible:
    - CreateProvider: role = "admin" -> role = "user"
    - UpdateProvider: role = "admin" -> role = "user"
    - DeleteProvider: role = "admin" -> role = "user"
  This was done in crates/openshell-server/src/grpc/mod.rs as part of
  the multi-tenant port, with the mistaken rationale that ownership
  enforcement would replace RBAC for provider operations.
- The existing tests correctly enforce that provider write operations
  require admin role in the RBAC layer. The ownership enforcement layer
  (which we added) provides *additional* per-tenant isolation on top of
  RBAC, not a replacement for it.

## Fixes Applied

### Fix 1: Revert Provider RBAC Role Annotations
- File: crates/openshell-server/src/grpc/mod.rs
- Changed back to original:
    Line 360: role = "user" -> role = "admin" (CreateProvider)
    Line 424: role = "user" -> role = "admin" (UpdateProvider)
    Line 464: role = "user" -> role = "admin" (DeleteProvider)
- This restores the defense-in-depth model: RBAC gates access at the
  method level, ownership enforcement gates access at the resource level.
