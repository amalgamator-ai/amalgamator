--------------------------------------------------------------------------------
1. GATEWAY CONTROL PLANE
--------------------------------------------------------------------------------
Category:         Core / Control Plane
Maturity:         MATURE
Description:      The gateway is the OpenShell control plane. It exposes gRPC
                  and HTTP APIs for sandbox lifecycle management, provider
                  credentials, policy updates, settings, inference configuration,
                  log streaming, and relay coordination. It persists domain
                  objects in SQLite or Postgres, authenticates clients via mTLS
                  or OIDC, and coordinates supervisor relay sessions.
Key Files:
  - crates/openshell-server/               (Gateway server implementation)
  - crates/openshell-server/src/           (API handlers, persistence, auth)
  - proto/openshell.proto                   (gRPC service definition)
  - architecture/gateway.md                 (Architecture doc)
Known Limitations:
  - Currently single-player mode; multi-tenant enterprise is planned
  - JWT signing-key rotation is an offline operator action
  - Delete operations not yet CAS-protected

--------------------------------------------------------------------------------
2. SANDBOX SUPERVISOR RUNTIME
--------------------------------------------------------------------------------
Category:         Core / Runtime
Maturity:         MATURE
Description:      The sandbox supervisor runs inside every sandbox workload as
                  root, prepares isolation layers, fetches config from the
                  gateway, injects credentials, runs the policy proxy, starts
                  the SSH server, opens a supervisor relay back to the gateway,
                  and launches the agent command as a restricted unprivileged
                  child process with cleared capability bounding set.
Key Files:
  - crates/openshell-sandbox/               (Supervisor binary)
  - architecture/sandbox.md                 (Architecture doc)
Known Limitations:
  - Child setup clears capability bounding set; fails closed on EPERM
  - Gateway config polling fails → keeps last-known-good policy
  - Live policy update invalid → rejects, keeps current policy

--------------------------------------------------------------------------------
3. POLICY ENGINE (OPA-BASED)
--------------------------------------------------------------------------------
Category:         Security / Policy
Maturity:         MATURE
Description:      Declarative YAML policy engine enforcing filesystem, network,
                  process, and inference constraints. Network policy evaluation
                  uses an in-process OPA engine. Policies are validated at load
                  time. Supports named rules, endpoint wildcards, binary
                  identity, L7 inspection, credential injection, and per-endpoint
                  enforcement modes (enforce/audit). Default-deny posture.
Key Files:
  - crates/openshell-policy/                (Policy engine crate)
  - proto/sandbox.proto                     (SandboxPolicy message)
  - architecture/security-policy.md         (Architecture doc)
Known Limitations:
  - Static policy (filesystem, process) requires sandbox recreation
  - OPA evaluation is local to each sandbox, not centralized

--------------------------------------------------------------------------------
4. FILESYSTEM ISOLATION (LANDLOCK)
--------------------------------------------------------------------------------
Category:         Security / Isolation
Maturity:         MATURE
Description:      Linux Landlock LSM restricts file paths the agent can read or
                  write. Configured via declarative YAML with read_only and
                  read_write path lists. Locked at sandbox creation. Supports
                  include_workdir for automatic working directory access.
                  Missing baseline paths are skipped gracefully. GPU device
                  paths auto-enriched when GPU present.
Key Files:
  - crates/openshell-sandbox/               (Landlock application)
  - crates/openshell-policy/                (FilesystemPolicy proto)
Known Limitations:
  - Requires Linux kernel 5.13+ with Landlock ABI support
  - Locked at creation; changes require new sandbox

--------------------------------------------------------------------------------
5. PROCESS ISOLATION (SECCOMP, PRIVILEGE REDUCTION)
--------------------------------------------------------------------------------
Category:         Security / Isolation
Maturity:         MATURE
Description:      Agent child processes run as unprivileged users with reduced
                  capabilities. Seccomp BPF blocks dangerous syscalls including
                  raw socket paths that bypass the proxy. The supervisor clears
                  the capability bounding set during privilege drop (fail-closed).
                  Supports configurable run_as_user and run_as_group.
Key Files:
  - crates/openshell-supervisor-process/    (Process restriction crate)
  - crates/openshell-sandbox/               (Child process spawning)
Known Limitations:
  - Locked at creation; cannot change at runtime

--------------------------------------------------------------------------------
6. NETWORK NAMESPACE AND PROXY ROUTING
--------------------------------------------------------------------------------
Category:         Security / Networking
Maturity:         MATURE
Description:      Each sandbox creates a network namespace that forces all
                  ordinary agent egress through the local CONNECT proxy. This
                  ensures no traffic can bypass policy evaluation. Combined with
                  seccomp blocking of raw socket syscalls.
Key Files:
  - crates/openshell-supervisor-network/    (Network namespace setup)
  - crates/openshell-sandbox/               (Proxy integration)
Known Limitations:
  - Network namespace setup requires root/CAP_NET_ADMIN in supervisor

--------------------------------------------------------------------------------
7. L7 POLICY PROXY (HTTP/TLS INSPECTION)
--------------------------------------------------------------------------------
Category:         Security / Proxy
Maturity:         MATURE
Description:      All sandbox egress is intercepted by a policy proxy that can
                  terminate TLS with an ephemeral sandbox CA for HTTP inspection.
                  Supports REST method/path rules, WebSocket upgrade rules,
                  GraphQL operation rules, MCP method/tool rules, and JSON-RPC
                  method rules. Credential injection on terminated streams.
                  Deny rules take precedence over allow rules. Access presets
                  (read-only, read-write, full) for quick configuration.
Key Files:
  - crates/openshell-sandbox/               (Proxy implementation)
  - crates/openshell-policy/                (L7Rule, L7DenyRule protos)
Known Limitations:
  - JSON-RPC responses and server-to-client MCP messages not parsed for policy
  - Raw streams are connection-scoped; policy reloads affect next connection
  - HTTP upgrades switch to raw relay by default

--------------------------------------------------------------------------------
8. PRIVACY ROUTER (INFERENCE ROUTING)
--------------------------------------------------------------------------------
Category:         Privacy / Inference
Maturity:         MATURE
Description:      Privacy-aware LLM routing that keeps sensitive context on
                  sandbox compute. Requests to https://inference.local bypass
                  OPA network policy and are handled by the inference router.
                  The proxy terminates local TLS, strips caller credentials
                  and disallowed headers, detects OpenAI/Anthropic request
                  shapes, and forwards through openshell-router using route
                  bundles fetched from the gateway. Supports multiple protocols
                  and provider-specific routing (Vertex AI, OpenAI, Anthropic,
                  NVIDIA, DeepInfra).
Key Files:
  - crates/openshell-router/                (Inference router crate)
  - proto/inference.proto                   (Inference service definition)
  - architecture/google-vertex-ai-provider.md
Known Limitations:
  - External inference endpoints not using inference.local must be in policy

--------------------------------------------------------------------------------
9. CREDENTIAL PROVIDER SYSTEM
--------------------------------------------------------------------------------
Category:         Security / Credentials
Maturity:         MATURE
Description:      Providers are named credential bundles injected into sandboxes
                  at creation. Credentials never leak into sandbox filesystem;
                  injected as environment variables at runtime. CLI auto-discovers
                  credentials from shell environment for recognized agents.
                  Provider credentials stored at gateway and fetched by supervisor.
                  Revision-scoped placeholders for rotating credentials. Per-
                  credential expiry enforcement at both gateway and sandbox.
Key Files:
  - crates/openshell-providers/             (Provider management crate)
  - providers/                              (Provider profile YAML definitions)
  - proto/openshell.proto                   (Provider messages)
Known Limitations:
  - Driver-controlled env vars override template values

--------------------------------------------------------------------------------
Category:         SDK / Configuration
Maturity:         MATURE
Description:      Provider profiles define credential schemas, endpoints,

Key Files:
  - providers/                              (Built-in profile YAML files)
  - proto/openshell.proto                   (ProviderProfile messages)
  - crates/openshell-providers/             (Profile management)
Known Limitations:
  - Profile updates require optimistic concurrency version

--------------------------------------------------------------------------------
11. DYNAMIC TOKEN GRANTS (SPIFFE / OAUTH2)
--------------------------------------------------------------------------------
Category:         Security / Identity
Maturity:         DEVELOPING
Description:      Provider profiles can declare dynamic token grants. For matching
                  HTTP endpoints, the supervisor obtains a SPIFFE JWT-SVID from
                  the local Workload API, exchanges it for an OAuth2 access token,
                  caches the token, and injects it as an Authorization: Bearer
                  header. Token grant endpoints are HTTPS-only (except loopback
                  and K8s service DNS). Token response lifetimes capped and cached
                  with expiry margin. Supports audience overrides per endpoint.
Key Files:
  - proto/openshell.proto                   (ProviderCredentialTokenGrant)
  - crates/openshell-sandbox/               (Token grant implementation)
  - examples/spiffe-token-grant-demo/       (Demo)
Known Limitations:
  - Requires SPIFFE Workload API socket mounted in sandbox
  - SPIFFE socket hidden from agent child processes via private mount namespace

--------------------------------------------------------------------------------
12. AWS SIGV4 REQUEST SIGNING
--------------------------------------------------------------------------------
Category:         Security / Credentials
Maturity:         DEVELOPING
Description:      For AWS endpoints requiring request-level signing, the proxy
                  supports SigV4 re-signing. When credential_signing: sigv4 is
                  set, the proxy strips client placeholder-based auth headers,
                  re-signs with real credentials from the provider. Supports
                  signed body, streaming unsigned, and unsigned payload modes.
                  AWS region extracted from hostname or explicit signing_region.
Key Files:
  - crates/openshell-sandbox/               (SigV4 signing implementation)
  - proto/sandbox.proto                     (credential_signing fields)
Known Limitations:
  - Chunk-signed streaming modes rejected
  - Mutually exclusive with request_body_credential_rewrite
  - Direct AWS Bedrock with SigV4 is a separate follow-up

13. CREDENTIAL REFRESH AND ROTATION
--------------------------------------------------------------------------------
Category:         Security / Credentials
Maturity:         DEVELOPING
Description:      Gateway-owned credential refresh for providers. Supports
                  multiple strategies: static, external, OAuth2 refresh token,
                  OAuth2 client credentials, and Google service account JWT.
                  ConfigureProviderRefresh stores refresh material; RotateProvider-
                  Credential mints fresh tokens. ADC-backed providers auto-rotate.
                  Refresh state persisted as scoped objects alongside providers.
Key Files:
  - proto/openshell.proto                   (Refresh messages)
  - crates/openshell-server/                (Refresh implementation)
Known Limitations:
  - Refresh material stored alongside provider records

14. DOCKER COMPUTE DRIVER
--------------------------------------------------------------------------------
Category:         Compute / Drivers
Maturity:         MATURE
Description:      In-process ComputeDriver backend for local Docker sandbox
                  containers. Uses host networking so loopback gateway endpoints
                  work from the supervisor. Supports bind-mounted supervisor
                  binary or supervisor image extraction. GPU passthrough with
                  CDI auto-detection and fallback to --gpus all. Per-sandbox
                  CPU/memory resource limits. Named volume mounts and tmpfs.
Key Files:
  - crates/openshell-driver-docker/         (Docker driver crate)
Known Limitations:
  - Host bind mounts unsafe; require explicit opt-in
  - macOS uses Docker Desktop host-gateway callback alias

17. MICROVM COMPUTE DRIVER (LIBKRUN)
--------------------------------------------------------------------------------
Category:         Compute / Drivers
Maturity:         BASIC
Description:      Standalone libkrun-backed ComputeDriver subprocess providing
                  per-sandbox microVM isolation. Embeds its own rootfs and
                  runtime. Boots a cached bootstrap rootfs.ext4, prepares OCI
                  images inside a bootstrap VM with umoci, attaches prepared
                  image disk read-only, and gives each sandbox a writable
                  overlay.ext4 for merged-root changes. Driver persists launch
                  requests and restarts VMs on driver startup.
Key Files:
  - crates/openshell-driver-vm/             (VM driver crate)
  - crates/openshell-vfio/                  (VFIO GPU passthrough)
Known Limitations:
  - Experimental
  - Per-sandbox CPU/memory fields accepted but currently ignored
  - Requires host virtualization support

--------------------------------------------------------------------------------
18. EXTENSION COMPUTE DRIVER (OUT-OF-TREE)
--------------------------------------------------------------------------------
Category:         Compute / Drivers
Maturity:         BASIC
Description:      Out-of-tree drivers operated alongside the gateway via Unix
                  domain socket. Selected by custom compute_drivers entry with
                  socket_path. Gateway connects to UDS, runs GetCapabilities,
                  and dispatches sandbox lifecycle through compute_driver.proto.
                  Driver process and socket lifecycle are operator-owned.
Key Files:
  - proto/compute_driver.proto              (Driver contract)
  - architecture/compute-runtimes.md        (Docs)
Known Limitations:
  - Gateway does not spawn, supervise, or remove unmanaged drivers
  - Trust boundary is socket filesystem permissions

23. MTLS AND PKI BOOTSTRAP
--------------------------------------------------------------------------------
Category:         Security / Authentication
Maturity:         MATURE
Description:      mTLS user authentication for local single-user deployments.
                  Clients present certificates signed by deployment CA. PKI
                  bootstrap via `openshell-gateway generate-certs` creates
                  CA, server/client TLS certs, and sandbox JWT signing material.
                  Supports output to Kubernetes Secrets or filesystem. Idempotent

Key Files:

  - crates/openshell-server/                (PKI generation)
  - deploy/helm/openshell/templates/certgen.yaml
Known Limitations:
  - JWT signing-key rotation is offline operator action
  - No online rotation with multiple verification keys yet

--------------------------------------------------------------------------------
25. SANDBOX JWT AUTHENTICATION
--------------------------------------------------------------------------------
Category:         Security / Authentication
Maturity:         MATURE
Description:      Gateway-signed JWTs bound to single sandbox IDs authenticate
                  supervisor RPCs. Docker/Podman/VM drivers deliver tokens via
                  bind-mounted files. K8s supervisors exchange projected
                  ServiceAccount tokens through IssueSandboxToken RPC (validated
                  via K8s TokenReview). Sandbox JWTs are not user credentials;
                  only accepted on supervisor-to-gateway RPC allowlist.
                  Supports both v1alpha1 and v1beta1 Agent Sandbox ownerReferences.
Key Files:
  - proto/openshell.proto                   (IssueSandboxToken, RefreshSandboxToken)
  - crates/openshell-server/                (JWT minting/validation)
Known Limitations:
  - Older tokens not server-revoked; bound by short TTL
  - Default TTL=0 for local gateways (non-expiring)

26. GATEWAY PERSISTENCE (SQLITE / POSTGRES)
--------------------------------------------------------------------------------
Category:         Core / Storage
Maturity:         MATURE
Description:      Protobuf object store with SQLite (local default) or Postgres
                  (shared deployments). Generic schema with id, object_type,
                  name, scope, version, status, payload columns. Optimistic
                  concurrency control (CAS) with resource_version. Compile-time
                  enforcement: unconditional writes gated behind #[cfg(test)].
                  All creates use MustCreate, updates use update_message_cas.
                  SQLite files tightened to mode 0o600 for credential protection.
Key Files:
  - crates/openshell-server/src/persistence/ (Store implementation)
  - crates/openshell-server/migrations/      (SQL migrations)
Known Limitations:
  - SQLite for single-replica only; Postgres needed for HA
  - Global settings use Mutex + CAS (insufficient for multi-replica)

27. SUPERVISOR RELAY SYSTEM
--------------------------------------------------------------------------------

Maturity:         MATURE

  - Live relay streams lost on supervisor disconnect

--------------------------------------------------------------------------------
31. POLICY ADVISOR PIPELINE
--------------------------------------------------------------------------------
Category:         Security / Policy
Maturity:         DEVELOPING
Description:      Turns observed denials into draft policy recommendations.
                  Two proposers: sandbox-side mechanistic mapper (L4 denials →
                  rules) and agent-authored via policy.local API. Gateway is
                  single referee. Pipeline: Submit → Validate (prover) →
                  Auto-approval gate (opt-in, requires prover delta empty) →
                  Implicit supersede (newer proposals auto-reject older matching
                  chunks) → Escalation to human review. Supports approve, reject,
                  edit, undo, clear operations. Draft history tracking.
Key Files:
  - proto/openshell.proto                   (Draft policy RPCs)
  - crates/openshell-server/                (Advisor implementation)
  - examples/policy-advisor/                (Demo)
  - examples/agent-driven-policy-management/ (Agent-driven demo)
  - rfc/0002-agent-driven-policy-management/ (RFC)
Known Limitations:
  - L7 denials excluded from mechanistic mapping (by design)
  - LLM-based contextual reviewer planned but not implemented

--------------------------------------------------------------------------------
32. FORMAL POLICY PROVER (Z3)
--------------------------------------------------------------------------------
Category:         Security / Verification
Maturity:         DEVELOPING
Description:      Z3-based formal verification of policy proposals. Builds Z3
                  model from merged policy plus sandbox credential set, computes
                  delta of findings between baseline and proposed policy. Detects:
                  link_local_reach (cloud metadata), l7_bypass_credentialed
                  (non-HTTP wire protocols), credential_reach_expansion (new
                  authenticated reach), capability_expansion (new HTTP methods).
                  Any finding blocks auto-approval.
Key Files:
  - crates/openshell-prover/                (Z3 prover crate)
  - architecture/security-policy.md         (Prover docs)
Known Limitations:
  - v1 does not model credential scopes (read-only vs write)
  - Credential presence is sandbox-coarse, not binary-fine

--------------------------------------------------------------------------------
33. OCSF STRUCTURED SECURITY LOGGING
--------------------------------------------------------------------------------
Category:         Observability / Security
Maturity:         MATURE
Description:      OCSF v1.7.0 event types for structured security logging.

                  ProcessActivity, DetectionFinding, ConfigStateChange,

ARCHITECTURE SUMMARY
================================================================================

OpenShell's architecture is organized around three stable runtime components:

  CLI / SDK / TUI  →  Gateway (Control Plane)  →  Supervisor (Data Plane)

The GATEWAY owns:
  - Authenticated API access (gRPC + HTTP)
  - Durable state (SQLite / Postgres)
  - Policy and settings delivery
  - Provider credential management
  - Inference configuration
  - Supervisor relay coordination
  - Draft policy advisor pipeline

The SUPERVISOR owns:
  - Sandbox-local security boundary
  - Filesystem, process, network isolation
  - Policy proxy (L4/L7 enforcement)
  - Inference interception and routing
  - Credential injection (env vars + HTTP headers)
  - SSH server for connect/exec
  - OCSF security logging
  - Gateway config polling

Integration boundaries are driver/adapter-based:
  - COMPUTE drivers: Docker, Podman, K8s, VM, Extension
  - CREDENTIALS drivers: Provider profiles, token grants
  - CONTROL-PLANE IDENTITY: mTLS, OIDC, Cloudflare JWT
  - SANDBOX IDENTITY: Gateway JWT, SPIFFE (external)

The POLICY MODEL uses overlapping controls:
  - Landlock (filesystem) — locked at creation
  - Seccomp (process) — locked at creation
  - Network namespace — locked at creation
  - OPA proxy (network, L7) — hot-reloadable
  - Inference router — hot-reloadable
