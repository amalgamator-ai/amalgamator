1. ISSUES FOUND AND FIXED
================================================================================

12 issues were identified across 4 severity levels. All have been corrected
in the reviewed test plan (test_plan_review_V1.txt).

1.1 CRITICAL ISSUES (1)
────────────────────────

  R1-1: OidcConfig test helper uses wrong field names

    PROBLEM: The test_server_state_with_ownership() helper constructs
    OidcConfig with field names that don't exist in the actual struct:
      - `jwks_ttl: 300` — actual field is `jwks_ttl_secs` (config.rs:472)
      - `ca_cert_path: None` — field doesn't exist on OidcConfig at all
        (it's on TlsConfig). OidcConfig has #[serde(deny_unknown_fields)]
        which makes this a hard compilation error.

    IMPACT: Every test using this helper would fail to compile. This
    affects ~50+ integration tests across Sections 9, 10, 11, and 15.

    FIX: Corrected field names to match the actual OidcConfig struct.
    Removed the non-existent ca_cert_path field.

    VERIFICATION METHOD: Compared test plan's struct literal against
    the actual OidcConfig at crates/openshell-core/src/config.rs:463-493.

1.2 HIGH ISSUES (3)
────────────────────

  R1-2: Provider shared access contradicts check_ownership semantics

    PROBLEM: Section 3.3 tests that check_ownership returns
    PermissionDenied for resources with no owner label. But Section 10.3
    tests that shared providers (no owner label) are accessible to any
    user. These are logically contradictory.

    ROOT CAUSE: The port plan describes different access semantics for
    sandboxes (no label = deny, migration safety) vs providers (no label
    = shared, accessible to all).

    FIX: Added `allow_unowned: bool` parameter to check_ownership().
    Sandboxes pass false (strict), providers pass true (shared access).
    Updated all tests to include the parameter.

  R1-3: Integration test file can't call private/pub(super) handlers

    PROBLEM: Section 15 proposed tests in tests/ownership_integration.rs
    that call handle_create_sandbox_inner() (private, line 119) and
    other pub(super) handlers. Integration test files in tests/ are a
    separate crate and can only access pub items.

    VERIFICATION: Confirmed handle_create_sandbox_inner has no pub
    modifier at sandbox.rs:119. handle_delete_sandbox_inner is also
    private at line 496. The pub(super) handlers are module-private.

    FIX: Eliminated the separate tests/ownership_integration.rs file.
    All handler tests are placed in the source files' #[cfg(test)]
    modules where they can access private functions. Section 15 E2E
    lifecycle tests are incorporated into sandbox.rs and provider.rs
    test modules.

  R1-4: Provider role change tests test the wrong gate mechanism

    PROBLEM: Tests "create_provider_role_changed_to_user_when_ownership_enabled"
    and "create_provider_still_admin_only_when_ownership_disabled" call
    handle_create_provider directly. But the role check happens at the
    gRPC service routing layer via #[rpc_auth] attribute, not in the
    handler. Calling the handler directly ALWAYS bypasses role checks.

    The port plan Step 11E adds a RUNTIME GUARD inside the handler for
    the disabled case, which IS testable by direct call. But the enabled
    case would always pass regardless of the #[rpc_auth] attribute value.

    FIX: Tests renamed and reframed to explicitly test the runtime guard.
    The #[rpc_auth] change is documented as verified by compilation and
    existing auth integration tests, not by direct handler invocation.

1.3 MEDIUM ISSUES (4)
─────────────────────

  R1-5: OIDC groups extraction tests assume wrong mechanism

    PROBLEM: Section 5.1 tested direct JSON deserialization of groups.
    But the port plan adds groups with #[serde(skip)], and the existing
    roles field uses the same pattern (serde(skip) + extract_roles()
    method walking the `extra` field). Groups will use extract_groups()
    following the identical pattern.

    VERIFICATION: Confirmed roles has #[serde(skip)] at oidc.rs:103-104
    and extract_roles() at oidc.rs:119-133 walks self.extra via dot-path.

    FIX: Section 5 tests rewritten to exercise extract_groups() method
    with various claim structures (flat array, nested path, missing,
    non-array, mixed types).

  R1-6: K8s driver sandbox_labels() test describes wrong behavior

    PROBLEM: Section 12 said "sandbox_labels() reads from
    spec.template.labels." The CURRENT sandbox_labels() (driver.rs:857-865)
    only inserts LABEL_SANDBOX_ID and LABEL_MANAGED_BY — it does NOT
    read template.labels. Step 12 modifies it to include template labels.

    FIX: Section 12 tests now explicitly state they test the MODIFIED
    function and document what the modification IS. Also clarified that
    the K8s driver aliases DriverSandbox as Sandbox (line 28).

  R1-7: Streaming handler "allowed" tests need clarification

    PROBLEM: Tests like watch_sandbox_allowed_for_owner need the handler
    to proceed past the ownership check into streaming setup, which may
    fail with NoopTestDriver if no sandbox is running.

    FIX: "Allowed" streaming tests now assert "NOT PermissionDenied"
    rather than full Ok, acknowledging that other errors may occur.

  R1-8: Significant test overlap between Sections 9-10 and Section 15

    PROBLEM: Many Section 15 tests duplicated Section 9-10 single-operation
    tests with different framing.

    FIX: Section 15 stripped of duplicates, retaining only multi-step
    lifecycle scenarios that exercise inter-operation interactions not
    covered by single-operation tests.

1.4 LOW ISSUES (4)
───────────────────

  R1-9: labels_from_json() tests for non-existent function
    FIX: Removed. Function not defined in port plan, not needed.

  R1-10: Meta-tests not implementable as test functions
    FIX: Reclassified as CI gate checks, not counted as test cases.

  R1-11: Missing test for explicit ownership disabled (Some(false))
    FIX: Added ownership_config_disabled_when_explicitly_false to Section 8.

  R1-12: Missing label serialization roundtrip test
    FIX: Enhanced Section 11 list_with_selector test to explicitly
    document the roundtrip verification (was partially implicit before).
