2. ITERATION EVOLUTION
================================================================================

The following describes the progression across all iterations:

V1 (Initial Plan):
  - First comprehensive plan for multi-tenant support
  - 18 steps covering per-user ownership + gateway-per-tenant
  - V1-R1 review found 11 issues (3 critical, 3 high, 3 medium, 2 low):
    * Critical: Principal extraction pattern wrong, label access pattern
      wrong, OidcClaims.extra type wrong
    * High: object_id() pattern missed, watch/exec handlers missed,
      Helm pod template wrong file
    * Medium: deny_unknown_fields implications, GatewayFileSection
      constraints, scope requirement missed
    * Low: SandboxIndex optional marking, admin bypass design

V2 (Rebuilt Plan Incorporating V1-R1):
  - All 11 V1-R1 fixes integrated from the start
  - Restructured to 20 steps with explicit dependency graph
  - Added 6 corrections from fresh source verification
  - V2-R1 review found 6 additional issues (1 high, 2 medium, 3 low):
    * HIGH: Provider runtime guard uses empty admin_role when ownership
      disabled -- functional regression that would break admin provider
      creation in OIDC-enabled, ownership-disabled deployments
    * MEDIUM: OidcConfig deny_unknown_fields incorrectly claimed absent;
      provider:write scope requirement not documented
    * LOW: Dead helper function with wrong trait bounds; pod labels
      targeting wrong template file; ClusterRole name drops suffix

V3 (Current -- From Scratch):
  - Built from scratch with ALL 17 prior issues pre-fixed
  - Fresh codebase verification with 4 parallel exploration agents
  - Key improvements over V2:

    1. Correct OwnershipEnforcement Design (prevents R2-1 by construction):
       ownership_config() ALWAYS populates admin_role from OIDC config,
       regardless of whether ownership is enabled. The V2 design required
       a separate code path to read admin_role from state.config.oidc
       when ownership was disabled. V3 eliminates this complexity by
       ensuring admin_role is always populated from the same source.

    2. Verified Line Numbers:
       All line numbers confirmed against current OpenShell HEAD via
       4 parallel exploration agents. No unverified structural claims.

    3. Correct Helm Chart Details:
       - Chart name is "helm-chart" (V2 used "openshell")
       - Values path is server.oidc.* (V2 used oidc.*)
       - Sandbox namespace is server.sandboxNamespace (V2 used driver.namespace)
       - Template directory has 16 files (V2 had incomplete list)

    4. Cleaner Tenant Label Architecture:
       V3 adds tenant labels to the openshell.labels helper (which all
       resources use), rather than modifying individual template files.
       This ensures comprehensive coverage without per-file changes.
       V2 required modifying _gateway-workload.tpl; V3 requires only
       _helpers.tpl (the labels helper).

    5. No Dead Code:
       V2 included a labels_from_metadata helper with incorrect trait
       bounds that was never called. V3 has no helper function -- uses
       the inline pattern throughout, which is clearer and avoids the
       compile error.

    6. Known Limitations Section:
       V3 adds Section 10 documenting three known limitations:
       - Global name uniqueness constraint (with future migration path)
       - Watch bus not tenant-filtered (with explanation of why it's safe)
       - Pre-existing resources without owner labels (with admin fallback)

    7. Complete Test Plan:
       V3's Step 20 provides actual Rust test code for 13 ownership
       module unit tests, 5 provider ownership tests, 8 integration
       tests, and Helm template validation tests. V2 had test
       descriptions without code.

    8. Better Risk Analysis:
       V3's risk analysis includes 12 risks with specific mitigations.
       Risk #5 (admin role source) is explicitly marked as "MITIGATED
       BY DESIGN" since the V3 ownership_config() design prevents it.

Quality trend:
  V1:  First draft -- correct architecture, many implementation errors
  V2:  Major improvement -- correct patterns, residual config/template bugs
  V3:  Production-ready -- verified against source, defensive design patterns

Architectural stability:
  The two-layer architecture (per-user ownership + gateway-per-tenant) has
  been stable since V1. No architectural changes across iterations. All
  improvements have been implementation-level corrections:
  - Correct Rust patterns (Principal extraction, label access, object_id)
  - Correct serde behavior (deny_unknown_fields + default)
  - Correct Helm patterns (shared partials, suffix preservation, values paths)
  - Correct authorization logic (admin_role source, scope requirements)

Key design decision validated across iterations:
  The ownership_config() method on ServerState that always populates
  admin_role from OIDC config is the V3 innovation that prevents the
  most serious bug found in V2 (Issue R2-1). This design makes the
  bug impossible by construction, rather than relying on correct code
  paths in each handler.
