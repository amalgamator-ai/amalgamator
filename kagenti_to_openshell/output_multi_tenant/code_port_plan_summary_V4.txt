1.2 New Findings in V4 (10 total)
----------------------------------

Beyond pre-fixing the 25 prior issues, V4 identified 10 new findings:

  V4-1: Config uses builder pattern (.with_* methods)
    Impact: New ownership/tenant fields should follow the builder pattern
    for consistency, adding .with_ownership() and .with_tenant_id() methods.
    V3 used direct field assignment, inconsistent with the codebase pattern.

  V4-2: OidcConfig struct literal in cli.rs requires explicit update
    Impact: Adding groups_claim to OidcConfig requires updating the struct
    literal at cli.rs lines 396-406. V3 did not explicitly address this,
    which would cause a compile error.

  V4-3: handle_create_ssh_session needs ownership enforcement
    Impact: SSH session creation (line 1330) was not explicitly listed in
    V3 Step 10 as needing ownership enforcement. It fetches a sandbox by
    ID and must verify ownership. V4 adds explicit Step 10C.

  V4-4: K8s driver labels at TWO distinct levels
    Impact: sandbox_labels() (CRD-level) and template.labels (pod-level)
    are separate code paths. V3 corrected the proto type access path but
    did not clarify the two-level label architecture. V4 Step 12 explains
    both paths and why only sandbox_labels() needs modification.

  V4-5: Docker driver CONFIRMED no code change needed
    Impact: Docker driver starts with template.labels.clone() at line 2337.
    Owner labels in the template automatically propagate. V3-R1 noted this
    as "verify needed"; V4 confirms with exact line number.

  V4-6: End-to-end label flow diagram added
    Impact: V4 includes a complete ASCII diagram (Section 11) tracing
    owner labels from API request → gateway → persistence → compute →
    K8s driver / Docker driver. This was not present in any prior iteration.

  V4-7: GatewayFileSection deny_unknown_fields explicitly addressed
    Impact: Both OidcConfig AND GatewayFileSection have deny_unknown_fields.
    V3 addressed OidcConfig but was vague about GatewayFileSection. V4
    explicitly states that new fields in GatewayFileSection MUST use
    #[serde(default)] and provides exact placement.

  V4-8: Config::new() initializer requires new field defaults
    Impact: Config::new() at line 569 lists all 16 fields explicitly.
    Adding ownership and tenant_id requires adding default values in this
    initializer (ownership: None, tenant_id: None). V3 did not mention this.

  V4-9: Provider listing in-memory filter strategy
    Impact: V3's provider list filtering relied on list_with_selector which
    doesn't support "label absent" queries needed for showing shared +
    user-owned providers. V4 Step 11B provides a practical in-memory
    filtering approach.

  V4-10: CLI arg for groups_claim needed
    Impact: OidcConfig's groups_claim needs a CLI arg (--oidc-groups-claim)
    and environment variable (OPENSHELL_OIDC_GROUPS_CLAIM) in RunArgs.
    V3 added the config field but not the CLI integration.
