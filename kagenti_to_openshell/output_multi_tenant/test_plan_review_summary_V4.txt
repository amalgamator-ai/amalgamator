1.2 MEDIUM ISSUES (2)
──────────────────────

  R4-1: validate_token() takes 1 argument, not 2

    PROBLEM: All 4 wiremock OIDC tests (Section 17) call:
      cache.validate_token(&jwt, &config).await.unwrap()
    But the actual signature is:
      pub async fn validate_token(&self, token: &str) -> Result<Identity, Status>
    The OidcConfig is captured inside JwksCache during new(), not passed
    to validate_token. Additionally, Test 17.3 modifies config.groups_claim
    AFTER JwksCache construction, but the config is already captured inside
    the cache — the mutation would have no effect.

    Verified at oidc.rs line 288: only &self and token: &str.

    FIX:
    - Remove &config from all validate_token calls
    - Test 17.3: modify config BEFORE constructing JwksCache:
        let (mock, mut config, key) = setup_mock_jwks_server().await;
        config.groups_claim = "custom.team_membership".to_string();
        let cache = JwksCache::new(&config).await.unwrap();
        cache.validate_token(&jwt).await.unwrap();

  R4-2: E2E test file location wrong — e2e/rust/ is a separate crate

    PROBLEM: Section 16 places tests at:
      e2e/rust/tests/ownership_lifecycle.rs
    But e2e/rust/ is a SEPARATE workspace crate (openshell-e2e) that:
    - Has its own [workspace] in Cargo.toml
    - Uses feature gating (#![cfg(feature = "e2e")])
    - Runs CLI binary commands via openshell_cmd (black-box testing)
    - Cannot access #[cfg(test)] items from openshell-server

    The Section 16 tests are white-box handler tests that call
    test_server_state_with_ownership(), make_user(), and handler
    functions directly. They cannot compile in e2e/rust/tests/.

    FIX: Move Section 16 tests into the handler test modules:
    - 16.1 + 16.3 (5 tests) → grpc/sandbox.rs #[cfg(test)] mod tests
    - 16.2 (3 tests) → grpc/provider.rs #[cfg(test)] mod tests
    These are handler-level integration tests, not E2E tests. The
    "E2E" label was misleading.

1.3 LOW ISSUES (2)
───────────────────

  R4-3: put_if name parameter is &str, not Option<&str>

    PROBLEM: Section 12.1 passes Some("my-sandbox") for the name
    parameter, but the actual put_if signature has name: &str (not
    Option<&str>). Verified at persistence/mod.rs line 236.

    FIX: Changed Some("my-sandbox") to "my-sandbox".

  R4-4: Test 6.4.7 uses .. struct update syntax on Identity without Default

    PROBLEM: Test 6.4.7 describes Identity construction ending with
    `..` (struct update syntax), but Identity has no Default impl
    (#[derive(Debug, Clone)] only, verified at identity.rs lines 15-31).
    Without Default, the `..` syntax won't compile.

    FIX: Spelled out all 6 Identity fields explicitly (subject,
    display_name, roles, scopes, groups, provider).
