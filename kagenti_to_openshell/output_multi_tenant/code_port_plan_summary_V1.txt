2. KEY ARCHITECTURAL DECISIONS
================================================================================

Decision 1: Two-Layer Multi-Tenancy
  Layer 1 (per-user ownership) handles application-level user isolation within
  a gateway instance via the openshell.ai/owner label. Layer 2 (gateway-per-
  tenant) handles organizational isolation via Kubernetes namespaces and RBAC.
  Both layers compose without coupling.

Decision 2: Owner-Label Approach (not DB column for V1)
  V1 stores ownership information in the existing labels JSON column, leveraging
  the existing list_with_selector() API. This avoids database schema migrations
  while providing full ownership enforcement. A future V2 can add an owner
  column for name-scoped uniqueness if needed.

Decision 3: Zero Breaking Changes
  All multi-tenancy behavior is gated behind configuration flags (ownership.enabled
  and tenant.id). Default values disable all new behavior, ensuring existing
  single-user deployments are unaffected.

Decision 4: Minimal Protobuf Changes
  No changes to the protobuf message definitions. The owner is carried in the
  existing ObjectMeta.labels map. This preserves API compatibility and avoids
  forcing clients to update.

3. ITERATION EVOLUTION
================================================================================

V1 (current iteration):
  - First comprehensive plan covering the complete multi-tenancy feature
  - Designed for incremental implementation across 5 phases
  - Prioritizes backward compatibility and zero breaking changes
  - Defers database migration to a future V2 iteration
  - Covers both Rust gateway code and Helm chart infrastructure
  - Includes detailed Rust code examples matching OpenShell's exact conventions
    (derive macros, error handling with thiserror, tonic::Status mapping,
    #[allow(clippy::...)] patterns, guard.rs test helper patterns)

  Known limitations in V1:
  - Name uniqueness remains global (two users in shared gateway cannot have
    same-named sandboxes). Acceptable in gateway-per-tenant where each gateway
    has its own database.
  - Provider resolution for user-owned > shared requires listing all providers
    and filtering client-side. A future optimization can add a DB-level query
    for owner-scoped name lookup.
  - Groups extraction from OIDC JWT is optional and not used for authorization
    in V1. It's included for audit logging and future group-based policies.
  - K8s E2E tests require a live cluster with Keycloak, which may not be
    available in all CI environments.
