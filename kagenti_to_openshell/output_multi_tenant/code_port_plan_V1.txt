1. EXECUTIVE SUMMARY
================================================================================

This plan ports Kagenti's multi-tenant deployment support to OpenShell. The
feature operates at two complementary layers:

  Layer 1 — Per-User Ownership (Rust gateway code changes):
    Within a single gateway instance (shared by a team/tenant), enforce
    per-user isolation via the openshell.ai/owner label. This is the
    core Rust work: owner stamping on create, per-user filtering on list,
    ownership checks on get/delete, admin bypass, anti-spoofing.

  Layer 2 — Gateway-Per-Tenant (Helm/infrastructure changes):
    Each tenant (team/organization) gets a dedicated Kubernetes namespace
    with an isolated gateway stack, namespace-scoped RBAC, per-tenant
    OIDC audience scoping, ResourceQuota, LimitRange, and TLS certs.
    This is primarily Helm chart and deployment tooling work.

Both layers compose: Layer 2 isolates tenants at the Kubernetes boundary,
while Layer 1 isolates users within a tenant at the application layer.

The plan preserves backward compatibility: when OIDC is disabled or
multi-tenancy config is absent, all ownership logic is bypassed
(Anonymous principal => no owner stamping, no filtering).

================================================================================
2. ARCHITECTURAL DECISION
================================================================================

DECISION: Adopt the Kagenti "owner-label" approach for Layer 1 and the
"gateway-per-tenant Helm deployment" approach for Layer 2.

Rationale:

  1. Owner-label approach leverages EXISTING OpenShell infrastructure:
     - labels column in objects table (already present)
     - list_with_selector() API (already implemented)
     - ObjectMeta.labels in protobuf (already defined)
     - Identity.subject from OIDC JWT (already extracted)
     No schema changes to protobuf messages are needed.

  2. Gateway-per-tenant avoids invasive single-gateway multi-tenant changes:
     - No tenant column needed in the database (each gateway has its own DB)
     - No tenant-aware connection pooling
     - No cross-tenant broadcast filtering on watch bus
     - Tenant isolation enforced by Kubernetes namespace RBAC
     - Clean lifecycle management (deploy/destroy per-tenant independently)

  3. OIDC audience scoping per gateway instance is already supported:
     - OidcConfig.audience is a single configurable value
     - Each gateway instance in its own namespace gets its own audience
     - No code change needed for audience-per-tenant; it's config-per-deploy

  Alternatives considered and rejected:

  A. Single gateway, tenant column in DB:
     Would require invasive schema changes, all queries must carry tenant,
     watch bus must filter by tenant, sandbox index must partition by tenant.
     Much higher complexity for marginal benefit.

  B. Virtual tenants via gateway configuration:
     Would require multi-audience OIDC validation, per-request tenant
     resolution, and query-level tenant partitioning. Breaks the clean
     separation that gateway-per-tenant provides.

  //! Per-user ownership enforcement for multi-tenant deployments.
  //!
  //! When OIDC is enabled, each object (sandbox, provider) is stamped with
  //! `openshell.ai/owner = <identity.subject>` at creation time. List, get,
  //! and delete operations enforce that users can only access their own
  //! objects, unless the caller has the admin role (ownership bypass).
  //!
  //! When OIDC is disabled (Anonymous principal), ownership is not enforced.
  //! This preserves backward compatibility for single-user local gateways.

  use super::identity::Identity;
  use super::principal::Principal;
  use std::collections::HashMap;
  use tonic::Status;
  use tracing::{debug, info};

  /// Label key for per-user ownership.
  pub const LABEL_OWNER: &str = "openshell.ai/owner";

  /// Label key for tenant identity.
  pub const LABEL_TENANT: &str = "openshell.ai/tenant";

  /// Reserved label key prefix. Client-supplied labels with this prefix
  /// are stripped at creation time to prevent spoofing.
  const RESERVED_LABEL_PREFIX: &str = "openshell.ai/";

  /// Configuration for ownership enforcement.
  #[derive(Debug, Clone)]
  pub struct OwnershipConfig {
      /// When true, ownership enforcement is active.
      /// Set to true when OIDC is configured with admin/user roles.
      pub enabled: bool,

      /// Role name that grants admin access (ownership bypass).
      pub admin_role: String,
  }

  impl OwnershipConfig {
      /// Create an ownership config from the OIDC config.
      /// Returns enabled=false when OIDC is not configured.
      pub fn from_authz(admin_role: &str) -> Self {
          Self {
              enabled: !admin_role.is_empty(),
              admin_role: admin_role.to_string(),
          }
      }

      /// Disabled ownership (for backward compatibility).
      pub fn disabled() -> Self {
          Self {
              enabled: false,
              admin_role: String::new(),
          }
      }
  }

  /// Determine whether ownership enforcement should be applied for
  /// the given principal. Returns `None` when ownership is not applicable
  /// (anonymous, ownership disabled, admin bypass).
  pub fn resolve_owner(
      config: &OwnershipConfig,
      principal: &Principal,
  ) -> Option<String> {
      if !config.enabled {
          return None;
      }
      match principal {
          Principal::User(user) => {
              if is_admin(&user.identity, &config.admin_role) {
                  // Admin callers are not subject to ownership enforcement.
                  // They can see all objects and create objects without owner.
                  None
              } else {
                  Some(user.identity.subject.clone())
              }
          }
          Principal::Sandbox(_) | Principal::Anonymous => None,
      }
  }

  /// Stamp owner label onto a mutable label map, stripping any
  /// client-supplied openshell.ai/* keys first (anti-spoofing).
  ///
  /// If `owner` is `None` (admin or anonymous), client-supplied
  /// reserved keys are still stripped but no owner is stamped.
  pub fn stamp_owner_labels(
      labels: &mut HashMap<String, String>,
      owner: Option<&str>,
  ) {
      // Strip all client-supplied reserved labels (anti-spoofing).
      labels.retain(|key, _| !key.starts_with(RESERVED_LABEL_PREFIX));

      // Stamp owner if applicable.
      if let Some(owner_id) = owner {
          let sanitized = sanitize_label_value(owner_id);
          labels.insert(LABEL_OWNER.to_string(), sanitized);
          debug!(owner = %owner_id, "stamped owner label on object");
      }
  }

  /// Build a label selector string that includes the owner filter.
  ///
  /// If the caller is an admin or ownership is disabled, returns `None`
  /// (no additional filtering). Otherwise returns
  /// `"openshell.ai/owner=<subject>"`.
  pub fn owner_label_selector(
      config: &OwnershipConfig,
      principal: &Principal,
  ) -> Option<String> {
      let owner = resolve_owner(config, principal)?;
      Some(format!("{}={}", LABEL_OWNER, sanitize_label_value(&owner)))
  }

  /// Combine an optional user-provided label selector with the owner
  /// filter. Returns the merged selector string.
  pub fn merge_label_selectors(
      user_selector: &str,
      owner_selector: Option<&str>,
  ) -> String {
      match (user_selector.is_empty(), owner_selector) {
          (true, None) => String::new(),
          (true, Some(owner)) => owner.to_string(),
          (false, None) => user_selector.to_string(),
          (false, Some(owner)) => format!("{},{}", user_selector, owner),
      }
  }

  /// Check ownership of an existing object. Returns `Ok(())` if the
  /// caller is the owner or an admin. Returns
  /// `Err(Status::permission_denied)` otherwise.
  ///
  /// `object_labels` is the JSON-deserialized label map from the object.
  /// `object_kind` is a human-readable name for error messages (e.g.
  /// "sandbox", "provider").
  #[allow(clippy::result_large_err)]
  pub fn enforce_ownership(
      config: &OwnershipConfig,
      principal: &Principal,
      object_labels: &HashMap<String, String>,
      object_kind: &str,
  ) -> Result<(), Status> {
      if !config.enabled {
          return Ok(());
      }
      match principal {
          Principal::User(user) => {
              if is_admin(&user.identity, &config.admin_role) {
                  return Ok(());
              }
              let caller_subject = &user.identity.subject;
              if let Some(owner) = object_labels.get(LABEL_OWNER) {
                  if owner == caller_subject {
                      Ok(())
                  } else {
                      info!(
                          caller = %caller_subject,
                          owner = %owner,
                          kind = %object_kind,
                          "ownership check failed: caller is not owner"
                      );
                      // Return NotFound rather than PermissionDenied to
                      // avoid leaking object existence to non-owners.
                      Err(Status::not_found(format!("{object_kind} not found")))
                  }
              } else {
                  // Object has no owner label (admin-created / legacy).
                  // Non-admin users can access shared objects.
                  Ok(())
              }
          }
          // Sandbox principals access objects via sandbox-scoped guards,
          // not user ownership. Anonymous principals bypass ownership.
          Principal::Sandbox(_) | Principal::Anonymous => Ok(()),
      }
  }

  /// Extract object labels from a protobuf message's JSON label string.
  pub fn parse_object_labels(labels_json: Option<&str>) -> HashMap<String, String> {
      labels_json
          .and_then(|json| serde_json::from_str(json).ok())
          .unwrap_or_default()
  }

  /// Extract labels from a protobuf ObjectMeta's label map.
  pub fn labels_from_proto(
      labels: &HashMap<String, String>,
  ) -> HashMap<String, String> {
      labels.clone()
  }

  /// Returns `true` if the identity has the admin role.
  fn is_admin(identity: &Identity, admin_role: &str) -> bool {
      !admin_role.is_empty() && identity.roles.iter().any(|r| r == admin_role)
  }

  /// Sanitize a string for use as a Kubernetes label value.
  ///
  /// Kubernetes label values must be <= 63 chars and match:
  ///   ([A-Za-z0-9][-A-Za-z0-9_.]*)?[A-Za-z0-9]
  /// Keycloak UUID subjects satisfy this natively, but other OIDC
  /// providers may use email addresses or other formats.
  pub fn sanitize_label_value(value: &str) -> String {
      let sanitized: String = value
          .chars()
          .filter(|c| c.is_ascii_alphanumeric() || *c == '-' || *c == '_' || *c == '.')
          .take(63)
          .collect();
      if sanitized.is_empty() {
          "unknown".to_string()
      } else {
          sanitized
      }
  }

Key design decisions:
  - Returns NotFound (not PermissionDenied) for non-owners to avoid
    leaking object existence. Matches Kagenti behavior.
  - Admin bypass checks identity.roles for admin_role. Same pattern as
    existing AuthzPolicy.check().
  - Shared objects (no owner label) are accessible to all users.
    Admins create shared providers; users get their own.
  - Anti-spoofing: ALL openshell.ai/* labels stripped from client input
    before stamping the server-derived owner.

New dependencies: None (uses existing serde_json, tonic::Status, tracing).

Purpose:
  The current name uniqueness constraint is global:
    UNIQUE(object_type, name) WHERE name IS NOT NULL

  With per-user ownership, two users should be able to create objects
  with the same name (e.g., both alice and bob can have a sandbox
  named "dev"). We need to add an owner column to the objects table
  and change the uniqueness constraint to include it.

  IMPORTANT: This is OPTIONAL for the initial implementation. The
  simpler approach is to keep global name uniqueness and rely on the
  owner label in the JSON labels column for filtering. The migration
  below is for a future iteration when name-scoping is required.

  FOR V1: Use the simpler label-based approach (no schema change).
  Owner information is stored in the labels JSON column, and name
  uniqueness remains global. This avoids migration risk.

SQLite migration (006_add_owner_column.sql):
  -- Add owner column for per-user name scoping.
  -- Nullable: NULL means shared/admin-created object.
  ALTER TABLE objects ADD COLUMN owner TEXT;

  -- Drop the old global name uniqueness index.

  -- Create a new owner-scoped name uniqueness index.
  -- Two users can have objects with the same name.
  -- A NULL owner means globally unique (admin-created shared objects).
  CREATE UNIQUE INDEX objects_name_owner_uq
      ON objects (object_type, name, COALESCE(owner, ''))

Purpose:
  The in-memory SandboxIndex maps sandbox_name -> sandbox_id and
  agent_pod -> sandbox_id. In a gateway-per-tenant deployment, this
  index is already per-tenant (each gateway has its own process).

  For the per-user ownership layer, the index does NOT need to be
  partitioned by owner because:
    - Name lookups (sandbox_id_for_sandbox_name) resolve to the DB,
      where ownership checks happen
    - Agent pod lookups are for sandbox-principal authentication,
      not user-scoped
    - The index is performance optimization, not authorization boundary

  HOWEVER, we should add optional owner tracking for metrics/debugging.

Target file:
  crates/openshell-server/src/sandbox_index.rs

Changes (minimal):

  A. Add owner field to the inner index entry:

     #[derive(Debug, Default)]
     struct Inner {
         sandbox_name_to_id: HashMap<String, String>,
         agent_pod_to_id: HashMap<String, String>,
         /// Optional: sandbox_id -> owner subject for debugging/metrics.
         sandbox_owner: HashMap<String, String>,
     }

  B. Populate owner from sandbox labels in update_from_sandbox():

     pub fn update_from_sandbox(&self, sandbox: &Sandbox) {
         let mut inner = self.inner.write().expect("sandbox index lock poisoned");
         if let Some(metadata) = &sandbox.metadata {
             // ... existing name/pod index updates ...

             // Track owner for metrics.
             if let Some(owner) = metadata.labels.get("openshell.ai/owner") {
                 inner.sandbox_owner.insert(metadata.id.clone(), owner.clone());
             }
         }
     }

  C. Clean up owner on remove:

     pub fn remove_sandbox(&self, sandbox_id: &str) {
         let mut inner = self.inner.write().expect("sandbox index lock poisoned");
         inner.sandbox_name_to_id.retain(|_, v| v != sandbox_id);
         inner.agent_pod_to_id.retain(|_, v| v != sandbox_id);
         inner.sandbox_owner.remove(sandbox_id);
     }

  D. Add a public method for metrics/debugging:

     #[must_use]
     pub fn owner_for_sandbox(&self, sandbox_id: &str) -> Option<String> {
         let inner = self.inner.read().expect("sandbox index lock poisoned");
         inner.sandbox_owner.get(sandbox_id).cloned()
     }

  - This is a LOW-priority change. The SandboxIndex is not on the

  - All authorization checks happen at the persistence layer.
  - The index is useful for telemetry: counting sandboxes per user.

      /// Build the ownership enforcement configuration from the
      /// server's OIDC and config settings.
      pub fn ownership_config(&self) -> crate::auth::ownership::OwnershipConfig {
          // Ownership is enabled when:
          // 1. The config has ownership.enabled = true, AND
          // 2. OIDC is configured (we need a subject to stamp as owner)
          let enabled = self.config.ownership.enabled
              && self.config.oidc.is_some();

              .map(|oidc| oidc.admin_role.clone())
              .unwrap_or_default();
          crate::auth::ownership::OwnershipConfig {
              enabled,
              admin_role,
          }
      }

6. RISK ANALYSIS
================================================================================

HIGH RISK:

  1. Backward Compatibility (CRITICAL)
     Risk: Existing single-user deployments break when ownership is enabled.
     Mitigation: Ownership is disabled by default (config.ownership.enabled=false).
                  All ownership logic is gated on the config flag AND OIDC being
                  configured. Anonymous principals bypass all ownership checks.
     Validation: Step 18 includes test_ownership_disabled_shows_all().

  2. Name Uniqueness Conflict (MEDIUM)
     Risk: In shared-gateway mode (single gateway, multiple users), two users
            cannot create sandboxes with the same name (global uniqueness).
     Mitigation: V1 uses global name uniqueness (no DB migration). This is
                  acceptable for gateway-per-tenant (each gateway has own DB).
                  Future V2 can add owner-scoped name uniqueness via migration.
     Validation: Document as known limitation.

  3. Provider Resolution Correctness (HIGH)
     Risk: The user-owned > shared provider resolution could introduce subtle
            bugs if a user's provider has different credentials than the shared
            provider with the same name.
     Mitigation: Resolution is deterministic (user-owned wins). Users are
                  informed via list output which provider they own. Admin can
                  see all providers. Provider names are user-chosen, so naming
                  collisions are intentional.
     Validation: Step 18 includes test_sandbox_resolves_user_owned_provider_first().

MEDIUM RISK:

  4. Principal Extraction Ordering
     Risk: Extracting the principal before request.into_inner() requires
            accessing extensions before consuming the request.
     Mitigation: Clone the Principal from extensions (it derives Clone).
                  This matches the pattern already used in guard.rs
                  (enforce_sandbox_scope reads from extensions).

  5. Label Selector Performance (Postgres)
     Risk: Adding owner-based label selector to every list query could
            impact Postgres query performance.
     Mitigation: Postgres already uses JSONB @> operator for label filtering,
                  which is indexed via GIN. Adding one more selector key has
                  minimal performance impact. Add GIN index in migration if
                  needed.

  6. Helm Chart Breaking Changes
     Risk: Adding tenant values to the Helm chart could break existing
            Helm deployments if values.yaml restructuring is incompatible.
     Mitigation: All new values under the `tenant` section are optional
                  with empty/false defaults. Existing deployments that don't
                  set tenant.id continue to work as before.

LOW RISK:

  7. OIDC Group Claim Compatibility
     Risk: Not all OIDC providers use the same claim path for groups.
     Mitigation: groups_claim is configurable (same pattern as roles_claim).
                  Default is empty (groups extraction disabled). Users
                  configure per their OIDC provider.

  8. Label Value Sanitization
     Risk: Non-UUID OIDC subjects (email addresses) may need sanitization
            for Kubernetes label values.
     Mitigation: sanitize_label_value() strips non-compliant characters
                  and truncates to 63 chars. Test coverage included.
