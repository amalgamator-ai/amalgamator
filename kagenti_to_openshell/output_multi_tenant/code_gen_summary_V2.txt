1. EXPLANATION OF CODE PATCH AND TESTS
============================================================================

This iteration implements the multi-tenant resource ownership enforcement
feature for OpenShell, porting the gateway-per-tenant pattern from Kagenti.
The implementation adds:

A) CORE INFRASTRUCTURE (openshell-core crate):
   - OwnershipConfigCore struct: enabled flag + optional tenant_id
   - groups_claim field on OidcConfig for JWT group extraction
   - LABEL_OWNER and LABEL_TENANT constants in driver_utils
   - Public re-export of OwnershipConfigCore from lib.rs

B) AUTHENTICATION ENHANCEMENTS (openshell-server auth module):
   - Groups field added to Identity struct for tenant mapping
   - extract_groups() method on OidcClaims (mirrors extract_roles pattern)
   - Groups extraction wired into validate_token() pipeline
   - All 13 Identity construction sites updated with groups: vec![]

C) OWNERSHIP MODULE (NEW: auth/ownership.rs - 438 lines):
   - OwnershipConfig: server-side config with admin_role for bypass
   - sanitize_label_value(): K8s-compliant label value sanitization
   - stamp_owner_labels(): Anti-spoofing label stamping on resources
   - check_ownership(): Authorization check against resource labels
   - owner_label_selector(): Label selector builder for list filtering
   - 27 unit tests covering all functions and edge cases

D) CONFIGURATION (CLI + config file):
   - --ownership-enabled flag (OPENSHELL_OWNERSHIP_ENABLED env)
   - --tenant-id flag (OPENSHELL_TENANT_ID env)
   - ownership_enabled and tenant_id in GatewayFileSection (TOML)
   - Full precedence chain: CLI > env > file > default
   - ownership_config() helper on ServerState

E) GRPC HANDLER MODIFICATIONS:
   Sandbox handlers (grpc/sandbox.rs):
   - create: Extracts principal BEFORE into_inner(), stamps owner labels
     on BOTH ObjectMeta.labels (persistence) AND SandboxTemplate.labels
     (compute drivers)
   - get: Ownership check against sandbox labels
   - list: Combines user label selector with owner label selector
   - delete: Fetches sandbox with proper error propagation (NOT
     .ok().flatten()), ownership check before deletion

   Provider handlers (grpc/provider.rs):
   - create: Extracts principal, ensures metadata exists, stamps labels
   - get: Ownership check against provider labels
   - list: Uses owner_label_selector for filtered listing via new
     list_provider_records_with_selector function
   - update: Validates provider_name non-empty BEFORE ownership check
     (security fix from V1 review)
   - delete: Fetches existing provider, ownership check before deletion

   Provider RBAC (grpc/mod.rs):
   - create_provider, update_provider, delete_provider: Changed from
     role = "admin" to role = "user" (ownership enforcement replaces
     admin-only gate)

F) COMPUTE LAYER (compute/mod.rs):
   - create_sandbox now serializes ObjectMeta.labels to the DB labels
     column (was passing None), enabling label-selector queries including
     ownership-filtered list operations

2. ITERATION EVOLUTION (V1 -> V2)
============================================================================

V1 (Previous Iteration):
- Initial implementation of the multi-tenant ownership feature
- Code review (code_gen_review_V1.patch) identified 4 issues:
  * ISSUE 1 (SECURITY HIGH): sandbox delete used .ok().flatten() on store
    fetch, swallowing DB errors and skipping ownership check
  * ISSUE 2 (SECURITY HIGH): provider update bypassed ownership on empty
    name because check was inside if !name.is_empty()
  * ISSUE 3 (BUG MEDIUM): CLI env var bool parsing - without
    action = ArgAction::Set, OPENSHELL_OWNERSHIP_ENABLED=false was
    interpreted as true
  * ISSUE 4 (PERF LOW): Unnecessary HashMap clones in ownership checks

V2 (This Iteration - From Scratch):
- Complete reimplementation incorporating ALL V1 review fixes:
  * FIX 1: Sandbox delete now uses .map_err(|e| Status::internal(...))?
    to properly propagate store errors
  * FIX 2: Provider update validates name non-empty with early error
    return BEFORE ownership check
  * FIX 3: CLI ownership-enabled flag uses action = ArgAction::Set and
    default_value_t = false
  * FIX 4: Uses reference-based patterns (let empty = HashMap::new();
    .unwrap_or(&empty)) to avoid unnecessary clones
- Additional improvements:
  * Cleaner code structure with better separation of concerns
  * More comprehensive test coverage in ownership.rs (27 tests)
  * Groups_claim wired through OIDC config construction
  * ServerState.ownership_config() helper method

============================================================================
5. SECURITY ANALYSIS
============================================================================

Security properties maintained:
- Anti-spoofing: Client-supplied openshell.ai/owner and openshell.ai/tenant
  labels are stripped before server-side values are applied
- Error propagation: Store errors are properly propagated (not swallowed)
  in sandbox delete and provider operations
- Input validation: Provider name validated non-empty before ownership check
- Admin bypass: Admin role holders bypass ownership checks
- Graceful degradation: Pre-existing resources without owner labels are
  accessible by all users (no retroactive lockout)
- Feature toggle: Ownership is disabled by default, activated via config

Known limitations (documented, not fixed - same as V1):
- Subject collision through lossy sanitization (e.g. alice@a.com and
  alice@b.com both sanitize to alice_a.com / alice_b.com)
- ownership_config() allocates on every call (should cache in ServerState)
- sanitize_label_value truncates before trimming (sub-optimal for edge cases)
