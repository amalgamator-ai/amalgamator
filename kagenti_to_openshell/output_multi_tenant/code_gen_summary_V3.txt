EXPLANATION OF CODE PATCH (V3)
============================================================================

This iteration implements multi-tenant resource ownership enforcement for
OpenShell, porting the concept from Kagenti's gateway-per-tenant pattern
(Keycloak audience scoping, namespace isolation) into OpenShell's Rust-based
gateway server. The implementation is done from scratch, incorporating ALL
learnings from V1 and V2 iterations (and their reviews).

The feature adds:

1. **Identity Groups Field** (Step 1)
   Added `groups: Vec<String>` field to the Identity struct in
   auth/identity.rs. Updated all 15 Identity construction sites across
   the codebase to include the new field (groups: vec![] for most paths,
   groups: claims.groups for the OIDC path).

2. **OIDC Groups Extraction** (Step 2)
   Added `groups_claim` field to OidcConfig (default: "groups") with serde
   default. Added `groups: Vec<String>` field to OidcClaims with
   `#[serde(skip)]`. Implemented `extract_groups()` method on OidcClaims
   following the same dot-separated path traversal pattern as
   `extract_roles()`. Called in `validate_token()` after `extract_roles()`.

3. **Label Constants** (Step 3)
   Added LABEL_OWNER ("openshell.ai/owner") and LABEL_TENANT
   ("openshell.ai/tenant") constants to openshell-core/driver_utils.rs.

4. **Ownership Module** (Step 4)
   Created auth/ownership.rs as a pure function library with:
   - OwnershipConfig struct (enabled, admin_role, tenant_id)
   - sanitize_label_value() - K8s label value sanitization
   - stamp_owner_labels() - stamps owner/tenant on a mutable label map
     with anti-spoofing (strips client-supplied ownership labels)
   - check_ownership() - verifies caller owns a resource by label match
   - owner_label_selector() - builds label selector for list filtering
   - 24 unit tests covering all functions and edge cases

5. **Configuration** (Step 5)
   Added OwnershipConfigCore struct to openshell-core/config.rs with
   serde support. Added ownership field to Config struct and Config::new().
   Exported from openshell-core/lib.rs. Added ownership_enabled and
   tenant_id to GatewayFileSection in config_file.rs.

6. **ServerState Helper** (Step 6)
   Added ownership_config() method to ServerState in lib.rs that builds
   the server-side OwnershipConfig from the core config plus the OIDC
   admin role name for bypass checks.

7. **CLI Arguments** (Step 6)
   Added --ownership-enabled (env: OPENSHELL_OWNERSHIP_ENABLED) and
   --tenant-id (env: OPENSHELL_TENANT_ID) CLI arguments to RunArgs.
   Wired into prepare_server_config() with CLI > TOML file > default
   precedence using arg_defaulted(). Added groups_claim to the OIDC
   config construction.

8. **Sandbox Ownership** (Steps 7-9)
   - handle_create_sandbox_inner: Extracts Principal BEFORE into_inner().
     Stamps ownership labels on BOTH ObjectMeta.labels (for persistence)
     AND SandboxTemplate.labels (for compute drivers). This ensures
     labels appear on both the gateway DB records and K8s pods/Docker
     containers.
   - handle_get_sandbox: Adds ownership check via check_ownership().
   - handle_list_sandboxes: Combines user-supplied label selector with
     ownership selector using comma-separated format.
   - handle_delete_sandbox_inner: Fetches sandbox with proper error
     propagation (.map_err, not .ok().flatten()), then performs ownership
     check before deletion.

9. **Sandbox Label Persistence** (Step 7 fix from R4-8)
   Modified compute/mod.rs create_sandbox() to serialize ObjectMeta.labels
   to the DB labels column (was passing None). This enables label-selector
   queries to work for all sandbox labels including ownership.

10. **Provider Ownership** (Step 11)
    - handle_create_provider: Extracts Principal, ensures metadata exists
      via get_or_insert_with(Default::default), stamps ownership labels.
    - handle_get_provider: Adds ownership check.
    - handle_list_providers: Uses owner_label_selector for filtering.
    - handle_update_provider: Validates non-empty provider name BEFORE
      ownership check (V1 security fix), fetches existing, checks
      ownership.
    - handle_delete_provider: Fetches existing with map_err error
      propagation (not silently swallowing errors), checks ownership.
    - create_provider_record: Serializes labels to DB labels column.
    - Added list_provider_records_with_selector() helper.

11. **Provider Role Changes** (Step 11)
    Changed rpc_auth roles for create_provider, update_provider, and
    delete_provider from "admin" to "user" in grpc/mod.rs. This allows
    regular users to manage their own providers with ownership enforcement.
    Profile/credential management methods remain admin-only.

============================================================================
KNOWN LIMITATIONS (documented, not bugs)
============================================================================

A. No CLI flag for --oidc-groups-claim. The groups_claim is hardcoded to
   "groups" when OIDC is configured via CLI args. When configured via TOML
   file, the groups_claim is properly deserialized via serde default.

B. ownership_config() allocates on every handler call. The OwnershipConfig
   struct is built fresh each time. For a latency-sensitive path this could
   be cached in ServerState, but allocation is cheap and the struct is small.

C. Subject collision through lossy sanitization. Two distinct OIDC subjects
   can sanitize to the same label value (e.g., "alice@a.com" and
   "alice+a.com" both become "alice_a.com"). This is inherent in the K8s
   label value constraint and is documented.

D. sanitize_label_value truncates before trimming. A 63-char string ending
   with a non-alphanumeric character will be shorter than necessary after
   trimming. This is cosmetic.

E. Provider profile/credential management methods remain admin-only as
   intended by the plan (import, update_profiles, rotate_credential,
   delete_refresh, delete_profile).
