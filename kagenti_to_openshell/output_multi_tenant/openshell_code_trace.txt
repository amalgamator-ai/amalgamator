1. EXECUTIVE SUMMARY
================================================================================

OpenShell is fundamentally single-tenant by design. There is:

  - NO tenant/owner field on any persistent object (sandboxes, providers)
  - NO per-user filtering on list/get operations
  - NO tenant column in the database schema
  - NO namespace-per-tenant in the Kubernetes driver
  - NO audience-based tenant scoping (audience is a single global value)
  - NO per-user provider isolation
  - NO owner-label stamping on sandbox creation
  - NO RBAC partitioning by tenant (roles are admin/user, not tenant-scoped)

The existing infrastructure that COULD support multi-tenancy:

  + Identity/Principal model (Identity.subject, Principal.User) — exists but unused for scoping
  + OIDC JWT with roles/scopes extraction — exists, could add tenant claim extraction
  + Label-based filtering (list_with_selector, labels column in DB) — exists
  + Namespace-scoped Kubernetes operations — exists as single-namespace model
  + ResourceQuota support — not present, would need to be added
  + Sandbox-principal scope guards (guard.rs) — exist for cross-sandbox, not cross-tenant

2. ARCHITECTURE OVERVIEW (Current Single-Tenant Model)
================================================================================

Current Model:
```
                    CLI (any user)
                        │
                        ▼
              ┌─────────────────┐
              │  Gateway Server │ ← single instance or HA replicas
              │  (gRPC + HTTP)  │   sharing one Postgres DB
              └────────┬────────┘
                       │
          ┌────────────┼────────────────┐
          ▼            ▼                ▼
    ┌──────────┐  ┌──────────┐  ┌──────────────┐
    │ Store    │  │ Compute  │  │ Auth Layer   │
    │ (SQLite/ │  │ Runtime  │  │ (OIDC/mTLS)  │
    │ Postgres)│  │ (K8s/    │  │ - role check │
    │          │  │  Docker/ │  │ - scope check│
    │ GLOBAL   │  │  Podman/ │  │ - NO tenant  │
    │ objects  │  │  VM)     │  │   check      │
    └──────────┘  └─────┬────┘  └──────────────┘
                        │
                   Single K8s
                   Namespace
                   (default: "openshell")
```

ALL users share:
  - The same persistence store (no per-user filtering)
  - The same compute namespace
  - The same providers (admin-created, globally visible)
  - The same sandbox list (any user sees all sandboxes)

3.2 Persistence Layer (Store, SQLite, Postgres)
────────────────────────────────────────────────────────────────────────────────

Files:

Database Schema (both backends):
  CREATE TABLE objects (
      id            TEXT PRIMARY KEY,
      object_type   TEXT NOT NULL,       ← "sandbox", "provider", "sandbox_policy" etc.
      name          TEXT,                ← human-readable name (unique per type)
      scope         TEXT,                ← application-owned scope (NOT tenant scope)
      version       INTEGER,
      status        TEXT,
      dedup_key     TEXT,
      hit_count     INTEGER DEFAULT 0,
      payload       BLOB NOT NULL,       ← serialized protobuf
      created_at_ms INTEGER NOT NULL,
      updated_at_ms INTEGER NOT NULL,
      labels        TEXT,                ← JSON-serialized label map
      resource_version INTEGER DEFAULT 1 ← optimistic concurrency
  );

  Unique indexes:
    objects_name_uq ON (object_type, name) WHERE name IS NOT NULL
    objects_version_uq ON (object_type, scope, version)
    objects_dedup_uq ON (object_type, scope, dedup_key)

  NOTE: name uniqueness is global within object_type.
  There is NO tenant column. No per-user partition.

ObjectRecord struct:
  pub struct ObjectRecord {
      pub object_type: String,
      pub id: String,
      pub name: String,
      pub payload: Vec<u8>,
      pub created_at_ms: i64,
      pub updated_at_ms: i64,
      pub labels: Option<String>,     ← JSON labels (could carry owner label)
      pub resource_version: u64,
  }

Store API (key methods):
  pub async fn put_if(&self, object_type, id, name, payload, labels, condition)
  pub async fn get(&self, object_type, id) -> Option<ObjectRecord>
  pub async fn get_by_name(&self, object_type, name) -> Option<ObjectRecord>
  pub async fn list(&self, object_type, limit, offset) -> Vec<ObjectRecord>
  pub async fn list_with_selector(&self, object_type, label_selector, limit, offset)
  pub async fn delete(&self, object_type, id) -> bool
  pub async fn put_scoped(&self, object_type, id, name, scope, payload, labels)
  pub async fn list_by_scope(&self, object_type, scope, limit, offset)

MULTI-TENANCY GAPS:
  - list() returns ALL objects of a type — no per-user filtering
  - get_by_name() looks up globally — two tenants cannot have same-named sandbox
  - No "owner" or "tenant" column for partitioning
  - The "scope" column is used for policy revisions scoped to sandbox_id, NOT tenancy
  - list_with_selector() EXISTS and could be used for owner-label filtering
  - Labels are stored as JSON — could carry openshell.ai/owner but don't today
  - Name uniqueness is global — would need (object_type, name, owner) for multi-tenant

EXISTING HOOKS THAT COULD BE LEVERAGED:
  - labels column: can store {"openshell.ai/owner": "<sub>"} on every object
  - list_with_selector(): can filter by openshell.ai/owner=<caller>
  - put_if() with labels: can stamp owner at creation time
  - Postgres JSONB @> operator: already used for efficient label filtering

AuthzPolicy:
  pub struct AuthzPolicy {
      pub admin_role: String,    ← "openshell-admin"
      pub user_role: String,     ← "openshell-user"
      pub scopes_enabled: bool,
  }

  check(identity, method):
    - Looks up required role for method (Admin or User)
    - Admin role implicitly satisfies User role requirement
    - If scopes_enabled, also checks required scope (sandbox:read, etc.)
    - NO tenant-level authorization

OIDC JWT Validation (oidc.rs):
  - Validates issuer, audience (single global value), signature
  - Extracts roles from configurable claim path
  - Extracts scopes from configurable claim
  - OidcClaims struct: sub, preferred_username, email, roles, extra (raw claims)
  - Audience is validated as: validation.set_audience(&[&self.config.audience])
    This is a SINGLE audience string — no per-tenant audience scoping

  OidcConfig:
    pub struct OidcConfig {
        pub issuer: String,         ← single OIDC issuer
        pub audience: String,       ← single audience (e.g. "openshell-cli")
        pub jwks_ttl: u64,
        pub roles_claim: String,    ← "realm_access.roles" for Keycloak
        pub scopes_claim: String,
        pub admin_role: String,     ← "openshell-admin"
        pub user_role: String,      ← "openshell-user"
        pub ca_cert_path: Option<String>,
    }

Sandbox Scope Guards (guard.rs):
  ensure_sandbox_scope(principal, claimed_sandbox_id):
    - Principal::User → passes through (RBAC was the gate)
    - Principal::Sandbox → must match sandbox_id exactly
    - Principal::Anonymous → rejected
  NOTE: User principals bypass sandbox scope checks entirely.
  There is NO owner check — any user with the right role can access any sandbox.

MULTI-TENANCY GAPS:
  - Identity has no tenant/group field
  - No tenant claim extraction from JWT
  - Audience is single-valued — can't scope per-tenant
  - AuthzPolicy has no tenant dimension — only admin/user roles
  - Sandbox scope guards only apply to sandbox principals, not users
  - No user-to-sandbox ownership enforcement on any API

3.4 Sandbox Lifecycle (grpc/sandbox.rs)
────────────────────────────────────────────────────────────────────────────────

File: crates/openshell-server/src/grpc/sandbox.rs

handle_create_sandbox_inner():
  1. Validates spec and labels
  2. Validates provider names exist (globally — no per-user filter)
  3. Generates UUID + petname for sandbox
  4. Creates Sandbox protobuf with metadata.labels from request
  5. Validates via compute driver
  6. Mints sandbox JWT (if configured)
  7. Calls compute.create_sandbox()
  NOTE: NO owner stamping. request.labels are passed through as-is.
  The caller's identity (Principal::User) is NOT consulted or recorded.

handle_list_sandboxes():
  - Calls store.list_messages::<Sandbox>(limit, offset)
  - Or store.list_messages_with_selector if label_selector is provided
  NOTE: Returns ALL sandboxes. No per-user filtering.

handle_get_sandbox():
  - Calls store.get_message_by_name::<Sandbox>(name)
  NOTE: Any authenticated user can get any sandbox by name.

handle_delete_sandbox():
  - Looks up sandbox by name, calls compute.delete_sandbox()
  NOTE: Any authenticated user can delete any sandbox.

SandboxIndex (sandbox_index.rs):
  In-memory HashMap mapping:
    sandbox_name → sandbox_id
    agent_pod → sandbox_id
  NOTE: Global index. No tenant partitioning.

MULTI-TENANCY GAPS:
  - CreateSandbox does not stamp owner from Principal::User.identity.subject
  - ListSandboxes returns all sandboxes regardless of caller identity
  - GetSandbox/DeleteSandbox has no ownership check for user principals
  - Client-supplied openshell.ai/owner labels are NOT stripped
  - SandboxIndex is global — would need per-tenant partitioning

3.5 Provider Management (grpc/provider.rs)
────────────────────────────────────────────────────────────────────────────────

File: crates/openshell-server/src/grpc/provider.rs

Provider CRUD:
  - CreateProvider: admin-only role, stores globally
  - GetProvider: user role, no ownership check
  - ListProviders: user role, returns ALL providers
  - UpdateProvider: admin role, no ownership check
  - DeleteProvider: admin role, no ownership check

NOTE: Providers are admin-managed global resources. There is no per-user
provider ownership, no shared/user-owned distinction, and no per-user

MULTI-TENANCY GAPS:
  - No per-user provider ownership (owner label not stamped)
  - No user-owned vs shared provider distinction
  - Provider name uniqueness is global (not scoped to owner)
  - ListProviders returns all providers to any authenticated user

4. MULTI-TENANCY GAP ANALYSIS
================================================================================

DIMENSION                   CURRENT STATE            NEEDED FOR MULTI-TENANCY
─────────────────────────── ──────────────────────── ──────────────────────────
Persistence partitioning    Global objects table     Per-owner label filtering
                            No owner column          or dedicated owner column

Sandbox creation            No owner stamping        Server-side owner stamp
                            Labels passed through    from Principal.identity.subject
                                                     Strip client openshell.ai/*

Sandbox listing             Returns all sandboxes    AND owner=<caller> into query
                            No per-user filter       Admin bypass for openshell-admin

Sandbox get/delete          Any user can access      PermissionDenied if owner!=caller
                            any sandbox              Admin bypass

Provider ownership          Admin-created, global    Per-user + shared providers
                            No ownership concept     Resolution: user > shared

Provider listing            Returns all providers    Filter by owner + shared

Namespace isolation         Single K8s namespace     Namespace-per-tenant or
                            for all sandboxes        owner-label on pods

OIDC audience scoping       Single global audience   Per-tenant audience validation
                            (e.g. "openshell-cli")   (aud=team1, aud=team2)

RBAC                        admin/user roles only    No change needed if using
                            No tenant dimension      owner-label approach

DB name uniqueness          Global (type, name)      Scoped (type, name, owner)
                                                     or namespace-scoped

Helm chart                  Single gateway deploy    Gateway-per-tenant pattern
                            Single namespace         or shared gateway + owner labels

ResourceQuota               None                     Per-tenant quotas

Certificate management      Single TLS cert set      Per-tenant leaf certs
                                                     (if gateway-per-tenant)
