ISSUE #1 [MEDIUM] — State machine ordering: summary results bypass budget_exhausted error kind
--------------------------------------------------------------------------
AFFECTED CODE:
  src/agents/embedded-agent-runner/run.ts, lines 3853-3928 (V3 patch)
  The budget exhaustion detection section.

WHAT IS WRONG:
  The three-block state machine was ordered:
    1. Budget exhaustion detection (sets budgetExhaustedSummaryPending, continues)
    2. Budget summary completion handler (checks budgetSummaryAttempt)
    3. Pending-to-active promotion (budgetExhaustedSummaryPending → budgetSummaryAttempt)

  The promotion from pending to active (block 3) occurred AFTER the
  completion handler (block 2). This means:

    Iteration N:   Budget exhausts → refund, set pending=true, continue
    Iteration N+1: Summary attempt dispatches with instruction in prompt.
                   After attempt returns: block 2 checks budgetSummaryAttempt
                   which is still false (promotion hasn't happened yet).
                   Block 3 sets budgetSummaryAttempt=true. Code falls through
                   to the normal terminal path (line ~4182) and returns the
                   summary text as a normal successful run WITHOUT the
                   budget_exhausted error kind.

  The budgetSummaryAttempt handler at block 2 is dead code in the happy
  path — it would only fire on a THIRD iteration (N+2) that never occurs
  because N+1 returns normally.

WHY IT MATTERS:
  When forceSummaryOnExhaustion is enabled and the summary attempt
  produces text (the expected happy path), the caller receives a normal
  success result instead of a budget_exhausted error. Downstream code
  that checks `result.meta.error?.kind === "budget_exhausted"` to detect
  budget exhaustion will not fire. The budget exhaustion is silently
  hidden as a successful run.

HOW FIXED:
  Moved the pending-to-active promotion block BEFORE the detection and
  completion checks:

    1. Pending-to-active promotion (budgetExhaustedSummaryPending → budgetSummaryAttempt)
    2. Budget summary completion handler (checks budgetSummaryAttempt) → return
    3. Budget exhaustion detection (sets budgetExhaustedSummaryPending, continues)

  Now on iteration N+1:
    - Block 1 fires: budgetExhaustedSummaryPending=true → budgetSummaryAttempt=true
    - Block 2 fires: budgetSummaryAttempt=true → returns buildBudgetExhaustedResult
    - Block 3: never reached (block 2 returned)

  This ensures the summary text is always wrapped in the budget_exhausted
  error kind via buildBudgetExhaustedResult.
