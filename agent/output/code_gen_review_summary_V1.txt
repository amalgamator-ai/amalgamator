--------------------------------------------------------------------------
AFFECTED CODE:

    - IterationBudget (class, from ../iteration-budget.js)

ISSUE #2 [MEDIUM] — Dead code / no-op if block in run.ts
--------------------------------------------------------------------------
AFFECTED CODE:
  src/agents/embedded-agent-runner/run.ts, lines ~1938-1941:
    if (iterationBudget && !budgetSummaryAttempt) {
      // Consume is already called via onBeforeToolCallingRound for tool rounds.
      // This is an additional top-level check for the outer run loop.
    }

WHAT IS WRONG:
  The if block body is empty. The comment claims consumption is handled
  elsewhere, but `onBeforeToolCallingRound` only fires during *tool-calling
  rounds* inside the inner agent loop. The outer run.ts loop iterates for
  many non-tool-call reasons (compaction retries, auth retries, empty
  response retries, timeout retries, rate-limit backoffs, etc.), and those
  iterations are never counted against the budget.

WHY IT MATTERS:
  With only `onBeforeToolCallingRound` consuming budget, a run that loops
  due to compaction retries, auth failures, or empty responses would never
  exhaust its budget — defeating the core purpose of the feature. The
  outer-loop counter is the primary budget enforcement point (matching
  Hermes's conversation_loop.py which counts every LLM call, not just
  tool rounds).

HOW FIXED:
  Changed the empty block to actually consume from the budget:
    if (iterationBudget && !budgetSummaryAttempt) {
      iterationBudget.consume();
    }


ISSUE #3 [LOW] — Duplicate IterationBudgetConfig type definition
--------------------------------------------------------------------------
AFFECTED CODE:
  src/agents/iteration-budget.ts (lines 22-27):
    export interface IterationBudgetConfig { ... }
  src/config/types.agent-defaults.ts (lines 128-137):
    export type IterationBudgetConfig = { ... };

WHAT IS WRONG:
  Two identical type definitions exist in different files. The config type
  in types.agent-defaults.ts is the canonical one (imported by
  agent-scope-config.ts, referenced by AgentDefaultsConfig). The copy in
  iteration-budget.ts creates a maintenance burden: changing one without
  the other causes silent structural drift.

WHY IT MATTERS:
  While TypeScript structural typing makes the two currently compatible,
  adding a field to one without the other would cause subtle type errors.
  OpenClaw's convention is single-source-of-truth for config types.

HOW FIXED:
  Removed the duplicate interface from iteration-budget.ts and replaced
  it with an import:
    import type { IterationBudgetConfig } from "../config/types.agent-defaults.js";


ISSUE #4 [LOW] — Schema pattern inconsistency: .optional() baked into schema
--------------------------------------------------------------------------
AFFECTED CODE:
  src/config/zod-schema.agent-runtime.ts:
    export const IterationBudgetConfigSchema = z.object({...}).strict().optional();
  src/config/zod-schema.agent-defaults.ts:
    iterationBudget: IterationBudgetConfigSchema,  // no .optional()
  src/config/zod-schema.agent-runtime.ts (AgentEntrySchema):
    iterationBudget: IterationBudgetConfigSchema,  // no .optional()

WHAT IS WRONG:
  The existing pattern (AgentRunRetriesConfigSchema) does NOT bake
  .optional() into the schema constant. Instead, usage sites add it:
    export const AgentRunRetriesConfigSchema = z.object({...}).strict();
    // usage: runRetries: AgentRunRetriesConfigSchema.optional(),

  The V1 patch bakes .optional() into IterationBudgetConfigSchema itself
  and then uses it without .optional() at usage sites. This is functionally
  equivalent but inconsistent with the established project convention.

WHY IT MATTERS:
  Inconsistency confuses developers following the pattern. Someone adding
  a new config field who copies the IterationBudgetConfigSchema pattern
  would break other usage sites that expect to control optionality.

HOW FIXED:
  Removed .optional() from IterationBudgetConfigSchema definition:
    export const IterationBudgetConfigSchema = z.object({...}).strict();
  Added .optional() at usage sites:
    iterationBudget: IterationBudgetConfigSchema.optional(),
