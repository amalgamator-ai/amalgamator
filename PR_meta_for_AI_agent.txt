The failure this PR fixes
-------------------------

the target contains expat.spec and patch files, not the unpacked source tree.
The run succeeded but took 1,697.7 s and $9.05 because both fused sessions ran,
were rejected by heuristics, and the legacy paths redid their work:

1. Fused pre-RED (169.8 s, 18 turns) wrote a valid pre_red_result.json and a

     expat-2.2.5-CVE-2025-59375-tests.patch
   The test patch payload touched only expat/tests/runtests.c.
   _validate_fused_pre_red used _is_test_only_path on the changed FILE paths.
   Neither the .spec nor the .patch matched a test path, so the session was
   rejected:
     "test-port commit changed non-test paths: ..."

2. Fused resolution (487 s, 59 turns) produced a correct commit that passed

patch. These were false negatives, not bad agent work. Expected fused-path

Design rule introduced by this PR
---------------------------------
Heuristics must never discard a session that committed cleanly. A fused result
can only be discarded for objective failures:

  - session raised or produced no usable result;
  - history was rewritten (base_head is no longer an ancestor of HEAD);
  - HEAD did not move / nothing was committed;
  - remaining cherry-pick conflicts;
  - committed conflict markers;
  - session scratch/build output cannot be stripped cleanly.

Heuristic signals are now gates/dossier evidence, not fallback triggers:

  - low fix/backport line overlap -> semantic_equivalence=fused_unmatched,
    fused_relatedness=advisory; keep the commit; build/test + 3a.2 decide;
  - test path names that do not match test patterns -> inspect the patch
    payload first; if the payload is tests-only, accept;
  - an unparsable patch carrier -> WARNING and keep the work;
  - a result that fails relatedness completely -> still keep the work; report
    the gate for human spot-check rather than rerunning resolution.

Do not "restore" a fallback on these signals. If a real quality problem is
found, add a deterministic check that proves it; do not make a naming or
line-overlap heuristic destructive again.


Packaging model
---------------
A changed path can be one of three things:

  source     normal source/test file (or a carrier payload path)
  packaging  .spec, debian/, rpm/, PKGBUILD, APKBUILD
  carrier    .patch / .diff; its payload is the effective change

Effective paths for a commit:
  - source paths are used as-is;
  - for each changed patch carrier, read the post-image at that commit and
    expand its touched paths from unified-diff headers;
  - spec/debian/etc. are packaging, not source.

The implementation is in auto_bug_fix/packaging.py:

  is_patch_carrier(path)
  is_packaging_path(path)
  carrier_paths(content)          -> paths a unified diff touches
  carrier_payload(content, n)     -> set of (polarity, normalized +/- line)

run_bug_fix.py wraps these:

  _EffectivePaths / _effective_paths(repo, ref, paths)
      Expands carriers read at `ref`; returns source, packaging, unparsed.
  _changed_packaging_paths(repo, range)
      Carrier/packaging paths in a diff range, for gates/dossier.
  _packaging_only(changed_files)
      True when every changed file is packaging/carrier.
  _expanded_payload_lines(repo, diff_args)
      Normal diff payload plus payloads of changed .patch/.diff files read
      from HEAD. Used by relatedness only.

Key behavior by function:

  _session_test_files
      Unwraps test-port commits through carriers and returns effective test
      paths (expat/tests/runtests.c), not the .patch path. Deletions excluded;
      AMCR statuses only. Accepts _is_test_path or _is_declared_test.

  _validate_fused_pre_red
      For test-port/prereq/leftovers commits it checks effective source paths.
      A spec plus a tests-only patch passes. A patch whose payload touches
      production source still fails ("test-port commit changed non-test paths").
      Packaging paths count as claimed by the commit. Unparsed carriers are
      warned about, not rejected.

  _run_fused_pre_red
      Records pre_red_reject with the exact problems on hard rejection.
      Records pre_red_carrier=packaging and a dossier entry when packaging
      carriers are present.
      Ported-test floor:
        - effective test paths from carriers count even though they do not
          exist as worktree paths;
        - planned paths only count if still present at HEAD (deleted tests do
          not satisfy the floor);
        - _is_declared_test counts SQL pairs;
        - planned-test "uncovered" and file-set warnings become INFO when a
          packaging carrier is present, because payload path names differ.

  _shares_content_with_fix / _fused_resolution_unmatched
      Uses _expanded_payload_lines for the backport side, so source lines
      inside a patch carrier are compared with the fix.
      Low overlap remains a true return from _fused_resolution_unmatched; the
      policy change is in the caller.

  _run_fused_resolution
      On low overlap: log, record semantic_equivalence=fused_unmatched and
      fused_relatedness=advisory, add a dossier entry, KEEP the commit, run
      3a.2. No reject_attempt(), no return None.
      Records resolution_carrier=packaging when carriers changed.

  _finalize_resolution
      If all changed files are packaging (spec + patch), skip deterministic
      rewrites, audit_added_tokens, audit_line_provenance and snapback:
      there is no source tree to audit. Record evidence_scope=packaging and a
      dossier note. Build, tests and review carry evidence.

README section "Packaging-carried changes (dist-git, patch stacks)" documents
the user-visible behavior.

Debugging a new teammate run
----------------------------
If the retry still falls back, capture the pipeline WARNING/INFO logger output,
not just the step console. The opus_ymir run_log contained only console output,
so the rejection reasons had to be inferred from gate records and step order.

Look for these strings:
  "Fused pre-RED session rejected"
  "Fused pre-RED: no regression test was ported"
  "unparsed packaging carrier"
  "fused session rewrote history"
  "fused session left ... conflicts"
  "failed to strip session scratch"
  "low line overlap with the fix"
  "fused result shares too little with the fix"  (old code only; should not
                                                   appear after this PR)

Tracker gates to inspect in the run JSON:
  pre_red_mode             fused | fused_fallback
  pre_red_reject           exact hard rejection problems
  pre_red_carrier          packaging
  resolution_mode          fused | fused_fallback
  resolution_carrier       packaging
  semantic_equivalence     fused_unmatched (advisory if fused_relatedness set)
  fused_relatedness        advisory
  evidence_scope           packaging

Artifacts to inspect:
  <run>/pre_red_result.json
  <run>/fused_pre_red_report.md
  <run>/fused_resolution_report.md
  git log --oneline <base>..HEAD, the changed paths in each session commit,
  and the contents of any .patch/.diff file.

If a carrier is not expanded:
  - print carrier_paths(patch_text) and carrier_payload(patch_text, 6);
  - check whether the patch is a standard unified diff (headers like
    "diff --git a/x b/x", "--- a/x", "+++ b/x");
  - check binary patches, quoted paths, or patches under a versioned source
    prefix (libexpat-R_2_2_5/expat/...): path matching is substring-based for
    tests, but a new format may need a parser change;
  - add a minimal fixture and a test before changing behavior.


Safe extension points / likely future issues
--------------------------------------------
1. Patch parser limitations
   auto_bug_fix/packaging.py is intentionally small. It handles unified-diff
   headers and +/- payload lines. Gaps:
   - quoted paths with spaces (git "a/..." escaping);
   - binary patches;
   - Debian debian/patches/series (no .patch suffix) and multiple patches;
   - modified patch files: the full post-image patch is expanded, so old hunks
     may contribute. Low relatedness is advisory, but if this causes wrong
     acceptance, make extraction hunk-aware; do not reintroduce a fallback.

2. Spec validation
   .spec files are accepted as packaging without parsing %patch references.
   The ported-test floor still requires an effective test path, so a spec-only
   test port fails. If stricter validation is needed, check that added
   PatchN/%patchN lines reference carriers that are tests-only; keep a fallback
   to advisory for unknown packaging syntax.

3. _packaging_only
   Treats every .patch/.diff as packaging, including a test fixture patch.
   In a source-tree repo this only matters when the whole change is a patch
   file; if that happens, consider requiring a .spec/debian/ packaging marker
   before skipping audits.

4. Relatedness threshold
   _RELATEDNESS_MIN_OVERLAP = 0.30 and _RELATEDNESS_MIN_LINE_LEN = 6 are
   measured, not arbitrary. Do not lower them to fix a specific case; expand
   the carrier payload instead. Low overlap stays advisory regardless.

5. Pre-RED floor semantics
   Effective test paths from a carrier are counted without existing at HEAD.
   A patch that adds a test but the spec never applies it would pass the floor.
   If that becomes a real issue, verify the spec applies the patch (or the
   build/test command includes it) using a deterministic check; report it as
   evidence, not as a reason to discard a valid session.

6. Don't conflate this PR with the speed optimizations
   PR #81 measured token/wall reductions on the fused source-tree path. This
   PR is a correctness/fallback fix. Wall numbers are load-sensitive; compare
   tokens and phase turn counts, and use matched or serialized runs.
