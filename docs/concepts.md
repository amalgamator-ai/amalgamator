# Concepts

## Two use cases

Amalgamator automates two evidence-heavy engineering jobs:

1. **GPU performance analysis** — profile LLM inference frameworks (vLLM,
   SGLang, TensorRT-LLM), analyze and compare GPU traces, and port optimizations
   between frameworks.
2. **Bug-fix backporting** — find which branches/tags lack a fix, then port that
   fix to another branch with a git-first pipeline that fails closed to a human.

Nothing in either path assumes a specific company, language, or monorepo layout.
Backporting needs a git repo and shell-invokable build/test commands (tested on
Go and C codebases). GPU work needs framework sources and traces or GPUs.

## Evidence first, LLM second

Both use cases share the same product rule: **deterministic mechanisms run
before generative ones, and LLM edits are checked against evidence.**

For backporting that means:

- Try `git cherry-pick` and mechanical patch apply before any LLM conflict edit.
- Audit LLM resolutions (identifiers, provenance, dead config) against the
  target tree.
- Require your build and test commands to pass before handing a dossier to a
  human.

For GPU analysis and codegen that means:

- Trace correlation and runtime gates use measured artifacts (traces, benchmarks,
  correctness checks).
- Resume/convergence is based on declared output files and markers, not chat
  memory.
- The PR flow never lets the agent push or merge; humans run network git/`gh`
  scripts after local verification.

## Human review is required

Pipelines produce reviewable commits, patches, dossiers, or draft PR material.
They do **not** merge autonomously. Treat every successful run as a candidate for
a person to accept, amend, or reject.

## Configuration shapes

| Area | Config style |
|------|----------------|
| Backport + scanner | YAML/JSON **case** or **scan** file + optional **`models.yaml`** registry |
| GPU profile / analyze / codegen | JSON configs (often generated by helpers) |
| GPU agent backend | Embedded `agent` section or `--agent-config` file |

Path rules differ by loader (working-directory-relative key files for the model
registry; agent key files relative to the declaring JSON). See
[Authentication](authentication.md) and the package READMEs.

## Cost tracking

Each model query records the effective model and profile ID. Provider-reported
cost (including zero) wins when present; otherwise Amalgamator estimates from
tokens. Self-hosted Ollama and custom-endpoint `openai/` profiles are treated as
zero token cost. A summary prints at the end of each run.

## Out of scope

- Autonomous merge without human confirmation
- Generating net-new test suites (pipelines run the build/test commands you give)
- Porting capabilities across unrelated agent platforms

See also the [root README](../README.md#scope) for the public product statement.
